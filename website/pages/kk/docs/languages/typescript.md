# TypeScript/JavaScript

| | |
| --- | --- |
| Бірлік | бума немесе файл |
| Bridge | генерацияланған бинарлық wire бар napi-rs немесе wasm-bindgen; кластар мен async те бар |
| Жазып алатын және қайта ойнататын | Node, `.ts` бастапқы файлдарын тікелей іске қосады |
| Қажет | Node 22.6+ (`profile` үшін Node 24+ керек) |
| Күйі | Тексерілген |

## Bridge-ті таңдау

`analyze` бірлікке немесе ол импорттайтын кез келген нәрсеге Node керек болса napi-rs-ті, тасымалданатын код үшін wasm-bindgen-ді таңдайды (ол браузерлерде де жұмыс істейді), ал UI мен редактор кодын JS-те қалдырады. `bridge --kind napi|wasm` бұл таңдауды қолмен ауыстырады.

Bridge арқылы өте алмайтын экспорттар себебі көрсетіліп TS-те қалады, ал shadow модулі түпнұсқаны қайта экспорттайды: функцияларды қабылдайтын немесе қайтаратын функциялар, генераторлар мен итераторлар, RegExp, `instanceof` тексерулері, generic-тер (`--as-json T` қолданба тек деректермен толтыратын біреуіне bridge жасайды) және типтерінде функциялар бар мәндер. [Bridge](/docs/concepts/bridge) бетін қараңыз.

## TS-ті сол күйінде жазып алу

`record` TS бастапқы файлдарын тікелей іске қосады: Node resolve hook-ы bundler стиліндегі импорттарды қадағалайды, репозиторийде ештеңе орнатылмаған болса `--resolve-from` npm пакеттерін береді, ал түрлендіруді қажет ететін TS (enum-дар, parameter properties) `--experimental-transform-types` арқылы қайта іске қосылады. `record --from-tests -- npx jest` түпнұсқаның өз тест жиынтығы жасайтын әр шақыруды кез келген runner-мен жазып алады. Түпнұсқаның қамтуы TS/JS үшін өлшенеді ([Қамту](/docs/concepts/coverage)).

## Порт нені дұрыс істеуі керек

Нақты кодтағы жазылған кейстер арқылы табылған:

- `str.length`, `indexOf` және `slice` UTF-16 код бірліктерін санайды, сондықтан эмодзи екі позиция алады. Генерацияланған `utf16` көмекшілерін қолданыңыз.
- `u` флагы жоқ `/.../i` тек ASCII әріптерін регистрге тәуелсіз салыстырады, ал Rust-тың `regex` кітапханасы Unicode-ты салыстырады, сондықтан vercel/ms-те `"1 ſ"` (ұзын s) және Кельвин белгісі секунд ретінде парсталып кетер еді.
- `Math.round` жартыларды жоғары дөңгелектейді (`-2.5` нәтижесі `-2`); Rust-тың `round` функциясы нөлден алысқа дөңгелектейді. Генерацияланған `js.rs` ішінде `js::math_round` бар.
- `${n}` `1e+21`, `5e-324` және `-0` үшін `0` басып шығарады. `js::number_to_string` осыны қайталайды.
- `String.prototype.trim` Rust-тың `char::is_whitespace` функциясын емес, JS бос орын таңбаларын қолданады.

## Жылдамдық

Бір шақыру бойынша порт әр жолы bridge үшін төлейді, ал V8 кішкентай функцияларды наносекундтарда орындайды. vercel/ms өзінің жазылған кейстерінде бір шақыруға 0.56x жұмыс істеді; x18n ядросының порттары JS-тен шақырылғанда TS-тен баяуырақ. Batch-тар ретінде цикл Rust-қа көшеді:

| Жүктеме | Түпнұсқа | everything-rust-пен |
| --- | ---: | ---: |
| x18n бүйірлік панеліндегі іздеу, 50,000 кілт (Node) | бір сұранысқа 10 ms | 0.5 ms: 20x жылдамырақ |
| Сол іздеу браузерде (wasm, бір ағын) | 10 ms | 0.95 ms: 11.5x |
| Fuse.js, 50,000 жол | 91.2 ms | 2.8 ms: 32x |
| vercel/ms `parse` x100,000 | 11.8 ms | 0.65 ms: 18x (беруді қоса санағанда 3.4x) |
| vercel/ms `format` x100,000 | 2.1 ms | беруімен 2.5 ms: 0.8x |

Тәжірибелер: [json-server](/docs/real-world/json-server), [Fuse.js](/docs/real-world/fuse-js), [vercel/ms](/docs/real-world/vercel-ms), [x18n](/docs/real-world/x18n).
