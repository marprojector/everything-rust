# Жазып алу және қайта ойнату

`record` пен `diff` бір бірлікті дәлелдейді; `app record` пен `app replay` алты тілдің кез келгеніндегі CLI-лар мен серверлер үшін қолданбаны дәлелдейді. Қолданба қара жәшік ретінде қарастырылады.

```sh
everything-rust app record . -- python3 cli.py          # түпнұсқаны іске қосатын команда
everything-rust app replay .                            # түпнұсқа 100% өтуі керек
everything-rust app replay . --build "target/release/mytool"
```

## Кейстер қайдан алынады

`app record` түпнұсқаны мыналарда іске қосады:

- қолданбаның өз құжатталған мысалдары: оның Markdown және shell файлдарындағы `$ mytool ...` жолдары, олар атайтын файлдармен бірге;
- `--inputs` JSONL файлы, әр жолда бір `{"name", "args", "stdin", "env", "files"}`;
- сол кейстерден алынған семантикалық тұзақтар: ASCII емес және эмодзи жолдары, теріс бөлу және модуль, толып кету, өте үлкен және өте кішкентай float-тар, map реті, жоқ файлдар.

Әр кейс екі рет іске қосылады; екі іске қосу арасында ерекшеленген нәрсе `[..]` wildcard-қа айналады. `--normalize timestamps|uuids|key-order` немесе `--normalize name=regex` кейстермен бірге сақталатын нормализаторларды қосады. `app record` нені ерекшеленгенін түрі бойынша хабарлайды: мәндер (енді wildcard), рет (жолдар кез келген ретпен салыстырылады) және жолдар (кез келген нәрсеге сәйкес келетін `...`). Әрқайсысын қараңыз.

## Кейстер қарапайым файлдар

Кейстер `rust/app-cases/` ішіндегі [trycmd](https://docs.rs/trycmd) файлдары:

| Файл | Ішінде не бар |
| --- | --- |
| `<case>.toml` | argv, env, шығу коды |
| `<case>.stdin` | стандартты кіріс |
| `<case>.stdout`, `<case>.stderr` | түпнұсқа басып шығарған нәрсе |
| `<case>.in/` | кіріс файлдары |
| `<case>.out/` | жазылған файлдар |

Оларды қолмен оқып, өңдеңіз; порттың бинарлық файлы болғаннан кейін Rust тесті оларды `trycmd` арқылы іске қоса алады.

## Қайта ойнату

- `app replay` кез келген build-ті кейстерге қарсы іске қосады, `passed/total` басып шығарады, әр құлаған кейс үшін diff-пен `rust/app-cases/replay-report.md` жазады және кез келген сәйкессіздікте нөлдік емес кодпен аяқталады.
- [Front door](/docs/whole-apps/front-door) сияқты `EVERYTHING_RUST_FALLBACK_LOG` атаған файлға жазып отыратын build (түпнұсқаға әр fallback үшін бір жол) өзінің fallback үлесін де хабарлатады.
- `app replay --case <name>` есеп берген атау бойынша бір кейсті қайта іске қосады: барлығын қайта іске қоспас бұрын сәйкессіздікті түзетуге арналған жылдам, қайталанатын цикл.

## CI-да қайта ойнату

Есепте уақыт өлшемдері немесе уақытша жолдар жоқ: бір build-тің екі рет қайта ойнатылуы бірдей файл жазады. Оны commit жасаңыз, содан кейін CI-да іске қосыңыз:

```sh
everything-rust app replay .
git diff --exit-code rust/app-cases/replay-report.md
```

Жартылай портталған қолданба бұдан кейін өтетін нәрседегі кез келген өзгерісте, жақсы болсын не нашар болсын, есеп сол өзгеріспен жаңартылмайынша CI-да құлайды.

## Сандық шығыс

`app record --float-tolerance 1e-9` сандарға үлкенірек мәннің сол үлесі шегінде сәйкес келуге мүмкіндік береді. [Float рұқсат ауытқуы](/docs/concepts/float-tolerance) бетін қараңыз.
