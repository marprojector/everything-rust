# Бүкіл қолданбаны порттау

Мақсат түпнұсқа сияқты жұмыс істейтін таза Rust қолданбасы, ал түпнұсқа эталон ретінде сақталады. Rust кодын агентіңіз жазады; everything-rust жұмысты ретке келтіреді, қаңқасын жасайды және әр қадамды дәлелдейді. CLI-лар, HTTP серверлер және кітапханалар.

```
analyze --whole-app ──> app record ──> app front-door ──> per unit: the loop, then app wire ──> app lift
 shape, every           what the app    Rust owns the       gate passes, so the unit answers in    pure Rust,
 dependency, the        does from the   entry point; the     Rust: replay 100%, fallback rate down proved by
 decisions to make      outside         original answers                                           replay
```

## 1. Жоспарлау

```sh
everything-rust analyze . --whole-app
```

`--whole-app` мыналарды қосады: қолданбаның пішіні (CLI, сервер немесе кітапхана) және кіру нүктелері, әр сыртқы тәуелділік (импортталған немесе жарияланған) өзінің Rust crate-і және сәйкестігімен, бөліктер түріндегі порттау реті (бір-бірін импорттайтын бірліктер бірге көшеді), және ұсынылған жауабы бар нөмірленген шешімдер: сақталатын бірліктер, бұғатталған бірліктер, crate-і жоқ немесе жартылай ғана бар тәуелділіктер.

## 2. Бүкіл қолданбаны жазып алу, содан кейін кіру нүктесін көшіру

1. [`app record` және `app replay`](/docs/whole-apps/record-replay) бағдарламаны сырттан, қара жәшік ретінде дәлелдейді.
2. [`app front-door`](/docs/whole-apps/front-door) түпнұсқаның алдына Rust бинарлық файлын қояды; әр команда әлі де түпнұсқаны іске қосады.
3. Әр бірлік [цикл](/docs/concepts/the-loop) арқылы өтеді, содан кейін `app wire` оның командаларын Rust-қа береді.
4. Қайта ойнату 0 fallback үлесімен өтіп, әр бірлік gate-тен өткенде, [`app lift`](/docs/whole-apps/lift) түпнұсқаны алып тастайды.

[Серверлер](/docs/whole-apps/servers) мен [кітапханалар](/docs/whole-apps/libraries) сол командаларды қолданады.

## Агент оны қалай орындайды

[Whole-app skill](https://github.com/marprojector/everything-rust/blob/main/skills/everything-rust/whole-app.md) агентті осы жол бойымен жүргізеді, тек өзіңіз қабылдай алатын шешімдерден бастап:

- **Сұрақ алу (grilling)**: агент раундтармен сұрайды, әр сұрақ ұсынылған жауабымен, порт тәуелді әр шешім анықталғанша, және әрқайсысын `rust/DECISIONS.md` ішінде ADR ретінде жазады, ал `rust/GLOSSARY.md` түпнұсқаның терминдерін Rust атауларына сәйкестендіреді.
- **Зерттеу**: фондық агенттер әр тәуелділіктің бастапқы дереккөздерін оқып, тапқан әр семантикалық тұзағымен `rust/research/<topic>.md` жазады.
- **Сессиялар бойынша**: `rust/MAP.md` әр бірлікті оның күйімен тізімдейді; сессия бастамас бұрын бір бірлікті өзіне алады, ал әр бақылау нүктесі келесі сессия үшін `rust/HANDOFF.md` қалдырады. Бір толқындағы бірліктерді subagent-тер қатар порттай алады.
- **Ауысу (cutover)**: агент қолынан келгенін істеп, `rust/cutover.sh` жазады: тек өзіңіз жасай алатын қадамдарға (deploy, DNS, құпия деректер) арналған интерактивті скрипт, әр қадамда кері қайту жолымен.

Сұрақ алу, зерттеу және осы тәжірибелер [Matt Pocock skill-дерінен](https://github.com/mattpocock/skills) бейімделген.

## Бұл Rust-ты ескі дизайнға байлап тастамай ма?

Тек екеуі қатар жұмыс істеп тұрғанда ғана. Жазбалар мінез-құлықты ішкі құрылымнан емес, қолданбаның шекараларында (CLI шығысы, сервер жауаптары, модульдің экспортталған функциялары) тексереді. Бірліктер әлі bridge арқылы өтіп жатқанда ескі құрылымды қайталаңыз; `app lift` түпнұсқаны алып тастағаннан кейін Rust кодын еркін қайта құрылымдаңыз, ал `app replay` мінез-құлықты әлі де дәлелдейді.

## Нақты мысал

[json-server](/docs/real-world/json-server) әр қадамнан өтті: 514 жазылған HTTP кейсі, 99.8% fallback кезіндегі front door, алдымен оқулар қосылды (22.6% fallback), содан кейін әр маршрут (0%), және 514/514 өтетін таза Rust бинарлық файлына lift.
