# Үлес қосу

Көмегіңізге рахмет. Қате туралы хабарламалар, түзетулер, жаңа тіл қолдауы және нақты порттар туралы жазбалардың бәрі
құпталады, ал қатені түзететін pull request ашпас бұрын рұқсат сұраудың қажеті жоқ.

## Бастамас бұрын

- **Қате:** іске қосқан командаңыз, оның шығысы, платформаңыз және everything-rust нұсқасы
  (`everything-rust --version`) көрсетілген [issue](https://github.com/marprojector/everything-rust/issues/new/choose) ашыңыз.
  Кішкентай қайталау жобасы ең көп көмектеседі.
- **Үлкенірек өзгеріс** (жаңа тіл, жаңа команда, бірліктің немесе жазбаның не екенін өзгерту):
  жазбас бұрын пішіні туралы келісу үшін алдымен issue ашыңыз. Бұрынғы
  шешімдердің себептері [DECISIONS.md](https://github.com/marprojector/everything-rust/blob/main/DECISIONS.md) ішінде.
- **Қауіпсіздік мәселесі:** ашық issue ашпаңыз; [SECURITY.md](https://github.com/marprojector/everything-rust/blob/main/SECURITY.md) қараңыз.

## Баптау

Сізге Rust керек (stable, 1.97 немесе жаңарақ). Тесттер сондай-ақ әр бөлік өңдейтін тілді іске қосады және
runtime-ы жоқ бөлікті өткізіп жібереді, сондықтан өзіңіз өзгертетіндерін орнатыңыз:

| Не үшін | Орнату |
| --- | --- |
| TypeScript/JavaScript | Node 24 (`profile`-дан басқасы үшін 22.6+ жарайды) |
| Python | Python 3.9+ |
| C | C компиляторы (`cc`) |
| Go | Go 1.22+ |
| Ruby | Ruby 3.x |
| Java | JDK (17+) |
| PHP | PHP 8 |
| C# | .NET SDK |
| wasm bridge-тері | `rustup target add wasm32-unknown-unknown` және сәйкес `wasm-bindgen-cli` |

```sh
git clone https://github.com/marprojector/everything-rust
cd everything-rust
git config core.hooksPath .githooks
cargo test
```

`cargo run -- doctor` осы runtime-дардың қайсысы сізде бар екенін, олардың нұсқаларын және әрқайсысын
орнататын не жаңартатын команданы тізімдейді. Жоқ runtime тесттерін өткізіп жібермей, құлатуы үшін
(CI осылай істейді), оны `EVERYTHING_RUST_REQUIRE` ішінде атаңыз, мысалы
`EVERYTHING_RUST_REQUIRE=node,python3,go,ruby,java cargo test`.

Hook `scripts/check-secrets.sh` іске қосады, ол commit жасайтын нәрсеңіздегі кілттерді, токендерді және жеке
home-бума жолдарын қабылдамайды. CI оны әр файлда іске қосады.

## Өзгерісті енгізу

- **Әр түзету онсыз құлайтын тестпен бірге келеді.** Сенімді болу үшін тестті ескі кодқа қарсы бір рет
  іске қосыңыз.
- **Тесттер қайда орналасады:**
  - `tests/analyze.rs`: тілді анықтау, бірліктер, тәуекелдер, тәуелділіктер, `--whole-app`.
  - `tests/loop.rs`: әр тіл үшін bridge, record, diff және shadow, build-тердің орнына алмастырғыштармен.
  - `tests/native.rs`: шын құрастырылған, содан кейін жүктеліп, қайта ойнатылған bridge-тер.
  - `tests/app.rs` және `tests/http.rs`: CLI-лар мен серверлер үшін бүкіл қолданбаны жазып алу, қайта ойнату, front door және lift.
  - `tests/library.rs`: бүкіл кітапхана порттары.
  - Unit тесттер кодтың қасында орналасады.
- **Fixture-лер** `tests/fixtures/` астындағы кішкентай қолданбалар. CLI және HTTP fixture-лері әр тілде бірдей
  командалар мен маршруттарды жүзеге асырады (`tcli upper|len|div|words|copy|now`, `/hello`, `/upper`,
  `/div/{a}/{b}`, `/now`), сондықтан жаңасының мінез-құлқын басқаларымен бірдей етіп сақтаңыз.
- **Генерацияланған код** (everything-rust жазатын bridge-тер, драйверлер және front door-лар) да
  `clippy -D warnings` тексерісінен өтуі керек, өйткені `gate` оны пайдаланушылардың crate-терінде іске қосады.
- **Стиль:** айналаңыздағы кодқа сәйкес жазыңыз. Түсініктемелерді код өзі айта алмайтын нәрсе үшін қалдырыңыз, ал
  өзгерістің себебін оның орнына pull request ішінде жазыңыз.

## Crate сәйкестендіруін қосу

`analyze` код импорттайтын әр кітапхана үшін Rust crate-ін `src/crates.toml` ішінен атайды. Біреуін қосу
үшін оның тілі астына жазба қосыңыз: `names` (нақты пакет атаулары) немесе `prefixes` (атаудың басы,
Java мен C# үшін), `crates`, `fit` (`good`, `partial` немесе `none`) және сәйкестікті түсіндіру керек болса `note`.
Бірінші сәйкес келген жазба ұтады, сондықтан нақтыларын кең префикстерден бұрын қойыңыз. Кестеде
жоқ кітапхана `unknown` деп хабарланады; crate-ті ешқашан болжап жазбаңыз.

## Тіл қосу

PHP мен C# preview ретінде алдымен оқуға тұрарлық екі commit-те қосылды:
[e8ac243](https://github.com/marprojector/everything-rust/commit/e8ac243) (PHP) және
[caea59a](https://github.com/marprojector/everything-rust/commit/caea59a) (C#). Жаңа тіл де
солай басталады:

1. `src/lang/<name>.rs` ішіндегі плагин: табу, сканерлеу (импорттар мен тәуекелдер), шешу және экспорттар,
   сондай-ақ оның кітапханаларының crate-тері `src/crates.toml` ішінде `[[<name>]]` жазбалары ретінде.
2. `src/lang/mod.rs` ішінде анықтау және бағыттау.
3. `src/whole_app.rs` ішінде бүкіл қолданба қолдауы: кіру нүктелері, серверлер, жарияланған тәуелділіктер.
4. CLI және HTTP fixture-лері, кітапхана fixture-і және `tests/analyze.rs`, `tests/app.rs`
   мен `tests/http.rs` ішіндегі тесттер.
5. Bridge пайда болғанша `bridge` тілдің бірліктерін түсінікті хабармен қабылдамайды.

## README-ді аудару

Аудармалар құпталады және оларды қауымдастық жүргізеді. Жаңасы:

1. `docs/README_<CODE>.md` ішінде орналасады (мысалы `docs/README_PT.md`); түбірдегі `README.md`
   ағылшынша қалады және ешқашан қайта аталмайды не ауыстырылмайды.
2. `docs/` ішінен жұмыс істейтін жолдарды қолданады: `assets/logo.svg`, `../LICENSE`, `../README.md`.
3. Басқа аудармалардағыдай тіл жолынан басталады, өз тілі қарапайым мәтін ретінде,
   содан кейін оны қауымдастық жүргізетіні және ағылшынша README-ден артта қалуы мүмкін екені
   туралы ескерту (оны `docs/README_DE.md` ішінен көшіріп, аударыңыз).
4. Тіл жолының **соңына** қойылады, `README.md` ішінде де, әр аудармада да. Бұрыннан
   тізімделген тілдердің реті өзгермейді.

## Құжаттама сайты

Құжаттама сайты `website/` ішінде орналасқан (Void, `@void/md`, React). Оның көптеген беттері құрастыру кезінде
`README.md`, `CONTRIBUTING.md` және `docs/*.md` бөлімдерін қосады, сондықтан сол файлдарды өңдеңіз, сайт
соларға ілеседі. Оны `cd website && npm ci --ignore-scripts && npm run dev` арқылы іске қосыңыз, ал
`npm run build` арқылы құрастырыңыз. CLI анықтамалығы `website/content/cli-help.json` ішіндегі `--help` суретінен
алынады; CLI-ды өзгерткеннен кейін оны `website/` ішінде `cargo build --release` және
`npm run cli-help` арқылы жаңартыңыз.

## Pull request ашу

Push жасамас бұрын:

```sh
cargo fmt
cargo clippy --all-targets -- -D warnings
cargo test
```

- Не дұрыс емес болғанын, оны қалай қайталауға болатынын және өзгеріс оны қалай түзететінін айтыңыз.
- Issue-ді байланыстырыңыз (`Fixes #123`).
- Тексере алмаған кез келген нәрсені атап өтіңіз (басқа ОЖ, сізде жоқ runtime).
- Оны бір өзгеріспен шектеңіз: екі түзетуді екі pull request ретінде қарау оңайырақ.

CI барлық runtime-дар орнатылған Ubuntu мен macOS-та іске қосылады. Алғаш үлес қосушы үшін GitHub
CI іске қосылуын maintainer мақұлдағанша күтеді, сондықтан тексерулер басталмас бұрын аздаған кідіріс болады.

Pull request-тер commit-тері сақталып біріктіріледі, сондықтан тарихыңыз өзіңізде қалады. Өзгеріске
кішкентай түзетулер керек болса, maintainer тағы бір раунд сұраудың орнына үстіне commit қосуы мүмкін.

## Нақты портпен бөлісу

Нақты жобалардың порттары нені жұмыс істейтінін және нені бұзатынын көрсететін ең жақсы дәлел. Егер
everything-rust-ті нақты бір нәрседе қолдансаңыз, оны [docs/real-world.md](/docs/real-world/overview)
файлына қосатын issue немесе pull request өте құпталады. Жобаны, іске қосқан командаларыңызды,
кейстер санын және сізді таңғалдырған кез келген нәрсені көрсетіңіз.
