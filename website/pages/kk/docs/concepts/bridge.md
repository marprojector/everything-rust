# Bridge

```sh
everything-rust bridge <repo> <unit-id>          # crate <repo>/rust/<name> ішінде; ешқашан қайта жазбайды
everything-rust refresh <crate>                  # port.rs ішіндегі сигнатураны өзгерткеннен кейін
```

`bridge` байланыстырулары (`lib.rs`, сондай-ақ бастапқы тіл жүктейтін wrapper) және порттауға арналған stub-тары (`port.rs`) бар crate жасайды. Портты тек `src/port.rs` ішінде жазасыз; `src/lib.rs` пен wrapper-лер генерацияланады, ал `refresh` оларды `port.rs` ішіндегі сигнатуралардан қайта генерациялап, кез келген жаңа batch кластарын қосады. Ол `port.rs` файлына ешқашан қол тигізбейді.

Опциялар:

- `--batch fn:param` көптеген `param` мәндерін Rust ішінде ұстайтын класс қосады. [Batch-тар](/docs/concepts/batches) бетін қараңыз.
- `--as-json T` қолданба тек деректермен толтыратын тип параметріне (`paginate<T>(items: T[])` ішіндегі `T`) JSON мәндері ретінде bridge жасайды.
- `--keep "name: reason"` бастапқы тілде көбірек экспортты қалдырады, мысалы `Intl` деректеріне тәуелді код.
- `--kind` жоспар таңдаған bridge-ті ауыстырады (TypeScript үшін napi-rs немесе wasm).

## Әр тілдің bridge-і

| Тіл | Bridge |
| --- | --- |
| TypeScript/JavaScript | генерацияланған бинарлық wire бар napi-rs немесе wasm-bindgen; кластар мен async те бар |
| Python | PyO3 (abi3), тікелей түрлендіру, типтелген exception-дар |
| C | түпнұсқа атаулары мен header бар `extern "C"` функциялары |
| Go | типтелген cgo шақырулары және генерацияланған бинарлық wire, түпнұсқа API бар пакетте |
| Ruby | түпнұсқа модульдер астындағы magnus кеңейтімі |
| Java | типтелген JNI және генерацияланған бинарлық wire, түпнұсқа әдістері бар wrapper кластарында |

PHP және C# бірліктеріне әлі bridge жасау мүмкін емес; [PHP](/docs/languages/php) және [C#](/docs/languages/csharp) беттерін қараңыз.

## Bridge не шешеді

- Bridge арқылы өте алмайтын экспорттар себебі көрсетіліп бастапқы тілде қалады, ал shadow
  модулі түпнұсқаны қайта экспорттайды. TS үшін:
  функцияларды қабылдайтын немесе қайтаратын функциялар, генераторлар мен итераторлар, RegExp, `instanceof` тексерулері,
  generic-тер (`--as-json T` қолданба тек деректермен толтыратын біреуіне bridge жасайды), және типтерінде (импорттар, қайта экспорттар мен `extends` арқылы қадағаланады)
  функциялар бар мәндер. `--keep "name: reason"` көбірек қалдырады, мысалы `Intl` деректеріне тәуелді код.
- TS типтері Rust типтеріне сәйкестендіріледі, тип бүркеншік аттары импорттар арқылы шешіледі, ал параметр типтері
  әдепкі мәндерден шығарылады; құрылымды мәндер генерацияланған бинарлық wire ретінде өтеді (JSON тек
  wire модельдемейтін пішіндер үшін fallback ретінде).
- JSON `undefined`, NaN, Infinity, -0 немесе жалғыз суррогаттарды бере алмайды: құрылымды мәндер
  генерацияланған `index.cjs` аударатын белгілерді (`{"$undefined": true}`, `{"$num": "NaN"}`, `{"$utf16": [...]}`) тасымалдайды,
  көмекшілері crate-тің `js.rs` файлында.

`record` TS бастапқы файлдарын сол күйінде іске қосады: Node resolve hook-ы bundler стиліндегі импорттарды қадағалайды
(`./errors` бастап `./errors.ts` дейін), репозиторийде ештеңе орнатылмаған болса `--resolve-from` npm пакеттерін
береді, ал түрлендіруді қажет ететін TS (enum-дар, parameter properties)
`--experimental-transform-types` арқылы қайта іске қосылады.
