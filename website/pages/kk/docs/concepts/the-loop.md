# Цикл

Әр порт, бір ыстық функциядан бүкіл қолданбаға дейін, бір уақытта бір бірліктен сол қадамдардан өтеді. Порт тек `gate` өткенде ғана дайын.

everything-rust портты қалай тексереді, оның командалары нені шешеді және оның шектеулері қайда. [README](/) бетіне оралу.

## Қалай жұмыс істейді

```
profile ──> analyze ──> bridge ──> record ──> port.rs ──> diff ──> bench ──> shadow ──> gate
 where the    what to     the Rust   what the    you or      every     faster?    both side   done means
 time goes    port first  crate and  original    your agent  recorded  the        by side in  this passes
                          wrapper    does        write it    case      verdict    production
```

Түпнұсқа ақиқаттың көзі болып қала береді: `record` оны шеткі кейстерде (және өз кірістеріңізде) іске қосып,
оның не қайтаратынын немесе не лақтыратынын сақтайды; `diff` әр кейсті Rust-қа қарсы қайта ойнатады; барлығы
сәйкес келіп, `gate` өтпейінше ештеңе шығарылмайды. Шақырушылар бүкіл жол бойы түпнұсқа API-ді сақтайды.

Бүкіл қолданба да сол циклдан бірлік-бірлігімен өтеді, бүкіл бағдарламаны дәлелдейтін шеңбер ішінде
([Бүкіл қолданбаны порттау](/docs/whole-apps/overview)):

```

 shape, every           what the app    Rust owns the       gate passes, so the unit answers in         pure Rust,
 dependency, the        does from the   entry point; the     Rust: replay 100%, fallback rate down      proved by
 decisions to make      outside         original answers                                                replay
```

## Цикл

| Қадам | Команда | Не істейді |
| --- | --- | --- |
| 0. Profile | `everything-rust profile <repo> -- node bench.mjs` | Нақты жүктемені тілдің профайлері астында іске қосады (node, cProfile, `go test` pprof, JFR, Ruby трейсері): инклюзивті уақыт бойынша ыстық функциялар, олардың шақырушылары және қай циклдарға batch жасау керектігі; Rust аз ұтатын, компиляцияланып қойған кодты (numba, Cython, JAX) белгілейді |
| 1. Жоспар | `everything-rust analyze <repo>` | Бірліктер, порттау реті, `file:line` көрсетілген тәуекелдер, әр бірліктің bridge-і, тәуелділіктің crate-ке сәйкестігі, алғашқы порттау үшін ең жақсылары; `--whole-app` кіру нүктелері мен пішінді, әр тәуелділікті (импортталған немесе жарияланған) өз crate-імен, бөліктерді (бір-бірін импорттайтын бірліктер бірге көшеді) және ұсынылған жауабы бар нөмірленген шешімдерді қосады |
| 2. Bridge | `everything-rust bridge <repo> <unit>` | Байланыстырулары (`lib.rs`, сондай-ақ бастапқы тіл жүктейтін wrapper) және порттауға арналған stub-тары (`port.rs`) бар crate; `--batch fn:param` көптеген `param` мәндерін Rust ішінде ұстайтын класс қосады; `--as-json T` қолданба тек деректермен толтыратын тип параметріне JSON мәндері ретінде bridge жасайды |
| 3. Record | `everything-rust record <crate>` | Түпнұсқаны генерацияланған шеткі кейстерде (ASCII емес таңбалар, эмодзи, `-0`, `NaN`, float күтілетін жердегі int-тер, ...) және әр параметрдегі әр семантикалық тұзақта (жол ұзындығы мен регистрі, таңбалы бөлу, толып кету шекаралары, float-тарды басып шығару, map және сұрыптау реті) іске қосып, `cases.jsonl` сақтайды; `--from-tests -- npx jest` (немесе `-- pytest`) түпнұсқаның өз тест жиынтығы жасайтын әр шақыруды да жазып алады; `--float-tolerance 1e-9` сандық код үшін float-тарға сол үлес шегінде сәйкес келуге мүмкіндік береді |
| 3. Build | `everything-rust build <crate>` | Rust жағын құрастырады: `.node`, wasm пакеті, Python кеңейтімі немесе shared library |
| 3. Diff | `everything-rust diff <crate>` | Жазылған кейстерді Rust-қа қарсы, түпнұсқаның шақырушылары шақыратындай етіп қайта ойнатады; сәйкессіздіктерді тізімдейді |
| 3. Bench | `everything-rust bench <crate>` | Жазылған кейстерді түпнұсқада және Rust-та, bridge-ті қоса алғанда, уақытпен өлшейді |
| 4. Shadow | `everything-rust shadow <crate>` | Екеуін де іске қосып, түпнұсқаның нәтижесін қайтаратын, сәйкессіздіктерді хабарлайтын алмастырғыш; `EVERYTHING_RUST_MODE=old\|shadow\|new` |
| 5. Gate | `everything-rust gate <crate>` | fmt, clippy `-D warnings`, тесттер, `unsafe` аудиті, портталмаған ештеңе қалмауы, түпнұсқаның әр қате жолы үшін жазылған сәтсіз кейс, түпнұсқа қате қайтаратын жерде `unwrap`/`expect`/`panic!` болмауы (`// INFALLIBLE: <why>` деп белгіленбесе), build, API, мінез-құлық |
| Агенттер | `everything-rust setup` | MCP серверді (`everything-rust mcp`, әр қадам құрал ретінде) және workflow skill-ін ([`skills/everything-rust/SKILL.md`](https://github.com/marprojector/everything-rust/blob/main/skills/everything-rust/SKILL.md)) кодинг-агенттеріңізде тіркейді |

## Hot path-тар: деректерді Rust ішінде ұстау

Әр элемент үшін бір рет шақырылатын порт bridge үшін әр элементке бір рет төлейді және JIT-тен ұтылады. Ұтатын нәрсе
циклды көшіру: `profile` оны табады, ал `--batch` элементтерді бір рет алып, әр шақыруда функцияны олардың
барлығына барлық ядроларда, типтелген массив нәтижелерімен орындайтын класты генерациялайды.

```sh
everything-rust profile ../x18n -- node --experimental-strip-types $PWD/demo/x18n-search/search.ts .
# -> fuzzyScore: іске қосудың төрттен бірі, `matched` әр кілт үшін шақырады: batch жасаңыз
everything-rust bridge ../x18n packages/core/src/fuzzy.ts --batch fuzzyScore:text
```

```js
const search = new FuzzyScoreBatch(keys)          // once
const order = search.rank(query, 0)               // per keystroke: indexes, best first
```

`port.rs` ішіндегі `FuzzyScoreIndex` struct-ы әдепкі циклды элементтерді бір рет дайындайтын циклмен
алмастырады және өздігінен рейтингке қоя алады (`rank`): ол кілттерді кіші әріппен, әрқайсысын таңба маскасымен
сақтайды, әр кілттегі әр жиі кездесетін таңбаның бірінші позициясының кестесін (бір әріпті сұраныс бір
баған) және соңғы сұраныстың сәйкестіктерін ұстайды (`s`-тен кейін `se` теру тек `s` сәйкес келгендерді қайта бағалайды).
x18n бүйірлік панеліндегі 50,000 кілт бойынша іздеуде, әріп-әріппен терілгенде, нәтижелер бірдей:

| | Бір сұранысқа | TS-пен салыстырғанда |
| --- | ---: | ---: |
| TS: `map(fuzzyScore)`, filter, sort | 10 ms | 1x |
| Индекстегідей тарылтуы бар TS | 4.1-5.4 ms | 2x |
| Сол порт, әр кілт үшін шақырылады | - | 0.2-0.4x |
| `FuzzyScoreBatch`, әдепкі индекс (4 ядро) | 5.1 ms | 1.7x |
| `FuzzyScoreIndex` бар `FuzzyScoreBatch` (napi, 4 ядро) | 0.45-0.56 ms | **18-22x** |
| Wasm-мен дәл солай (бір ағын) | 0.95 ms | **11.5x** |

Дәл сондай тарылту жасайтын TS-пен салыстырғанда да Rust 7-12x жылдамырақ (wasm 5x). Қайтарылған
индекстерді кілттерге қарапайым циклмен айналдырыңыз: `Array.from(order, i => keys[i])` 20x қымбатқа, 0.4 ms-қа түсті.

Әр тіл batch-тарды алады, және олар бір шақырулық порттар ұтылатын жерде де түпнұсқадан озады.
4 ядродағы бірдей жұмыс, нәтижелер мен қателер бірдей (бенчмарктар әр demo бумасында):

| Тіл | Жүктеме | Түпнұсқа | Бір шақырулық порт түпнұсқамен салыстырғанда | Batch түпнұсқамен салыстырғанда |
| --- | --- | ---: | ---: | ---: |
| TS | x18n іздеуі, 50,000 кілт | 10 ms | 0.2-0.4x | **20x** |
| Python | `slugify`, 20,000 жол | 98 ms | - | **17x** |
| Ruby | `slugify`, 20,000 жол | 110 ms | - | **12.7x** |
| Ruby | `shellescape` (stdlib), 50,000 аралас мән | 88 ms | - | **11.8x** |
| Go | `Slugify`, 50,000 жол | 49 ms | 0.93x | **4x** |
| Java | `slugify`, 50,000 жол | 43 ms | 0.68x | **3x** |

Компиляцияланатын түпнұсқалар азырақ ұтады: әр элементке жұмыс онсыз да жылдам, сондықтан batch ядролар
санына қарай ұтады. Batch crate-тері mimalloc арқылы жады бөледі: жүйелік аллокатормен Go batch-і бір
ағыннан да баяу болды. Demo: [`demo/x18n-search`](https://github.com/marprojector/everything-rust/blob/main/demo/x18n-search/README.md).

## `bridge` не шешеді

- Bridge арқылы өте алмайтын экспорттар себебі көрсетіліп бастапқы тілде қалады, ал shadow
  модулі түпнұсқаны қайта экспорттайды. TS үшін:
  функцияларды қабылдайтын немесе қайтаратын функциялар, генераторлар мен итераторлар, RegExp, `instanceof` тексерулері,
  generic-тер (`--as-json T` қолданба тек деректермен толтыратын біреуіне bridge жасайды), және типтерінде (импорттар, қайта экспорттар мен `extends` арқылы қадағаланады)
  функциялар бар мәндер. `--keep "name: reason"` көбірек қалдырады, мысалы `Intl` деректеріне тәуелді код.
- TS типтері Rust типтеріне сәйкестендіріледі, тип бүркеншік аттары импорттар арқылы шешіледі, ал параметр типтері
  әдепкі мәндерден шығарылады; құрылымды мәндер генерацияланған бинарлық wire ретінде өтеді (JSON тек
  wire модельдемейтін пішіндер үшін fallback ретінде).
- JSON `undefined`, NaN, Infinity, -0 немесе жалғыз суррогаттарды бере алмайды: құрылымды мәндер
  генерацияланған `index.cjs` аударатын белгілерді (`{"$undefined": true}`, `{"$num": "NaN"}`, `{"$utf16": [...]}`) тасымалдайды,
  көмекшілері crate-тің `js.rs` файлында.

`record` TS бастапқы файлдарын сол күйінде іске қосады: Node resolve hook-ы bundler стиліндегі импорттарды қадағалайды
(`./errors` бастап `./errors.ts` дейін), репозиторийде ештеңе орнатылмаған болса `--resolve-from` npm пакеттерін
береді, ал түрлендіруді қажет ететін TS (enum-дар, parameter properties)
`--experimental-transform-types` арқылы қайта іске қосылады.

## `analyze` нені қарайды

- Пакеттер (`package.json`) және бастапқы файлдар; `node_modules`, build шығысы, fixture-лер,
  playground-тар, құрал конфигтері өткізіліп жіберіледі. Vue/Svelte/Astro `<script>` блоктары импорттар үшін парсталады.
- **Бірліктер**: бастапқы файлдар бумасы немесе пакеттің бастапқы түбіріндегі файл.
- **Толқындар**: бірліктің импорттары ертерек толқындарда келеді; импорт циклдары бірге портталады.
- **Bridge**: бірлікке немесе ол импорттайтын кез келген нәрсеге Node керек болса napi-rs; тасымалданатын
  код үшін wasm-bindgen; UI мен редактор коды үшін JS-те қалдыру.
- **Дайындық** (қаншалықты қауіпсіз) және **басымдық** (қауіпсіз әрі тұрарлық: циклдар мен жолдармен жұмыс, тесттер, өлшем).

| Тәуекел | Маңыздылығы | Мысал |
| --- | --- | --- |
| Жол офсеттері | жоғары | `slice`, `indexOf`, `matchAll`, `d` флагы: UTF-16 пен UTF-8 |
| Регекс синтаксисі | жоғары | lookaround, backreference, `y`: `regex` crate-інде жоқ |
| Динамикалық регекс | жоғары | `new RegExp(userPattern)`: іске қосу кезіндегі JS синтаксисі |
| Динамикалық код | жоғары | `eval`, `new Function`, есептелген `import()` |
| Динамикалық типтеу | орташа | `any`, `'key' in value` |
| Реттелген коллекциялар | орташа | `Map`, `Set`, `Object.keys`: енгізу реті |
| Async, генераторлар | орташа | promise және генератор шекаралары |
| Кластық мұрагерлік, reflection | орташа | `extends`, `Proxy`, `Reflect`, `Symbol` |
| Callback пішініндегі API-лер | орташа | функция типті параметрлер мен әдістер: көп сөйлесетін bridge-тер |
| Exception-дар, сандар, JSON | төмен | `throw`, биттік операциялар, `JSON.stringify` реті |

## Ол нені ұстай алмайды

Өту Rust жазылған әр кейске сәйкес келеді дегенді білдіреді, одан артық емес. Қайта жазуларға зиян
келтіретін нәрсе әдетте жазбадан тыс жатады, сондықтан шекаралардың қайда екенін біліңіз:

- **Ешкім жазып алмаған кірістер.** Генерацияланған кейстер, тұзақтар, түпнұсқаның тест жиынтығы
  (`record --from-tests`) және өзіңіздің `--inputs` шегі болып табылады. Нақты кірістерді қосыңыз (production
  үлгілері, қате туралы хабарламалар); prod-ты бұзатын пайдаланушы кірісі генератордың ойына сирек келеді.
- **Алға жылжыған түпнұсқа.** `record` бірлік файлдарының саусақ ізін сақтайды
  (`recorded-from.json`); кейін түпнұсқа өзгерсе, `diff` ескертеді, ал `gate` түпнұсқаның бұрын не
  істейтініне қарсы өтудің орнына, қайта жазып алмайынша құлайды.
- **Регекстер.** `regex` crate-інде lookaround немесе backreference жоқ, және тіпті компиляцияланатын
  үлгі де ASCII емес мәтінде `\w`, `\b`, `\d` және регистрге тәуелсіз салыстыруды JS, Python немесе Java-дан
  басқаша өңдеуі мүмкін. `fancy-regex`-ке ауыстыру немесе үлгіні қайта жазу әр жазылған кейстен өтіп,
  бәрібір түрік тіліндегі нүктесіз `ı` немесе zero-width joiner-де ерекшеленуі мүмкін. `record` регекс
  қолданатын файлдағы әр функцияға регекс тұзақтарын қосады (солар, Кельвин белгісі, ұзын s, араб-үнді
  цифрлары, жол бөлгіштер, соңғы сигма), бірақ нақты үлгілеріңізді нақты мәтінге қарсы fuzz-тестілеуді де ұмытпаңыз.
- **Іске қосулар арасында өзгеретін нәрсе.** `record` түпнұсқаны екі рет іске қосып, нені ерекшеленгенін
  сұрыптайды: өзгерген мәндер (уақыттар, id-лер) wildcard-қа айналады; басқа ретпен келген сол жолдар (hash map-тар,
  параллельдік) кез келген ретпен салыстырылады, сондықтан порт бәрібір дәл сол жолдарды шығаруы керек;
  жолдардың басқа саны `...` болады, ол кез келген нәрсеге сәйкес келеді. `record` әр түрін тізімдейді:
  әрқайсысын қараңыз, өйткені hash-рет немесе параллельдік айырмашылығы дәл портта шынымен өзгеруі мүмкін нәрсе.
- **Float-тар.** Санды мәтінге түрлендіру тілдер арасында ерекшеленеді (`1e21`, `-0`, цифрлар саны).
  Тұзақтар сол мәндерді қамтиды, және олар дәл сәйкес келуі керек; `--float-tolerance` тек
  дөңгелектеуді кешіреді, пішімдеуді ешқашан кешірмейді.
- **Шығыста жоқ кез келген нәрсе.** Уақыт, жады, жүктеме кезіндегі параллельдік және stdout, stderr, шығу кодтары,
  жазылған файлдар мен HTTP жауаптарынан басқа жанама әсерлер (желілік шақырулар, дерекқорлар,
  сигналдар) салыстырылмайды.
- **Басқа платформалар.** Жазба оны іске қосқан машинадағы мінез-құлықты дәлелдейді. Нәтижелері тип
  өлшемдеріне, байт ретіне немесе компиляторға тәуелді C коды target-те басқаша жұмыс істеуі мүмкін; сол себепті
  `analyze` аппаратурамен жұмыс істейтін C кодын C-да қалдырады.
## Әр қадам

| Қадам | Команда | Не істейді |
| --- | --- | --- |
| 0. Profile | `everything-rust profile <repo> -- node bench.mjs` | Нақты жүктемені тілдің профайлері астында іске қосады (node, cProfile, `go test` pprof, JFR, Ruby трейсері): инклюзивті уақыт бойынша ыстық функциялар, олардың шақырушылары және қай циклдарға batch жасау керектігі; Rust аз ұтатын, компиляцияланып қойған кодты (numba, Cython, JAX) белгілейді |
| 1. Жоспар | `everything-rust analyze <repo>` | Бірліктер, порттау реті, `file:line` көрсетілген тәуекелдер, әр бірліктің bridge-і, тәуелділіктің crate-ке сәйкестігі, алғашқы порттау үшін ең жақсылары; `--whole-app` кіру нүктелері мен пішінді, әр тәуелділікті (импортталған немесе жарияланған) өз crate-імен, бөліктерді (бір-бірін импорттайтын бірліктер бірге көшеді) және ұсынылған жауабы бар нөмірленген шешімдерді қосады |
| 2. Bridge | `everything-rust bridge <repo> <unit>` | Байланыстырулары (`lib.rs`, сондай-ақ бастапқы тіл жүктейтін wrapper) және порттауға арналған stub-тары (`port.rs`) бар crate; `--batch fn:param` көптеген `param` мәндерін Rust ішінде ұстайтын класс қосады; `--as-json T` қолданба тек деректермен толтыратын тип параметріне JSON мәндері ретінде bridge жасайды |
| 3. Record | `everything-rust record <crate>` | Түпнұсқаны генерацияланған шеткі кейстерде (ASCII емес таңбалар, эмодзи, `-0`, `NaN`, float күтілетін жердегі int-тер, ...) және әр параметрдегі әр семантикалық тұзақта (жол ұзындығы мен регистрі, таңбалы бөлу, толып кету шекаралары, float-тарды басып шығару, map және сұрыптау реті) іске қосып, `cases.jsonl` сақтайды; `--from-tests -- npx jest` (немесе `-- pytest`) түпнұсқаның өз тест жиынтығы жасайтын әр шақыруды да жазып алады; `--float-tolerance 1e-9` сандық код үшін float-тарға сол үлес шегінде сәйкес келуге мүмкіндік береді |
| 3. Build | `everything-rust build <crate>` | Rust жағын құрастырады: `.node`, wasm пакеті, Python кеңейтімі немесе shared library |
| 3. Diff | `everything-rust diff <crate>` | Жазылған кейстерді Rust-қа қарсы, түпнұсқаның шақырушылары шақыратындай етіп қайта ойнатады; сәйкессіздіктерді тізімдейді |
| 3. Bench | `everything-rust bench <crate>` | Жазылған кейстерді түпнұсқада және Rust-та, bridge-ті қоса алғанда, уақытпен өлшейді |
| 4. Shadow | `everything-rust shadow <crate>` | Екеуін де іске қосып, түпнұсқаның нәтижесін қайтаратын, сәйкессіздіктерді хабарлайтын алмастырғыш; `EVERYTHING_RUST_MODE=old\|shadow\|new` |
| 5. Gate | `everything-rust gate <crate>` | fmt, clippy `-D warnings`, тесттер, `unsafe` аудиті, портталмаған ештеңе қалмауы, түпнұсқаның әр қате жолы үшін жазылған сәтсіз кейс, түпнұсқа қате қайтаратын жерде `unwrap`/`expect`/`panic!` болмауы (`// INFALLIBLE: <why>` деп белгіленбесе), build, API, мінез-құлық |
| Агенттер | `everything-rust setup` | MCP серверді (`everything-rust mcp`, әр қадам құрал ретінде) және workflow skill-ін ([`skills/everything-rust/SKILL.md`](https://github.com/marprojector/everything-rust/blob/main/skills/everything-rust/SKILL.md)) кодинг-агенттеріңізде тіркейді |
