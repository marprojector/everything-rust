# Профайлдау және талдау

## Profile: көшіруге тұрарлық нәрсені табу

Мақсат жылдамдық болса, бірдеңе таңдамас бұрын өлшеңіз:

```sh
everything-rust profile <repo> -- node bench.mjs      # немесе: python3 bench.py, ruby bench.rb,
                                                    #     java -cp out Main, go test -run X -bench . ./pkg
```

`profile` нақты жүктемені тілдің профайлері астында іске қосады (node, cProfile, `go test` pprof, JFR, Ruby трейсері) және ыстық функцияларды инклюзивті уақыты, олардың шақырушылары бойынша, сондай-ақ қай циклдарға batch жасау керектігін тізімдейді. Go тек `go test` арқылы профайлданады; C-ға қолдау жоқ.

- Әр элемент үшін бір рет шақырылатын кішкентай функцияны жеке порттауға тұрмайды: Rust-қа бір шақыру оның жұмысынан қымбатқа түседі, ал JIT-тер (V8, JVM, Go) оны наносекундтарда орындайды. Оны шақырушыларымен бірге порттаңыз немесе [batch жасаңыз](/docs/concepts/batches). Кеңес жолы қайсысы екенін нақты командасымен айтады.
- Компиляцияланып қойған код (numba `@njit`, Cython, `@jax.jit`) машиналық код ретінде орындалады: Rust порты жылдамдықты аз ұтады. `profile` оны "Already compiled" астында тізімдейді.

## Analyze: портты жоспарлау

```sh
everything-rust analyze <repo> -o plan.md        # адамдар үшін
everything-rust analyze <repo> --json            # агенттер үшін: everything-rust/analyze@1 схемасы
everything-rust analyze <repo> --whole-app       # қосымша кіру нүктелері, пішін, тәуелділіктер, шешімдер
```

`analyze` бірліктерді, порттау ретін, `file:line` көрсетілген тәуекелдерді, әр бірліктің bridge-ін, әр тәуелділіктің crate-ке қаншалықты сәйкес келетінін және `start_here` тізімдейді: алғашқы порттау үшін ең жақсылары. `--whole-app` мыналарды қосады: қолданбаның пішіні (CLI, сервер немесе кітапхана) және кіру нүктелері, әр тәуелділік (импортталған немесе жарияланған) өз crate-імен, бөліктер (бір-бірін импорттайтын бірліктер бірге көшеді) және ұсынылған жауабы бар нөмірленген шешімдер. [Бүкіл қолданбаны порттау](/docs/whole-apps/overview) бетін қараңыз.

- Пакеттер (`package.json`) және бастапқы файлдар; `node_modules`, build шығысы, fixture-лер,
  playground-тар, құрал конфигтері өткізіліп жіберіледі. Vue/Svelte/Astro `<script>` блоктары импорттар үшін парсталады.
- **Бірліктер**: бастапқы файлдар бумасы немесе пакеттің бастапқы түбіріндегі файл.
- **Толқындар**: бірліктің импорттары ертерек толқындарда келеді; импорт циклдары бірге портталады.
- **Bridge**: бірлікке немесе ол импорттайтын кез келген нәрсеге Node керек болса napi-rs; тасымалданатын
  код үшін wasm-bindgen; UI мен редактор коды үшін JS-те қалдыру.
- **Дайындық** (қаншалықты қауіпсіз) және **басымдық** (қауіпсіз әрі тұрарлық: циклдар мен жолдармен жұмыс, тесттер, өлшем).

| Тәуекел | Маңыздылығы | Мысал |
| --- | --- | --- |
| Жол офсеттері | жоғары | `slice`, `indexOf`, `matchAll`, `d` флагы: UTF-16 пен UTF-8 |
| Регекс синтаксисі | жоғары | lookaround, backreference, `y`: `regex` crate-інде жоқ |
| Динамикалық регекс | жоғары | `new RegExp(userPattern)`: іске қосу кезіндегі JS синтаксисі |
| Динамикалық код | жоғары | `eval`, `new Function`, есептелген `import()` |
| Динамикалық типтеу | орташа | `any`, `'key' in value` |
| Реттелген коллекциялар | орташа | `Map`, `Set`, `Object.keys`: енгізу реті |
| Async, генераторлар | орташа | promise және генератор шекаралары |
| Кластық мұрагерлік, reflection | орташа | `extends`, `Proxy`, `Reflect`, `Symbol` |
| Callback пішініндегі API-лер | орташа | функция типті параметрлер мен әдістер: көп сөйлесетін bridge-тер |
| Exception-дар, сандар, JSON | төмен | `throw`, биттік операциялар, `JSON.stringify` реті |
## Тәуелділіктерге арналған crate-тер

`analyze` код импорттайтын әр кітапхана үшін Rust crate-ін `good`, `partial` немесе `none` сәйкестігімен атайды. Оның кестесінде жоқ кітапхана `unknown` деп хабарланады; кесте crate-ті ешқашан болжамайды. Біреуін қосу үшін [Үлес қосу](/docs/project/contributing#add-a-crate-mapping) бетін қараңыз.
