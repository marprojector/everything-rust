# 常见问题

关于 everything-rust 的常见问题。返回 [README](/)。

## 常见问题

**它会自动重写我的代码吗？** 不会。它找出该迁移什么，生成桥接层，
录制原实现的行为，并对照它校验 Rust 实现。`port.rs` 中的 Rust 代码由你或你的智能体编写；
由 `diff` 和 `gate` 判定它何时正确。

**我的应用的 API 会变吗？** 不会。调用方导入的是相同的函数（或者影子模块，它在你建立信心期间
同时运行两者，并返回原实现的结果）。

**Rust 一定更快吗？** 不一定，everything-rust 也会如实告诉你。每条数据调用一次的小函数
在 Rust 里往往更慢，因为每次调用都要跨过桥接层；V8、JVM 和 Go 运行这类函数
只需纳秒级时间。`profile` 会找到包在它外层的循环，`--batch` 把整个循环迁过去，`bench`
则在上线前给出结论。已经由 numba、Cython 或 JAX 编译的代码同样以机器码
运行：`profile` 和 `analyze` 会把它标出来，因为迁移它几乎换不来速度提升。

**我的代码偏数值计算，浮点数能完全一致吗？** 通常不能：不同编译器之间的运算顺序、乘加融合
（FMA）和数学库都不同。用 `--float-tolerance 1e-9` 录制
（`record` 或 `app record`），浮点数只要在较大值的该比例之内（绝对值小于
1 时按绝对误差）即可视为一致。整数、文本和结构仍然必须完全一致。

**我只有 APK、JAR 或 .exe，它能迁移这样的应用吗？** 不能。它迁移的是源码：它
解析函数，录制每个函数的行为，并对照运行中的原实现校验 Rust。
编译后的应用不具备这些条件，`analyze` 也会直接说明。根据二进制的可观测行为编写一个全新的 Rust
应用，是另一类项目。

**久经考验的 C 代码应该迁移吗？** 通常不该，`analyze` 会告诉你具体位置。操作
硬件寄存器、依赖编译器的类型大小或内存布局、或使用内联汇编的 C 代码
（`volatile`、位域、紧凑结构体、`__asm__`、整数强转为地址）会被标记为“保留在
C 中”：在你的机器上录制的结果证明不了目标平台上的任何行为，而且稳定的驱动或固件
代码从重写中获益很少。真正适合迁走的是它周围的可移植逻辑（解析、协议、数据处理）。

**它能迁移我的 Electron 应用吗？** 业务逻辑可以；窗口仍然是网页。`analyze
--whole-app` 会识别出 Electron，并规划把主进程逐块迁移，渲染进程则保持
原样。等逻辑全部变成 Rust 之后，再把 UI 迁到 Tauri（同一套 Web UI 跑在 Rust 后端上）是
单独的一步。

**C#、Kotlin 或 Swift 呢？** C# 处于预览阶段（见[支持语言](/docs/languages/overview)）；Kotlin 和
Swift 暂不支持。每种语言都需要解析器、录制器、桥接层和回放
驱动，而且都要经过端到端测试。如果你需要某种语言，请提一个 issue（或为已有的 issue 点赞）。

**移植出来的 Rust 会不会比原实现大很多？** 不应该。`gate` 会比较移植版与原实现的
行数，超过 3 倍（另加 50 行用于导入和签名）就会失败：这通常意味着在手写某个 crate 已经
提供的功能，或者在逐个处理各种情况。`analyze` 会列出应该使用的 crate。

**逐块迁移会不会把 Rust 锁死在旧应用的设计里？** 只在两者并行
运行期间才会。录制结果检查的是应用边界上的行为（CLI 的输出、服务端的
响应、模块导出的函数），而不是内部实现。在单元仍需跨越桥接层时，
沿用旧的结构；一旦 `app lift` 移除了原实现，你就可以自由重构 Rust 代码，
`app replay` 依然能验证行为。也不存在任何回调原实现的情况：
前门把原实现作为独立进程运行（或把 HTTP 请求转发给它），桥接的单元由
原实现调用，而绝不会反过来，回调函数也始终留在源语言中。

**我的代码会离开我的机器吗？** 不会：everything-rust 在本地运行，不会把你的任何代码
发送到任何地方。Cargo 会照常下载 crate；你的智能体发送给模型服务商的内容，
由该服务商按其自身政策处理。

**需要安装什么？** Rust，以及你要迁移的语言对应的运行时（见
[安装](/docs/introduction/install)）。

**遇到问题了。** 请提交 issue，附上命令、它的输出以及你的平台信息。
