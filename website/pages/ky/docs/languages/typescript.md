# TypeScript/JavaScript

| | |
| --- | --- |
| Бирдик | папка же файл |
| Bridge | генерацияланган бинардык wire менен napi-rs же wasm-bindgen; класстар жана async да бар |
| Ким жазып алат жана кайра ойнотот | Node, `.ts` баштапкы файлдарын түз иштетет |
| Керектүү | Node 22.6+ (`profile` үчүн Node 24+ керек) |
| Абалы | Текшерилген |

## Bridge'ди тандоо

`analyze` бирдикке же ал импорттогон бир нерсеге Node керек болсо napi-rs'ти, көчүрүлмө код үчүн wasm-bindgen'ди тандайт (ал браузерлерде да иштейт), ал эми UI жана редактор кодун JS'те калтырат. `bridge --kind napi|wasm` аны алмаштырат.

Bridge аркылуу өтө албаган экспорттор себеби көрсөтүлүп, TS'те калат, ал эми shadow модуль түп нусканы кайра экспорттойт: функцияларды кабыл алган же кайтарган функциялар, генераторлор жана итераторлор, RegExp, `instanceof` текшерүүлөрү, generic'тер (`--as-json T` колдонмо маалымат менен гана толтурганын өткөрөт) жана типтеринде функциялар бар маанилер. [Bridge](/docs/concepts/bridge) барагын караңыз.

## TS'ти болгондой жазып алуу

`record` TS баштапкы файлдарын түз иштетет: Node resolve hook bundler стилиндеги импорттор боюнча жүрөт, репозиторийде npm пакеттери орнотулбаса `--resolve-from` аларды берет, ал эми трансформацияны талап кылган TS (enum'дар, parameter properties) `--experimental-transform-types` менен кайра аракет кылынат. `record --from-tests -- npx jest` түп нусканын өзүнүн тесттери жасаган ар бир чакырууну каалаган runner менен жазып алат. Түп нусканын камтуусу TS/JS үчүн өлчөнөт ([Камтуу](/docs/concepts/coverage)).

## Порт эмнени туура жасашы керек

Чыныгы коддогу жазылган кейстер аркылуу табылган:

- `str.length`, `indexOf` жана `slice` UTF-16 код бирдиктерин санайт, ошондуктан эмодзи эки позицияны ээлейт. Генерацияланган `utf16` жардамчыларын колдонуңуз.
- `u` желегисиз `/.../i` ASCII тамгаларын гана регистрге көз карандысыз салыштырат, ал эми Rust'тун `regex`'и Unicode'ду да камтыйт, ошондуктан vercel/ms'те `"1 ſ"` (узун s) жана Кельвин белгиси секунда катары талданмак.
- `Math.round` жарымдарды жогору тегеректейт (`-2.5` `-2` берет); Rust'тун `round`'у нөлдөн алыстатат. Генерацияланган `js.rs`'те `js::math_round` бар.
- `${n}` `1e+21`, `5e-324` жана `-0` үчүн `0` басып чыгарат. `js::number_to_string` муну кайталайт.
- `String.prototype.trim` Rust'тун `char::is_whitespace`'ин эмес, JS боштук символдорун колдонот.

## Ылдамдык

Бир чакырууда порт ар бир жолу bridge үчүн төлөйт, ал эми V8 кичинекей функцияларды наносекунддарда иштетет. vercel/ms өзүнүн жазылган кейстеринде бир чакырууга 0.56x менен иштеди; x18n ядросунун порттору JS'тен чакырылганда TS'тен жайыраак. Batch катары цикл Rust'ка көчөт:

| Жүктөм | Түп нуска | everything-rust менен |
| --- | ---: | ---: |
| x18n каптал панелиндеги издөө, 50,000 ачкыч (Node) | бир суроого 10 ms | 0.5 ms: 20x ылдамыраак |
| Ошол эле издөө браузерде (wasm, бир агым) | 10 ms | 0.95 ms: 11.5x |
| Fuse.js, 50,000 сап | 91.2 ms | 2.8 ms: 32x |
| vercel/ms `parse` x100,000 | 11.8 ms | 0.65 ms: 18x (берүүнү эсептегенде 3.4x) |
| vercel/ms `format` x100,000 | 2.1 ms | берүү менен 2.5 ms: 0.8x |

Практикалык мисалдар: [json-server](/docs/real-world/json-server), [Fuse.js](/docs/real-world/fuse-js), [vercel/ms](/docs/real-world/vercel-ms), [x18n](/docs/real-world/x18n).
