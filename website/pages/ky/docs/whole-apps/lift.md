# Lift

Replay 0 fallback rate менен өтүп, ар бир бирдик gate'тен өткөндө, аны таза Rust колдонмосуна айлантыңыз:

```sh
everything-rust app lift .
```

- `app lift` экөө тең аткарылмайынча баш тартат жана эмне тоскоол болуп жатканын айтат: дагы эле fallback'ке түшкөн кейстер, дагы эле stub абалындагы glue, gate'тен өтпөгөн бирдиктер.
- Адегенде көчүрмөдө ал fallback жолун жана kill switch'терди алып салат, ар бир бирдик crate'ин `rust/app`'тын жөнөкөй китепканасына айлантат (`cdylib`, байланыштар же генерацияланган wrapper'лер жок) жана `rust/app/tests/app_cases.rs` кошот, ал `cargo test` учурунда `rust/app-cases`'ти trycmd менен иштетет, ошентип CI'га cargo'дон башка эч нерсе керек эмес.
- Андан кийин ал lift чек-листин иштетет: ар бир бирдикте жана `rust/app`'та fmt, clippy `-D warnings` жана тесттер, `rust/DECISIONS.md` ичинде аталган ар бир target орнотулган жерде курулат же текшерилет, иштөө убагында окулган файлдар жана asset папкалары камтылбаганы текшерилет, жана таза бинардык файлда replay. Баары өткөндө гана өзгөртүүлөр кайра жазылат. Түп нускага эч качан тийбейт.

## Lift'тен кийин

Бирдиктерде мындан ары байланыштар жок. json-server'де ар бир crate'тин `tests/recorded.rs` файлы өзүнүн жазылган кейстерин портто кайра ойнотот: бардык 3,399у `cargo test` менен, 514 HTTP кейсинин жанында иштейт.

Түп нуска жоголгондон кийин Rust'ту эркин кайра түзүңүз; `app replay` жүрүм-турумду дагы эле далилдейт.

## Андан кийин өтүү (cutover)

Workflow skill агентке колунан келгенин жасатып, `rust/cutover.sh` жаздырат: бул сиз гана аткара турган кадамдар (deploy'лор, DNS, secret'тер) үчүн интерактивдүү скрипт, ар бир кадамда артка кайтуу жолу менен.
