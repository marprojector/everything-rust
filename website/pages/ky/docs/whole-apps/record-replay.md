# Жазып алуу жана кайра ойнотуу

`record` жана `diff` бир бирдикти далилдейт; `app record` жана `app replay` колдонмону далилдейт, алты тилдин каалаганындагы CLI'лар жана серверлер үчүн. Колдонмо кара куту катары каралат.

```sh
everything-rust app record . -- python3 cli.py          # the command that runs the original
everything-rust app replay .                            # the original must pass 100%
everything-rust app replay . --build "target/release/mytool"
```

## Кейстер кайдан келет

`app record` түп нусканы төмөнкүлөрдө иштетет:

- колдонмонун өзүнүн документтештирилген мисалдары: анын Markdown жана shell файлдарындагы `$ mytool ...` саптары, алар атаган файлдар менен;
- `--inputs` JSONL файлы, ар бир сапта бир `{"name", "args", "stdin", "env", "files"}`;
- ошол кейстерден алынган семантикалык тузактар: ASCII эмес жана эмодзи саптары, терс бөлүү жана модуль боюнча калдык, толуп кетүү, чоң жана өтө кичине float'тар, map тартиби, жок файлдар.

Ар бир кейс эки жолу иштетилет; эки иштетүүнүн ортосунда айырмаланган нерсе `[..]` wildcard'ына айланат. `--normalize timestamps|uuids|key-order` же `--normalize name=regex` кейстер менен бирге сакталган нормализаторлорду кошот. `app record` эмне айырмаланганын түрү боюнча көрсөтөт: маанилер (эми wildcard'тар), тартип (саптар каалаган тартипте салыштырылат) жана саптар (каалаган нерсеге дал келген `...`). Ар бирин карап чыгыңыз.

## Кейстер жөнөкөй файлдар

Кейстер `rust/app-cases/` ичиндеги [trycmd](https://docs.rs/trycmd) файлдары:

| Файл | Эмнени камтыйт |
| --- | --- |
| `<case>.toml` | argv, env, чыгуу коду |
| `<case>.stdin` | стандарттык киргизүү |
| `<case>.stdout`, `<case>.stderr` | түп нуска эмне басып чыгарганы |
| `<case>.in/` | кирген файлдар |
| `<case>.out/` | жазылган файлдар |

Аларды кол менен окуп, оңдоңуз; порттун бинардык файлы пайда болгондо Rust тести аларды `trycmd` менен иштете алат.

## Кайра ойнотуу

- `app replay` каалаган build'ди кейстерге каршы иштетет, `passed/total` басып чыгарат, ар бир өтпөгөн кейс үчүн diff менен `rust/app-cases/replay-report.md` жазат жана каалаган дал келбестикте нөлдөн башка код менен аяктайт.
- `EVERYTHING_RUST_FALLBACK_LOG` аталган файлга сап кошкон build (түп нускага ар бир fallback үчүн бир сап), [front door](/docs/whole-apps/front-door) сыяктуу, өзүнүн fallback rate көрсөткүчүн да алат.
- `app replay --case <name>` бир кейсти отчет берген аты боюнча кайра иштетет: баарын кайра иштетүүдөн мурун дал келбестикти оңдоо үчүн ылдам, кайталана турган цикл.

## CI'да кайра ойнотуу

Отчетто убакыттар же убактылуу жолдор жок: бир эле build'дин эки кайра ойнотуусу бирдей файл жазат. Аны commit кылыңыз, андан кийин CI'да иштетиңиз:

```sh
everything-rust app replay .
git diff --exit-code rust/app-cases/replay-report.md
```

Ошондо жарым-жартылай порттолгон колдонмо өткөн нерседеги каалаган өзгөрүүдө, жакшы же жаман болсун, отчет аны менен жаңыртылмайынча CI'дан өтпөйт.

## Сандык чыгыш

`app record --float-tolerance 1e-9` сандарга чоңураак маанинин ошол үлүшүнүн чегинде дал келүүгө уруксат берет. [Float тактыгы](/docs/concepts/float-tolerance) барагын караңыз.
