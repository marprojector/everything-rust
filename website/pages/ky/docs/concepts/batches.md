# Batch'тар жана hot path'тар

```sh
everything-rust bridge <repo> <unit> --batch fn:param    # or: everything-rust refresh <crate> --batch fn:param
```

`--batch` `param` маанилерин бир жолу кабыл алып, аларды Rust ичинде сактаган класс генерациялайт: `new FnBatch(items)` (TS, Python, Java), `Mod::FnBatch.new(items)` (Ruby), `NewFnBatch(items)` (Go). Ар бир суроо үчүн `run(<other args>)` бардык натыйжаларды бир массив катары кайтарат, ал эми `rank(<other args>, min)` элементтердин индекстерин эң жакшысынан баштап кайтарат. Ал бардык ядролордо иштейт, ал эми каталар түп нусканыкындай. C'дан башка ар бир тил batch'тарды алат.

Ар бир элемент үчүн бир жолу чакырылган порт bridge үчүн ар бир элементке бир жолу төлөйт жана JIT'ке утулат. Утуучу нерсе
циклди көчүрүү: `profile` аны табат, ал эми `--batch` элементтерди бир жолу кабыл алып,
ар бир чакырууда функцияны алардын баарында, бардык ядролордо иштетип, натыйжаларды typed array катары берген класс генерациялайт.

```sh
everything-rust profile ../x18n -- node --experimental-strip-types $PWD/demo/x18n-search/search.ts .
# -> fuzzyScore: a quarter of the run, called per key by `matched`: batch it
everything-rust bridge ../x18n packages/core/src/fuzzy.ts --batch fuzzyScore:text
```

```js
const search = new FuzzyScoreBatch(keys)          // once
const order = search.rank(query, 0)               // per keystroke: indexes, best first
```

`port.rs` ичиндеги `FuzzyScoreIndex` struct'у демейки циклди элементтерди бир жолу даярдаган цикл менен алмаштырат
жана өзү тизмектей алат (`rank`): ал ачкычтарды кичине тамгага айландырылган абалда, ар бирин символ маскасы менен,
ар бир ачкычтагы ар бир жалпы символдун биринчи позициясынын таблицасын (бир тамгалуу суроо бир
мамыча) жана акыркы суроонун дал келүүлөрүн сактайт (`s`'тен кийин `se` терүү `s` дал келгендерди гана кайра баалайт). x18n'дин
50,000 ачкыч боюнча каптал панелиндеги издөөсүндө, тамгалап терилгенде, натыйжалар бирдей:

| | Бир суроого | TS'ке салыштырмалуу |
| --- | ---: | ---: |
| TS: `map(fuzzyScore)`, filter, sort | 10 ms | 1x |
| Индекстегидей эле тарытуу менен TS | 4.1-5.4 ms | 2x |
| Ошол эле порт, ар бир ачкычка чакырылган | - | 0.2-0.4x |
| `FuzzyScoreBatch`, демейки индекс (4 ядро) | 5.1 ms | 1.7x |
| `FuzzyScoreIndex` менен `FuzzyScoreBatch` (napi, 4 ядро) | 0.45-0.56 ms | **18-22x** |
| Ошол эле wasm менен (бир агым) | 0.95 ms | **11.5x** |

Ошол эле тарытууну жасаган TS'ке каршы да Rust 7-12x ылдамыраак (wasm 5x). Кайтарылган
индекстерди ачкычтарга жөнөкөй цикл менен айлантыңыз: `Array.from(order, i => keys[i])` 20x кымбатыраак, 0.4 ms турду.

Ар бир тил batch'тарды алат жана алар бир чакырууга порттор утулган жерде да түп нусканы утат. Ошол
эле иш 4 ядродо, натыйжалар жана каталар бирдей (бенчмарктар ар бир demo папкасында):

| Тил | Жүктөм | Түп нуска | Бир чакырууга порт түп нускага каршы | Batch түп нускага каршы |
| --- | --- | ---: | ---: | ---: |
| TS | x18n издөөсү, 50,000 ачкыч | 10 ms | 0.2-0.4x | **20x** |
| Python | `slugify`, 20,000 сап | 98 ms | - | **17x** |
| Ruby | `slugify`, 20,000 сап | 110 ms | - | **12.7x** |
| Ruby | `shellescape` (stdlib), 50,000 аралаш маани | 88 ms | - | **11.8x** |
| Go | `Slugify`, 50,000 сап | 49 ms | 0.93x | **4x** |
| Java | `slugify`, 50,000 сап | 43 ms | 0.68x | **3x** |

Компиляцияланган түп нускалар азыраак утушат: бир элементке кеткен иш буга чейин эле ылдам, ошондуктан batch
ядролордун саны эсебинен утат. Batch crate'тери mimalloc менен эс бөлөт: системалык аллокатор менен Go batch'ы
бир агымдан жайыраак болгон. Demo: [`demo/x18n-search`](https://github.com/marprojector/everything-rust/blob/main/demo/x18n-search/README.md).
## Ылдам индекс жазуу

- Чакыруучуга batch'ты ар бир суроого эмес, бир жолу курдуруңуз. Кайтарылган индекстерди элементтерге жөнөкөй цикл менен кайра айлантыңыз.
- Элементтерди бир жолу даярдоо үчүн (кичине тамга, маскалар, позиция таблицалары) `port.rs` ичинде `new(items)` жана `run(<other args>)` менен `pub struct FnIndex` аныктаңыз. Ал элемент-элементи боюнча функция менен бирдей натыйжа бериши керек.
- Тизмектөө ишти өткөрүп жибере алганда, индекске өзүнүн `rank(<other args>, min)` методун бериңиз. Ал функциянын натыйжаларын тизмектөөгө дал келиши керек: упай жогорудан төмөнгө, теңдерде элементтердин тартиби менен.
- Batch порттун бир элементке ылдамдыгын ядролорго көбөйтөт. Компиляцияланган түп нускаларга (Go, Java) каршы порттун өзү ылдам болушу керек: ASCII'ни Unicode таблицаларысыз иштетиңиз, ар бир натыйжаны алдын ала өлчөмү берилген бир `String` ичинде куруңуз, ортодогу көчүрмөлөрдөн качыңыз.
- Go жана Java'да иш бүткөндө batch'ты жабыңыз (finalizer'лер fallback гана).
