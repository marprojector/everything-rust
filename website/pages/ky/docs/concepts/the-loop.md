# Цикл

Ар бир порт, бир ысык функциядан бүт колдонмого чейин, ошол эле кадамдардан бир убакта бир бирдик менен өтөт. Порт `gate` өткөндө гана даяр болот.

everything-rust портту кантип текшерет, анын буйруктары эмнени чечет жана анын чектери кайда. [README](/) барагына кайтуу.

## Кантип иштейт

```
profile ──> analyze ──> bridge ──> record ──> port.rs ──> diff ──> bench ──> shadow ──> gate
 where the    what to     the Rust   what the    you or      every     faster?    both side   done means
 time goes    port first  crate and  original    your agent  recorded  the        by side in  this passes
                          wrapper    does        write it    case      verdict    production
```

Түп нуска чындыктын булагы бойдон калат: `record` аны чектик кейстерде (жана өзүңүздүн киргизүүлөрүңүздө) иштетип,
ал эмне кайтарарын же кандай ката ыргытарын сактайт; `diff` ар бир кейсти Rust'ка каршы кайра ойнотот; алардын баары дал
келмейинче жана `gate` өтмөйүнчө эч нерсе чыгарылбайт. Чакыруучулар бүт жол бою түп нуска API'син сакташат.

Бүт колдонмо ошол эле циклден бирдик-бирдиги менен, бүт программаны далилдеген алкактын ичинде өтөт
([Бүт колдонмону порттоо](/docs/whole-apps/overview)):

```
 dependency, the        does from the   entry point; the     Rust: replay 100%, fallback rate down      proved by
 decisions to make      outside         original answers                                                replay
```

## Цикл

| Кадам | Буйрук | Эмне кылат |
| --- | --- | --- |
| 0. Profile | `everything-rust profile <repo> -- node bench.mjs` | Чыныгы жүктөмдү тилдин профилдөөчүсү астында иштетет (node, cProfile, `go test` pprof, JFR, Ruby tracer): ысык функциялар инклюзивдүү убакыт боюнча, алардын чакыруучулары жана кайсы циклдерди batch кылуу керек; Rust аз пайда берген, буга чейин компиляцияланган кодду (numba, Cython, JAX) белгилейт |
| 1. Plan | `everything-rust analyze <repo>` | Бирдиктер, порттоо тартиби, `file:line` менен тобокелдиктер, ар бир бирдиктин bridge'и, көз карандылыктын crate'ке шайкештиги, биринчи порттоо үчүн эң жакшылары; `--whole-app` кирүү чекиттерин жана форманы, ар бир көз карандылыкты (импорттолгон же жарыяланган) анын crate'и менен, бөлүктөрдү (бири-бирин импорттогон бирдиктер чогуу көчөт) жана сунушталган жооп менен номерленген чечимдерди кошот |
| 2. Bridge | `everything-rust bridge <repo> <unit>` | Байланыштары (`lib.rs`, плюс баштапкы тил жүктөгөн wrapper) жана порттоо үчүн stub'тары (`port.rs`) бар crate; `--batch fn:param` көптөгөн `param` маанилерин Rust ичинде сактаган класс кошот; `--as-json T` колдонмо маалымат менен гана толтурган тип параметрин JSON маанилери катары өткөрөт |
| 3. Record | `everything-rust record <crate>` | Түп нусканы генерацияланган чектик кейстерде (ASCII эмес текст, эмодзи, `-0`, `NaN`, float күтүлгөн жерде int'тер, ...) жана ар бир параметрдеги ар бир семантикалык тузакта (саптын узундугу жана регистри, белгилүү бөлүү, толуп кетүү чектери, float'тарды басып чыгаруу, map жана сорттоо тартиби) иштетип, `cases.jsonl` сактайт; `--from-tests -- npx jest` (же `-- pytest`) түп нусканын өзүнүн тесттери жасаган ар бир чакырууну да жазып алат; `--float-tolerance 1e-9` сандык код үчүн float'тарга ошол үлүштүн чегинде дал келүүгө уруксат берет |
| 3. Build | `everything-rust build <crate>` | Rust тарабын курат: `.node`, wasm пакети, Python кеңейтүүсү же shared library |
| 3. Diff | `everything-rust diff <crate>` | Жазылган кейстерди Rust'ка каршы, түп нусканын чакыруучулары кантип чакырса ошондой чакырып, кайра ойнотот; дал келбестиктерди тизмектейт |
| 3. Bench | `everything-rust bench <crate>` | Жазылган кейстерди түп нускада жана Rust'та, bridge'ди кошо, убакытка өлчөйт |
| 4. Shadow | `everything-rust shadow <crate>` | Экөөн тең иштеткен, түп нусканын натыйжасын кайтарган жана дал келбестиктер жөнүндө кабарлаган drop-in алмаштыргыч; `EVERYTHING_RUST_MODE=old\|shadow\|new` |
| 5. Gate | `everything-rust gate <crate>` | fmt, clippy `-D warnings`, тесттер, `unsafe` аудити, портталбаган эч нерсе калбашы, түп нусканын ар бир ката жолу үчүн жазылган ийгиликсиз кейс, түп нуска ката кайтарган жерде `unwrap`/`expect`/`panic!` болбошу (`// INFALLIBLE: <why>` деп белгиленбесе), build, API, жүрүм-турум |
| Агенттер | `everything-rust setup` | MCP серверди (`everything-rust mcp`, ар бир кадам курал катары) жана workflow skill'ин ([`skills/everything-rust/SKILL.md`](https://github.com/marprojector/everything-rust/blob/main/skills/everything-rust/SKILL.md)) коддоо агенттериңиз менен каттайт |

## Hot path'тар: маалыматты Rust ичинде кармоо

Ар бир элемент үчүн бир жолу чакырылган порт bridge үчүн ар бир элементке бир жолу төлөйт жана JIT'ке утулат. Утуучу нерсе
циклди көчүрүү: `profile` аны табат, ал эми `--batch` элементтерди бир жолу кабыл алып,
ар бир чакырууда функцияны алардын баарында, бардык ядролордо иштетип, натыйжаларды typed array катары берген класс генерациялайт.

```sh
everything-rust profile ../x18n -- node --experimental-strip-types $PWD/demo/x18n-search/search.ts .
# -> fuzzyScore: a quarter of the run, called per key by `matched`: batch it
everything-rust bridge ../x18n packages/core/src/fuzzy.ts --batch fuzzyScore:text
```

```js
const search = new FuzzyScoreBatch(keys)          // once
const order = search.rank(query, 0)               // per keystroke: indexes, best first
```

`port.rs` ичиндеги `FuzzyScoreIndex` struct'у демейки циклди элементтерди бир жолу даярдаган цикл менен алмаштырат
жана өзү тизмектей алат (`rank`): ал ачкычтарды кичине тамгага айландырылган абалда, ар бирин символ маскасы менен,
ар бир ачкычтагы ар бир жалпы символдун биринчи позициясынын таблицасын (бир тамгалуу суроо бир
мамыча) жана акыркы суроонун дал келүүлөрүн сактайт (`s`'тен кийин `se` терүү `s` дал келгендерди гана кайра баалайт). x18n'дин
50,000 ачкыч боюнча каптал панелиндеги издөөсүндө, тамгалап терилгенде, натыйжалар бирдей:

| | Бир суроого | TS'ке салыштырмалуу |
| --- | ---: | ---: |
| TS: `map(fuzzyScore)`, filter, sort | 10 ms | 1x |
| Индекстегидей эле тарытуу менен TS | 4.1-5.4 ms | 2x |
| Ошол эле порт, ар бир ачкычка чакырылган | - | 0.2-0.4x |
| `FuzzyScoreBatch`, демейки индекс (4 ядро) | 5.1 ms | 1.7x |
| `FuzzyScoreIndex` менен `FuzzyScoreBatch` (napi, 4 ядро) | 0.45-0.56 ms | **18-22x** |
| Ошол эле wasm менен (бир агым) | 0.95 ms | **11.5x** |

Ошол эле тарытууну жасаган TS'ке каршы да Rust 7-12x ылдамыраак (wasm 5x). Кайтарылган
индекстерди ачкычтарга жөнөкөй цикл менен айлантыңыз: `Array.from(order, i => keys[i])` 20x кымбатыраак, 0.4 ms турду.

Ар бир тил batch'тарды алат жана алар бир чакырууга порттор утулган жерде да түп нусканы утат. Ошол
эле иш 4 ядродо, натыйжалар жана каталар бирдей (бенчмарктар ар бир demo папкасында):

| Тил | Жүктөм | Түп нуска | Бир чакырууга порт түп нускага каршы | Batch түп нускага каршы |
| --- | --- | ---: | ---: | ---: |
| TS | x18n издөөсү, 50,000 ачкыч | 10 ms | 0.2-0.4x | **20x** |
| Python | `slugify`, 20,000 сап | 98 ms | - | **17x** |
| Ruby | `slugify`, 20,000 сап | 110 ms | - | **12.7x** |
| Ruby | `shellescape` (stdlib), 50,000 аралаш маани | 88 ms | - | **11.8x** |
| Go | `Slugify`, 50,000 сап | 49 ms | 0.93x | **4x** |
| Java | `slugify`, 50,000 сап | 43 ms | 0.68x | **3x** |

Компиляцияланган түп нускалар азыраак утушат: бир элементке кеткен иш буга чейин эле ылдам, ошондуктан batch
ядролордун саны эсебинен утат. Batch crate'тери mimalloc менен эс бөлөт: системалык аллокатор менен Go batch'ы
бир агымдан жайыраак болгон. Demo: [`demo/x18n-search`](https://github.com/marprojector/everything-rust/blob/main/demo/x18n-search/README.md).

## `bridge` эмнени чечет

- Bridge аркылуу өтө албаган экспорттор себеби көрсөтүлүп, баштапкы тилде калат, ал эми shadow
  модуль түп нусканы кайра экспорттойт. TS үчүн:
  функцияларды кабыл алган же кайтарган функциялар, генераторлор жана итераторлор, RegExp, `instanceof` текшерүүлөрү,
  generic'тер (`--as-json T` колдонмо маалымат менен гана толтурганын өткөрөт) жана типтеринде (импорттор, кайра экспорттор жана `extends` аркылуу аныкталган)
  функциялар бар маанилер. `--keep "name: reason"` көбүрөөгүн калтырат, мисалы `Intl` маалыматына көз каранды кодду.
- TS типтери Rust типтерине шайкештелет, тип alias'тары импорттор аркылуу чечилет, ал эми параметр типтери
  демейки маанилерден аныкталат; структуралык маанилер генерацияланган бинардык wire катары өтөт (JSON wire
  моделдебеген формалар үчүн гана fallback катары).
- JSON `undefined`, NaN, Infinity, -0 же жалгыз surrogate'терди туюндура албайт: структуралык маанилер
  генерацияланган `index.cjs` которгон белгилерди (`{"$undefined": true}`, `{"$num": "NaN"}`, `{"$utf16": [...]}`) алып жүрөт,
  жардамчылары crate'тин `js.rs` файлында.

`record` TS баштапкы файлдарын болгондой иштетет: Node resolve hook bundler стилиндеги импорттор боюнча жүрөт
(`./errors` → `./errors.ts`), репозиторийде npm пакеттери орнотулбаса `--resolve-from` аларды берет, ал эми
трансформацияны талап кылган TS (enum'дар, parameter properties) `--experimental-transform-types` менен кайра аракет кылынат.

## `analyze` эмнени карайт

- Пакеттер (`package.json`) жана баштапкы файлдар; `node_modules`, build чыгышы, fixture'лер,
  playground'дор, курал конфигурациялары өткөрүлүп жиберилет. Vue/Svelte/Astro `<script>` блоктору импорттор үчүн талданат.
- **Бирдиктер**: баштапкы файлдардан турган папка же пакеттин баштапкы тамырындагы файл.
- **Толкундар**: бирдиктин импорттору мурунку толкундарда келет; импорт циклдери чогуу порттолот.
- **Bridge**: бирдикке же ал импорттогон бир нерсеге Node керек болсо napi-rs; көчүрүлмө код үчүн
  wasm-bindgen; UI жана редактор коду үчүн JS'те калтыруу.
- **Даярдык** (канчалык коопсуз) жана **приоритет** (коопсуз жана арзыйт: циклдер жана сап менен иштөө, тесттер, өлчөм).

| Тобокелдик | Олуттуулук | Мисал |
| --- | --- | --- |
| Саптагы позициялар | жогору | `slice`, `indexOf`, `matchAll`, `d` желеги: UTF-16 жана UTF-8 |
| Regex синтаксиси | жогору | lookaround, backreference, `y`: `regex` crate'инде жок |
| Динамикалык regex | жогору | `new RegExp(userPattern)`: иштөө убагындагы JS синтаксиси |
| Динамикалык код | жогору | `eval`, `new Function`, эсептелген `import()` |
| Динамикалык типтөө | орто | `any`, `'key' in value` |
| Тартиптелген коллекциялар | орто | `Map`, `Set`, `Object.keys`: кошулуу тартиби |
| Async, генераторлор | орто | promise жана генератор чектери |
| Класстардын мурасы, reflection | орто | `extends`, `Proxy`, `Reflect`, `Symbol` |
| Callback формасындагы API'лер | орто | функция типтеги параметрлер жана методдор: көп сүйлөгөн bridge'дер |
| Exception'дор, сандар, JSON | төмөн | `throw`, биттик амалдар, `JSON.stringify` тартиби |

## Ал эмнени кармай албайт

Өтүү Rust жазылган ар бир кейске дал келет дегенди гана билдирет, андан ашык эмес. Кайра жазууларга
зыян келтирген нерсе көбүнчө жазуудан тышкары жатат, ошондуктан чектер кайда экенин билиңиз:

- **Эч ким жазып албаган киргизүүлөр.** Генерацияланган кейстер, тузактар, түп нусканын тесттери
  (`record --from-tests`) жана өзүңүздүн `--inputs` чек болуп саналат. Чыныгы киргизүүлөрдү кошуңуз (production
  үлгүлөрү, ката боюнча отчеттор); prod'ду бузган колдонуучу киргизүүсү генератордун оюна сейрек келет.
- **Алдыга жылган түп нуска.** `record` бирдиктин файлдарынын манжа изин сактайт
  (`recorded-from.json`); кийин түп нуска өзгөргөндө, түп нуска мурун эмне кылганына каршы өтүүнүн ордуна,
  `diff` эскертет жана сиз кайра жазып алмайынча `gate` өтпөйт.
- **Регулярдык туюнтмалар.** `regex` crate'инде lookaround же backreference жок, жана компиляцияланган
  үлгү да ASCII эмес текстте `\w`, `\b`, `\d` жана регистрге көз карандысыз дал келүүнү JS, Python
  же Java'дан башкача иштетиши мүмкүн. `fancy-regex`'ке алмаштыруу же үлгүнү кайра жазуу ар бир
  жазылган кейстен өтүп, бирок түркчө чекитсиз `ı` же zero-width joiner'де айырмаланышы мүмкүн. `record`
  регулярдык туюнтмаларды колдонгон файлдагы ар бир функцияга regex тузактарын кошот (жогоруда айтылгандар, Кельвин белгиси, узун s,
  араб-инди цифралары, сап бөлгүчтөр, акыркы сигма), бирок чыныгы үлгүлөрүңүздү чыныгы текстте fuzz кылыңыз.
- **Иштетүүдөн иштетүүгө өзгөргөн нерселер.** `record` түп нусканы эки жолу иштетип, эмне айырмаланганын иргейт:
  өзгөргөн маанилер (убакыт, id'лер) wildcard'ка айланат; башка тартиптеги ошол эле саптар (hash map'тер,
  параллелдүүлүк) каалаган тартипте салыштырылат, ошондуктан порт дагы эле так ошол саптарды чыгарышы керек;
  саптардын башка саны `...` болуп калат, ал каалаган нерсеге дал келет. `record` ар бир түрүн тизмектейт:
  ар бирин карап чыгыңыз, анткени hash тартибиндеги же параллелдүүлүктөгү айырма портто чындап өзгөрүшү мүмкүн
  болгон нерсенин так өзү.
- **Float'тар.** Санды текстке айландыруу тилдерде ар башка (`1e21`, `-0`, цифралардын саны).
  Тузактарга ошол маанилер кирет жана алар так дал келиши керек; `--float-tolerance` тегеректөөнү гана
  кечирет, форматтоону эч качан кечирбейт.
- **Чыгышта жок нерселер.** Убакыт, эс тутум, жүктөм астындагы параллелдүүлүк жана stdout, stderr, чыгуу
  коддору, жазылган файлдар жана HTTP жооптордон башка кошумча эффекттер (тармак чакыруулары, маалымат базалары,
  сигналдар) салыштырылбайт.
- **Башка платформалар.** Жазуу аны иштеткен машинадагы жүрүм-турумду гана далилдейт. Натыйжалары
  типтердин өлчөмүнө, endianness'ке же компиляторго көз каранды болгон C коду максаттуу платформада башкача иштеши мүмкүн; ошол себептен `analyze`
  жабдык менен иштеген C кодун C'да калтырат.

| 0. Profile | `everything-rust profile <repo> -- node bench.mjs` | Чыныгы жүктөмдү тилдин профилдөөчүсү астында иштетет (node, cProfile, `go test` pprof, JFR, Ruby tracer): ысык функциялар инклюзивдүү убакыт боюнча, алардын чакыруучулары жана кайсы циклдерди batch кылуу керек; Rust аз пайда берген, буга чейин компиляцияланган кодду (numba, Cython, JAX) белгилейт |
| 1. Plan | `everything-rust analyze <repo>` | Бирдиктер, порттоо тартиби, `file:line` менен тобокелдиктер, ар бир бирдиктин bridge'и, көз карандылыктын crate'ке шайкештиги, биринчи порттоо үчүн эң жакшылары; `--whole-app` кирүү чекиттерин жана форманы, ар бир көз карандылыкты (импорттолгон же жарыяланган) анын crate'и менен, бөлүктөрдү (бири-бирин импорттогон бирдиктер чогуу көчөт) жана сунушталган жооп менен номерленген чечимдерди кошот |
| 2. Bridge | `everything-rust bridge <repo> <unit>` | Байланыштары (`lib.rs`, плюс баштапкы тил жүктөгөн wrapper) жана порттоо үчүн stub'тары (`port.rs`) бар crate; `--batch fn:param` көптөгөн `param` маанилерин Rust ичинде сактаган класс кошот; `--as-json T` колдонмо маалымат менен гана толтурган тип параметрин JSON маанилери катары өткөрөт |
| 3. Record | `everything-rust record <crate>` | Түп нусканы генерацияланган чектик кейстерде (ASCII эмес текст, эмодзи, `-0`, `NaN`, float күтүлгөн жерде int'тер, ...) жана ар бир параметрдеги ар бир семантикалык тузакта (саптын узундугу жана регистри, белгилүү бөлүү, толуп кетүү чектери, float'тарды басып чыгаруу, map жана сорттоо тартиби) иштетип, `cases.jsonl` сактайт; `--from-tests -- npx jest` (же `-- pytest`) түп нусканын өзүнүн тесттери жасаган ар бир чакырууну да жазып алат; `--float-tolerance 1e-9` сандык код үчүн float'тарга ошол үлүштүн чегинде дал келүүгө уруксат берет |
| 3. Build | `everything-rust build <crate>` | Rust тарабын курат: `.node`, wasm пакети, Python кеңейтүүсү же shared library |
| 3. Diff | `everything-rust diff <crate>` | Жазылган кейстерди Rust'ка каршы, түп нусканын чакыруучулары кантип чакырса ошондой чакырып, кайра ойнотот; дал келбестиктерди тизмектейт |
| 3. Bench | `everything-rust bench <crate>` | Жазылган кейстерди түп нускада жана Rust'та, bridge'ди кошо, убакытка өлчөйт |
| 4. Shadow | `everything-rust shadow <crate>` | Экөөн тең иштеткен, түп нусканын натыйжасын кайтарган жана дал келбестиктер жөнүндө кабарлаган drop-in алмаштыргыч; `EVERYTHING_RUST_MODE=old\|shadow\|new` |
| 5. Gate | `everything-rust gate <crate>` | fmt, clippy `-D warnings`, тесттер, `unsafe` аудити, портталбаган эч нерсе калбашы, түп нусканын ар бир ката жолу үчүн жазылган ийгиликсиз кейс, түп нуска ката кайтарган жерде `unwrap`/`expect`/`panic!` болбошу (`// INFALLIBLE: <why>` деп белгиленбесе), build, API, жүрүм-турум |
| Агенттер | `everything-rust setup` | MCP серверди (`everything-rust mcp`, ар бир кадам курал катары) жана workflow skill'ин ([`skills/everything-rust/SKILL.md`](https://github.com/marprojector/everything-rust/blob/main/skills/everything-rust/SKILL.md)) коддоо агенттериңиз менен каттайт |
