# Жазып алуу

```sh
everything-rust record <crate>
everything-rust record <crate> --from-tests -- npx jest      # or: -- pytest
everything-rust record <crate> --inputs extra.jsonl
```

`record` түп нуска функцияларды иштетет жана ар бири эмне кайтарарын же кандай ката ыргытарын crate'тин жанындагы `cases.jsonl` ичине сактайт: порт дал келиши керек болгон жүрүм-турум. Кийин чыккан дал келбестик жүрүм-турумдагы айырма: портту оңдоңуз, жазууну эч качан оңдобоңуз.

## Кейстер кайдан келет

- **Генерацияланган чектик кейстер**: ASCII эмес текст, эмодзи, `-0`, `NaN`, float күтүлгөн жерде int'тер жана башкалар (`--count` ар бир функцияга канчадан экенин коёт).
- Ар бир параметрдеги **семантикалык тузактар**: саптын узундугу жана регистри, белгилүү бөлүү, толуп кетүү чектери, float'тарды басып чыгаруу, map жана сорттоо тартиби.
- Регулярдык туюнтмаларды колдонгон файлдагы ар бир функция үчүн **regex тузактары**: түркчө чекитсиз `ı`, Кельвин белгиси, узун s, араб-инди цифралары, сап бөлгүчтөр, акыркы сигма, zero-width joiner'лер.
- **Түп нусканын өзүнүн тесттери**: `--from-tests -- <test command>` тесттер бирдиктин экспорттолгон функцияларына жасаган ар бир чакырууну жазып алат (TS/JS каалаган runner менен, Python pytest же unittest менен). Андан кийин баштапкы код калыбына келтирилет. vercel/ms'те ал 167 Jest тестинен 340 чакырууну кармады.
- **Сиздин киргизүүлөрүңүз**: ар бир сапта бир `{"fn": name, "args": [...]}` бар `--inputs cases.jsonl`. Чыныгы киргизүүлөрдү кошуңуз (production үлгүлөрү, ката боюнча отчеттор); prod'ду бузган колдонуучу киргизүүсү генератордун оюна сейрек келет.

Python чакыруучулары `1`'ди `1.0` сыяктуу эле көп беришет, ошондуктан жазуу Python кейстеринин ар бир төртүнчүсүндө бүтүн сандарды int катары берет.

## cases.jsonl ичиндеги белгилер

JSON `undefined`, NaN, Infinity, -0 же жалгыз surrogate'терди туюндура албайт. Структуралык маанилер генерацияланган `index.cjs` которгон белгилерди алып жүрөт, жардамчылары crate'тин `js.rs` файлында:

| Белги | Мааниси |
| --- | --- |
| `{"$undefined": true}` | JavaScript `undefined` |
| `{"$num": "NaN"}` | JSON сактай албаган сан (`NaN`, `Infinity`, `-0`) |
| `{"$utf16": [...]}` | жалгыз surrogate'тер үчүн UTF-16 код бирдиктери катары берилген сап |

Функциянын келишиминен тышкары C киргизүүлөрү түп нусканы кулатышы мүмкүн. C драйвери ар бир кейсти fork кылынган бала процессте иштетет жана `crash: SIGSEGV` деп жазат; `diff` ал жерде порттун каалаган жүрүм-турумун кабыл алат, анткени C'нын жүрүм-туруму аныкталбаган.

## Эки иштетүү жана эмне айырмаланат

`record` түп нусканы эки жолу иштетип, иштетүүлөрдүн ортосунда эмне айырмаланганын иргейт: өзгөргөн маанилер (убакыт, id'лер) wildcard'ка айланат; башка тартиптеги ошол эле саптар (hash map'тер, параллелдүүлүк) каалаган тартипте салыштырылат; саптардын башка саны `...` болуп калат, ал каалаган нерсеге дал келет. `record` ар бир түрүн тизмектейт. Ар бирин карап чыгыңыз, анткени hash тартибиндеги же параллелдүүлүктөгү айырма портто чындап өзгөрүшү мүмкүн болгон нерсенин так өзү.

## Жазуу өзүнүн түп нускасын эстейт

`record` бирдиктин файлдарынын манжа изин сактайт (`recorded-from.json`). Кийин түп нуска өзгөргөндө, түп нуска мурун эмне кылганына каршы өтүүнүн ордуна, `diff` эскертет жана сиз кайра жазып алмайынча `gate` өтпөйт. [Diff](/docs/concepts/diff#stale-recordings) барагын караңыз.

## TypeScript өзгөчөлүктөрү

`record` TS баштапкы файлдарын болгондой иштетет: Node resolve hook bundler стилиндеги импорттор боюнча жүрөт (`./errors` → `./errors.ts`), репозиторийде npm пакеттери орнотулбаса `--resolve-from` аларды берет, ал эми трансформацияны талап кылган TS (enum'дар, parameter properties) `--experimental-transform-types` менен кайра аракет кылынат. Node'до түз иштей албаган TS'ти build чыгышынан `--module dist/x.mjs` менен же `--node-arg=--import=tsx` менен жазып алууга болот.

## Сандык код

Float'тар бит-битине сейрек дал келген код үчүн `--float-tolerance` менен жазып алыңыз. [Float тактыгы](/docs/concepts/float-tolerance) барагын караңыз.
