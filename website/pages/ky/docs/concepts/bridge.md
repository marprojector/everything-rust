# Bridge

```sh
everything-rust bridge <repo> <unit-id>          # crate in <repo>/rust/<name>; never overwrites
everything-rust refresh <crate>                  # after changing a signature in port.rs
```

`bridge` байланыштары (`lib.rs`, плюс баштапкы тил жүктөгөн wrapper) жана порттоо үчүн stub'тары (`port.rs`) бар crate түзөт. Портту `src/port.rs` ичинде гана жазасыз; `src/lib.rs` жана wrapper'лер генерацияланат, ал эми `refresh` аларды `port.rs`'теги сигнатуралардан кайра генерациялайт жана жаңы batch класстарын кошот. Ал `port.rs`'ке эч качан тийбейт.

Параметрлер:

- `--batch fn:param` көптөгөн `param` маанилерин Rust ичинде сактаган класс кошот. [Batch'тар](/docs/concepts/batches) барагын караңыз.
- `--as-json T` колдонмо маалымат менен гана толтурган тип параметрин (`paginate<T>(items: T[])` ичиндеги `T`) JSON маанилери катары bridge аркылуу өткөрөт.
- `--keep "name: reason"` көбүрөөк экспортту баштапкы тилде калтырат, мисалы `Intl` маалыматына көз каранды кодду.
- `--kind` план тандаган bridge'ди алмаштырат (TypeScript үчүн napi-rs же wasm).

## Ар бир тилдин bridge'и

| Тил | Bridge |
| --- | --- |
| TypeScript/JavaScript | генерацияланган бинардык wire менен napi-rs же wasm-bindgen; класстар жана async да бар |
| Python | PyO3 (abi3), түз айландыруу, типтелген exception'дор |
| C | түп нуска аталыштары жана header менен `extern "C"` функциялары |
| Go | типтелген cgo чакыруулары жана генерацияланган бинардык wire, түп нуска API'си бар пакетте |
| Ruby | түп нуска модулдардын астындагы magnus кеңейтүүсү |
| Java | типтелген JNI жана генерацияланган бинардык wire, түп нуска методдору бар wrapper класстарында |

PHP жана C# бирдиктерин азырынча bridge аркылуу өткөрүүгө болбойт; [PHP](/docs/languages/php) жана [C#](/docs/languages/csharp) барактарын караңыз.

## Bridge эмнени чечет

- Bridge аркылуу өтө албаган экспорттор себеби көрсөтүлүп, баштапкы тилде калат, ал эми shadow
  модуль түп нусканы кайра экспорттойт. TS үчүн:
  функцияларды кабыл алган же кайтарган функциялар, генераторлор жана итераторлор, RegExp, `instanceof` текшерүүлөрү,
  generic'тер (`--as-json T` колдонмо маалымат менен гана толтурганын өткөрөт) жана типтеринде (импорттор, кайра экспорттор жана `extends` аркылуу аныкталган)
  функциялар бар маанилер. `--keep "name: reason"` көбүрөөгүн калтырат, мисалы `Intl` маалыматына көз каранды кодду.
- TS типтери Rust типтерине шайкештелет, тип alias'тары импорттор аркылуу чечилет, ал эми параметр типтери
  демейки маанилерден аныкталат; структуралык маанилер генерацияланган бинардык wire катары өтөт (JSON wire
  моделдебеген формалар үчүн гана fallback катары).
- JSON `undefined`, NaN, Infinity, -0 же жалгыз surrogate'терди туюндура албайт: структуралык маанилер
  генерацияланган `index.cjs` которгон белгилерди (`{"$undefined": true}`, `{"$num": "NaN"}`, `{"$utf16": [...]}`) алып жүрөт,
  жардамчылары crate'тин `js.rs` файлында.

`record` TS баштапкы файлдарын болгондой иштетет: Node resolve hook bundler стилиндеги импорттор боюнча жүрөт
(`./errors` → `./errors.ts`), репозиторийде npm пакеттери орнотулбаса `--resolve-from` аларды берет, ал эми
трансформацияны талап кылган TS (enum'дар, parameter properties) `--experimental-transform-types` менен кайра аракет кылынат.
