# Профилдөө жана анализ

## Profile: көчүрүүгө арзыган нерсени табуу

Максат ылдамдык болсо, бир нерсени тандоодон мурун өлчөңүз:

```sh
everything-rust profile <repo> -- node bench.mjs      # or: python3 bench.py, ruby bench.rb,
                                                    #     java -cp out Main, go test -run X -bench . ./pkg
```

`profile` чыныгы жүктөмдү тилдин профилдөөчүсү астында иштетет (node, cProfile, `go test` pprof, JFR, Ruby tracer) жана ысык функцияларды инклюзивдүү убакыт боюнча, алардын чакыруучуларын жана кайсы циклдерди batch кылуу керектигин тизмектейт. Go `go test` аркылуу гана профилденет; C колдоого алынбайт.

- Ар бир элемент үчүн бир жолу чакырылган кичинекей функцияны өзүнчө порттоо **арзыбайт**: Rust'ка бир чакыруу анын ишинен кымбатыраак, ал эми JIT'тер (V8, JVM, Go) аны наносекунддарда иштетет. Аны чакыруучулары менен бирге порттоңуз же [batch кылыңыз](/docs/concepts/batches). Кеңеш сабы кайсынысы экенин так буйругу менен айтат.
- Буга чейин компиляцияланган код (numba `@njit`, Cython, `@jax.jit`) машиналык код катары иштейт: Rust порту ылдамдыкты аз гана кошот. `profile` аны "Already compiled" астында тизмектейт.

## Analyze: портту пландоо

```sh
everything-rust analyze <repo> -o plan.md        # for people
everything-rust analyze <repo> --json            # for agents: schema everything-rust/analyze@1
everything-rust analyze <repo> --whole-app       # plus entry points, shape, dependencies, decisions
```

`analyze` бирдиктерди, порттоо тартибин, `file:line` менен тобокелдиктерди, ар бир бирдиктин bridge'ин, ар бир көз карандылык crate'ке канчалык жакшы шайкештелерин жана `start_here` маанисин тизмектейт: биринчи порттоо үчүн эң жакшылары. `--whole-app` колдонмонун формасын (CLI, сервер же китепкана) жана кирүү чекиттерин, ар бир көз карандылыкты (импорттолгон же жарыяланган) анын crate'и менен, бөлүктөрдү (бири-бирин импорттогон бирдиктер чогуу көчөт) жана сунушталган жооп менен номерленген чечимдерди кошот. [Бүт колдонмону порттоо](/docs/whole-apps/overview) барагын караңыз.

- Пакеттер (`package.json`) жана баштапкы файлдар; `node_modules`, build чыгышы, fixture'лер,
  playground'дор, курал конфигурациялары өткөрүлүп жиберилет. Vue/Svelte/Astro `<script>` блоктору импорттор үчүн талданат.
- **Бирдиктер**: баштапкы файлдардан турган папка же пакеттин баштапкы тамырындагы файл.
- **Толкундар**: бирдиктин импорттору мурунку толкундарда келет; импорт циклдери чогуу порттолот.
- **Bridge**: бирдикке же ал импорттогон бир нерсеге Node керек болсо napi-rs; көчүрүлмө код үчүн
  wasm-bindgen; UI жана редактор коду үчүн JS'те калтыруу.
- **Даярдык** (канчалык коопсуз) жана **приоритет** (коопсуз жана арзыйт: циклдер жана сап менен иштөө, тесттер, өлчөм).

| Тобокелдик | Олуттуулук | Мисал |
| --- | --- | --- |
| Саптагы позициялар | жогору | `slice`, `indexOf`, `matchAll`, `d` желеги: UTF-16 жана UTF-8 |
| Regex синтаксиси | жогору | lookaround, backreference, `y`: `regex` crate'инде жок |
| Динамикалык regex | жогору | `new RegExp(userPattern)`: иштөө убагындагы JS синтаксиси |
| Динамикалык код | жогору | `eval`, `new Function`, эсептелген `import()` |
| Динамикалык типтөө | орто | `any`, `'key' in value` |
| Тартиптелген коллекциялар | орто | `Map`, `Set`, `Object.keys`: кошулуу тартиби |
| Async, генераторлор | орто | promise жана генератор чектери |
| Класстардын мурасы, reflection | орто | `extends`, `Proxy`, `Reflect`, `Symbol` |
| Callback формасындагы API'лер | орто | функция типтеги параметрлер жана методдор: көп сүйлөгөн bridge'дер |
| Exception'дор, сандар, JSON | төмөн | `throw`, биттик амалдар, `JSON.stringify` тартиби |
## Көз карандылыктар үчүн crate'тер

`analyze` код импорттогон ар бир китепкана үчүн Rust crate'ин `good`, `partial` же `none` шайкештиги менен атайт. Таблицасында жок китепкана `unknown` деп көрсөтүлөт; таблица crate'ти эч качан божомолдобойт. Жаңысын кошуу үчүн [Салым кошуу](/docs/project/contributing#add-a-crate-mapping) барагын караңыз.
