# 常見問題

大家常問的 everything-rust 相關問題。回到 [README](/)。

## 常見問題

**它會自動重寫我的程式碼嗎？** 不會。它會找出該搬移的部分、產生橋接、
錄製原始版本的行為，並拿它來檢查 Rust。Rust 程式碼由你或你的 AI 代理
在 `port.rs` 中撰寫；`diff` 與 `gate` 決定它何時正確。

**我的應用程式的 API 會改變嗎？** 不會。呼叫端匯入相同的函式（或影子模組，它會
同時執行兩者，並在你建立信心的期間回傳原始版本的結果）。

**Rust 一定比較快嗎？** 不一定，而 everything-rust 會老實告訴你。每個項目呼叫一次的小函式
在 Rust 中往往比較慢，因為每次呼叫都要跨越橋接；V8、JVM 與 Go 執行這類函式
只需要幾奈秒。`profile` 會找出包住它的迴圈，`--batch` 會把整個迴圈搬過去，而 `bench`
會在你出貨前給出結論。已由 numba、Cython 或 JAX 編譯的程式碼同樣是以機器
碼執行：`profile` 與 `analyze` 會標出它，因為移植它幾乎不會提升速度。

**我的程式碼是數值運算；浮點數會完全一致嗎？** 通常不會：運算順序、融合
乘加與數學函式庫在不同編譯器之間都有差異。請以 `--float-tolerance 1e-9` 錄製
（`record` 或 `app record`），之後浮點數只要在較大值的該比例內即視為一致（小於
1 時為絕對值）。整數、文字與結構仍然必須完全一致。

**它能移植我手上只有 APK、JAR 或 .exe 的應用程式嗎？** 不能。它移植的是原始碼：它會
解析函式、錄製每個函式的行為，並拿執行中的原始版本來檢查 Rust。
編譯後的應用程式沒有這些可用的東西，而 `analyze` 也會這麼告訴你。根據執行檔的外在行為撰寫一個新的 Rust
應用程式，是另一個專案。

**我應該移植久經考驗的 C 嗎？** 通常不該，而 `analyze` 會告訴你哪些地方不該。會存取
硬體暫存器、依賴編譯器的型別大小或記憶體配置，或使用行內組譯
（`volatile`、位元欄位、packed struct、`__asm__`、整數轉型為位址）的 C 程式碼，會被標記為「留在
C」：在你的機器上錄製的內容無法證明目標平台上的任何事，而穩定的驅動程式或韌體
程式碼也很少能從重寫中獲益。真正適合搬移的，是圍繞它們的可攜式邏輯（解析、通訊協定、資料處理）。

**它能移植我的 Electron 應用程式嗎？** 邏輯可以；視窗仍然是網頁。`analyze
--whole-app` 會辨識出 Electron，並逐步規劃主行程的移植，而渲染行程則維持
原樣。將 UI 移到 Tauri（同樣的網頁 UI 搭配 Rust 後端）是邏輯成為
Rust 之後的另一個步驟。

**那 C#、Kotlin 或 Swift 呢？** C# 目前為預覽（請參閱[語言](/docs/languages/overview)）；Kotlin 與
Swift 目前還不支援。每種語言都需要解析器、錄製器、橋接與重播
驅動程式，而且全部都要經過端對端測試。請為你需要的語言開一個 issue（或為現有的 issue 按讚）。

**Rust 版本不會比原始版本大很多嗎？** 不應該。`gate` 會比較移植版本與原始版本的
行數，超過 3 倍（另加 50 行給匯入與簽章）就會失敗：這通常代表你手寫了某個 crate 已經
做好的事，或是逐一處理個別案例。`analyze` 會列出應該使用的 crate。

**逐步移植不會把 Rust 綁死在舊應用程式的設計上嗎？** 只有在兩者並行執行
的期間會。錄製內容檢查的是應用程式邊緣的行為（CLI 的輸出、伺服器的
回應、模組匯出的函式），而不是它的內部。在單元仍然跨越橋接的期間，
請沿用舊的結構；一旦 `app lift` 移除了原始版本，就可以自由地重構 Rust，
而 `app replay` 仍然會證明行為正確。也沒有任何東西會回頭呼叫原始版本：
入口會以獨立行程執行它（或將 HTTP 轉發給它），已橋接的單元由原始版本
呼叫，絕不反過來，而回呼則留在來源語言中。

**我的程式碼會離開我的機器嗎？** 不會：everything-rust 在本機執行，不會把你的任何程式碼
傳送到任何地方。Cargo 會照常下載 crate，而你的 AI 代理的模型供應商會看到你的 AI 代理
傳送給它的內容，並依其自身的政策處理。

**需要安裝什麼？** Rust，以及你要移植的語言的執行環境（請參閱
[安裝](/docs/introduction/install)）。

**有東西壞掉了。** 開一個 issue，附上指令、它的輸出以及你的平台。
