# Fuse.js

[Fuse.js](https://github.com/krisk/Fuse) (20k звёзд, около 20 миллионов загрузок из npm в неделю,
коммит `edf2fb6`) это библиотека нечёткого поиска, на которой работают бесчисленные поля поиска. Портирована с помощью
everything-rust 1.6 (не выпущен); крейт лежит в [`demo/real-world/fuse-rs`](https://github.com/marprojector/everything-rust/tree/main/demo/real-world/fuse-rs).

`analyze` поместил все каталоги `src/` в один цикл импортов, поэтому Fuse нельзя портировать файл за файлом.
Вместо этого порт берёт путь, на который поиск тратит своё время: адаптер из 54 строк
(`adapter/relevance.ts`) экспортирует собственную оценку Fuse для одной строки из списка строк, собранную из
`BitapSearch`, нормы поля и `computeScoreSingle` Fuse. Именно эту функцию поиск по
50,000 строк выполняет 50,000 раз. `bridge --batch relevance:text` хранит строки в Rust и
выполняет поиск по всем ним, на всех ядрах.

| Шаг | Результат |
| --- | --- |
| адаптер | ранжирование адаптера совпадает с `new Fuse(list).search(q)` на 81 запросе и наборе опций ещё до всякого Rust |
| `record --inputs` | 3,414 кейсов: заголовки из собственных фикстур Fuse, не-ASCII, эмодзи, шаблоны длиннее 32 единиц, все поддерживаемые опции и опции неверного типа (отклонены, 149 кейсов) |
| порт | 673 строки на Rust вместо 839 строк Fuse, которые он заменяет |
| `diff` | 3,414/3,414 совпадают на первой сборке |
| `gate` | проходит |
| замена | `withRust(Fuse)` отвечает на поиски по списку строк на Rust и передаёт всё остальное в Fuse; на 360 поисках (12 наборов опций, 15 запросов, с `limit` и без) возвращает результаты, побайтово идентичные Fuse |

Время поиска на запрос, Apple M4 (10 ядер), Node 24, результаты проверены на идентичность перед замером:

| Список | Fuse.js | Rust | Ускорение |
| ---: | ---: | ---: | ---: |
| 1,000 строк | 1.9 ms | 0.1 ms | 18x |
| 10,000 строк | 19.1 ms | 0.7 ms | 27 to 30x |
| 50,000 строк | 91.2 ms | 2.8 ms | **32x** |
| 50,000 строк, одно ядро | 92.0 ms | 17.5 ms | 5.3x |

Что порт должен был сделать правильно:

- Bitap работает на 32-битных целых JS: `1 << 31` отрицательно, а `(1 << 31) - 1` это double, который
  становится `2147483647` при следующем сдвиге. Порт хранит эти значения такими, какие они в JS.
- Текст индексируется в кодовых единицах UTF-16, поэтому эмодзи занимает две позиции, как и в Fuse.
- `ignoreDiacritics` это NFD плюс список диапазонов комбинируемых знаков и несколько явно перечисленных букв
  (`ł`, `ß`, `ı`); порт использует тот же список.
- `String.prototype.trim` решает, какие строки Fuse пропускает: пробельные символы JS, а не
  `char::is_whitespace` из Rust (который включает U+0085 и не включает U+FEFF).

Найдено в инструменте и исправлено: пакетные крейты, у которых элементы были строками, а результаты нет,
получали неиспользуемый хелпер и падали на `clippy -D warnings`; а проверка размера в `gate` считала только
адаптер (54 строки, то есть в 12.5x «слишком большой») вместо импортируемых им файлов Fuse.

Что не покрыто: списки объектов с `keys`, расширенный поиск и поиск по токенам, логические запросы,
`includeMatches`, собственные `sortFn` или `getFn`. Замена передаёт их в Fuse без изменений.
Ускорению нужно, чтобы список оставался в Rust между поисками; его построение стоит примерно столько же, сколько
собственный индекс Fuse (3.4 ms против 2.8 ms для 50,000 строк).
