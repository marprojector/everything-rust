# Портирование целого приложения

Цель: приложение на чистом Rust, которое ведёт себя как оригинал, а оригинал сохраняется как эталон. Rust пишет ваш агент; everything-rust упорядочивает работу, создаёт заготовки и доказывает каждый шаг. CLI, HTTP-серверы и библиотеки.

```
analyze --whole-app ──> app record ──> app front-door ──> per unit: the loop, then app wire ──> app lift

 dependency, the        does from the   entry point; the     Rust: replay 100%, fallback rate down proved by
```

## 1. План

```sh
everything-rust analyze . --whole-app
```

`--whole-app` добавляет форму приложения (CLI, сервер или библиотека) и точки входа, каждую внешнюю зависимость (импортированную или объявленную) с её Rust-крейтом и степенью соответствия, порядок портирования в виде частей (модули, импортирующие друг друга, переносятся вместе) и пронумерованные решения с рекомендуемым ответом: оставляемые модули, заблокированные модули, зависимости без крейта или с частичным.

## 2. Запишите всё приложение, затем перенесите точку входа

1. [`app record` и `app replay`](/docs/whole-apps/record-replay) доказывают поведение программы снаружи, как чёрного ящика.
2. [`app front-door`](/docs/whole-apps/front-door) ставит Rust-бинарник перед оригиналом; каждая команда по-прежнему запускает оригинал.
3. Каждый модуль проходит [цикл работы](/docs/concepts/the-loop), затем `app wire` передаёт его команды в Rust.
4. [`app lift`](/docs/whole-apps/lift) удаляет оригинал, как только воспроизведение проходит с нулевой долей фолбэка и каждый модуль проходит gate.

[Серверы](/docs/whole-apps/servers) и [библиотеки](/docs/whole-apps/libraries) используют те же команды.

## Как агент проходит этот путь

[Навык для целого приложения](https://github.com/marprojector/everything-rust/blob/main/skills/everything-rust/whole-app.md) ведёт агента по этому пути, начиная с решений, которые можете принять только вы:

- **Допрос (grilling)**: агент задаёт вопросы раундами, каждый с рекомендуемым ответом, пока не будет закрыто каждое решение, от которого зависит порт, и записывает каждое из них как ADR в `rust/DECISIONS.md`, а `rust/GLOSSARY.md` сопоставляет термины оригинала с именами в Rust.
- **Исследование**: фоновые агенты читают первоисточники по каждой зависимости и пишут `rust/research/<topic>.md` со всеми найденными семантическими ловушками.
- **Между сессиями**: `rust/MAP.md` перечисляет все модули с их состоянием; сессия закрепляет за собой один модуль перед началом работы, а каждая контрольная точка оставляет `rust/HANDOFF.md` для следующей сессии. Модули одной волны могут портироваться параллельно субагентами.
- **Переключение**: агент делает всё, что может, и пишет `rust/cutover.sh`, интерактивный скрипт для шагов, которые можете выполнить только вы (деплои, DNS, секреты), с возможностью отката на каждом шаге.

Допрос, исследование и эти практики адаптированы из [навыков Matt Pocock](https://github.com/mattpocock/skills).

## Не привяжет ли это Rust к старой архитектуре?

Только пока обе версии работают бок о бок. Записи проверяют поведение на границах приложения (вывод CLI, ответы сервера, экспортируемые функции модуля), а не его внутренности. Повторяйте старую структуру, пока модули ещё пересекают мост; как только `app lift` удалил оригинал, свободно меняйте структуру кода на Rust, а `app replay` по-прежнему доказывает поведение.

## Реальный пример

[json-server](/docs/real-world/json-server) прошёл все шаги: 514 записанных HTTP-кейсов, входная точка при 99.8% фолбэка, сначала подключены чтения (22.6% фолбэка), затем все маршруты (0%), и подъём до бинарника на чистом Rust, который проходит 514/514.
