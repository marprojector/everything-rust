# Серверы

Те же команды доказывают корректность HTTP-серверов. `--http` означает, что команда запускает сервер; он берёт
порт из `PORT` или `{port}` в команде (`--port` для сервера, который всегда слушает один и тот же
порт):

```sh
everything-rust app record . --http -- node server.js
everything-rust app replay .
everything-rust app front-door .                                    # axum: every route proxied
everything-rust app wire . api --route 'GET /users/{id}' --route '*'
everything-rust app lift .
```

- Запросы берутся из строк `curl` в документации приложения (`curl -X POST -d ... http://localhost:8080/x`),
  из `--inputs` (`{"name", "method", "path", "headers", "body"}`) и из ловушек: сегменты пути и значения
  query заменяются теми же ловушками, что и аргументы CLI, тела запросов заменяются текстовыми и JSON-ловушками, плюс
  неизвестный маршрут. Каждый прогон запускает сервер заново и отправляет запросы в порядке имён, так что состояние
  между запросами сохраняется.
- Сервер, который хранит состояние в файлах, получает свежую копию при каждом запуске: `--fresh db.json` (файл
  или каталог, можно указать несколько раз) сохраняется как снимок в `http/files/` и копируется в новый рабочий
  каталог при каждом запуске оригинала, входной точки или сборки; `--arg db.json` задаёт
  аргумент, который каждый запуск получает после своей команды, так что Rust-бинарник запускается так же, как оригинал.
  `--pace 50` ждёт 50 ms после каждого ответа, для работы, которую сервер делает после ответа (наблюдатель
  за файлами, перезагружающий то, что сервер только что записал).
- Кейсы хранятся в `rust/app-cases/http/<case>.toml` (запрос, статус и значимые заголовки)
  и `<case>.body` (тело ответа, с `[..]` там, где два прогона различались). Date, server и
  другие заголовки, уникальные для каждого ответа, не учитываются; удалите любую строку заголовка, которая вам не важна.
- Входная точка представляет собой сервер на axum, который запускает оригинал на собственном порту и проксирует
  каждый маршрут, на который не отвечает ни один модуль. `wire --route` принимает маршруты axum: `METHOD /path/{param}`, `/path`
  для любого метода, `*` для всего остального; связующий код получает маршрут, его параметры и
  запрос. `lift` удаляет прокси; после этого HTTP-кейсы запускаются в CI через `app replay`.
## Реальный пример

[json-server](/docs/real-world/json-server) понадобились `--fresh`, `--arg` и `--pace`: он переписывает свою базу данных при каждой записи, а его наблюдатель за файлами может отменить запись, которая быстро следует за предыдущей.
