# Запись и воспроизведение

`record` и `diff` доказывают корректность одного модуля; `app record` и `app replay` доказывают корректность приложения, для CLI и серверов на любом из шести языков. Приложение рассматривается как чёрный ящик.

```sh
everything-rust app record . -- python3 cli.py          # the command that runs the original
everything-rust app replay .                            # the original must pass 100%
everything-rust app replay . --build "target/release/mytool"
```

## Откуда берутся кейсы

`app record` запускает оригинал на:

- собственных документированных примерах приложения: строки `$ mytool ...` в его Markdown- и shell-файлах, вместе с файлами, которые они упоминают;
- файле `--inputs` в формате JSONL, по одному `{"name", "args", "stdin", "env", "files"}` на строку;
- семантических ловушках, выведенных из этих кейсов: строки не-ASCII и эмодзи, деление и остаток от деления отрицательных чисел, переполнение, очень большие и очень маленькие float, порядок в map, отсутствующие файлы.

Каждый кейс запускается дважды; то, что различается между двумя прогонами, становится шаблоном `[..]`. `--normalize timestamps|uuids|key-order` или `--normalize name=regex` добавляют нормализаторы, которые сохраняются вместе с кейсами. `app record` сообщает, что различалось, по видам: значения (теперь шаблоны), порядок (строки сравниваются в любом порядке) и строки (`...`, совпадающее с чем угодно). Просмотрите каждое.

## Кейсы хранятся в обычных файлах

Кейсы хранятся как файлы [trycmd](https://docs.rs/trycmd) в `rust/app-cases/`:

| Файл | Содержит |
| --- | --- |
| `<case>.toml` | argv, окружение, код возврата |
| `<case>.stdin` | стандартный ввод |
| `<case>.stdout`, `<case>.stderr` | что напечатал оригинал |
| `<case>.in/` | входные файлы |
| `<case>.out/` | записанные файлы |

Читайте и редактируйте их вручную; тест на Rust может запускать их через `trycmd`, как только у порта появится бинарник.

## Воспроизведение

- `app replay` прогоняет любую сборку по кейсам, печатает `passed/total`, пишет `rust/app-cases/replay-report.md` с diff для каждого упавшего кейса и завершается с ненулевым кодом при любом расхождении.
- Для сборки, которая дописывает в файл, указанный в `EVERYTHING_RUST_FALLBACK_LOG` (по одной строке на каждый фолбэк к оригиналу), как это делает [входная точка](/docs/whole-apps/front-door), также сообщается доля фолбэка.
- `app replay --case <name>` перезапускает один кейс по имени, которое ему дал отчёт: быстрый, воспроизводимый цикл для исправления расхождения перед повторным прогоном всего набора.

## Воспроизведение в CI

В отчёте нет замеров времени и временных путей: два воспроизведения одной и той же сборки пишут одинаковый файл. Закоммитьте его, а затем запускайте в CI:

```sh
everything-rust app replay .
git diff --exit-code rust/app-cases/replay-report.md
```

Тогда наполовину портированное приложение роняет CI при любом изменении в том, что проходит, в лучшую или худшую сторону, пока отчёт не обновят вместе с этим изменением.

## Числовой вывод

`app record --float-tolerance 1e-9` позволяет числам совпадать с точностью до этой доли от большего значения. См. [Допуск для float](/docs/concepts/float-tolerance).
