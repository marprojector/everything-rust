# Мост (bridge)

```sh
everything-rust bridge <repo> <unit-id>          # крейт в <repo>/rust/<name>; никогда не перезаписывает
everything-rust refresh <crate>                  # после изменения сигнатуры в port.rs
```

`bridge` создаёт крейт с привязками (`lib.rs` плюс обёртка, которую загружает исходный язык) и заглушками для портирования (`port.rs`). Порт вы пишете только в `src/port.rs`; `src/lib.rs` и обёртки генерируются, а `refresh` перегенерирует их по сигнатурам в `port.rs`, добавляя новые пакетные классы. Он никогда не трогает `port.rs`.

Параметры:

- `--batch fn:param` добавляет класс, который хранит много значений `param` в Rust. См. [Пакеты](/docs/concepts/batches).
- `--as-json T` подключает через мост как JSON-значения параметр типа, который приложение наполняет только данными (`T` в `paginate<T>(items: T[])`).
- `--keep "name: reason"` оставляет на исходном языке дополнительные экспорты, например код, зависящий от данных `Intl`.
- `--kind` переопределяет мост, выбранный планом (napi-rs или wasm для TypeScript).

## Мост для каждого языка

| Язык | Мост |
| --- | --- |
| TypeScript/JavaScript | napi-rs или wasm-bindgen со сгенерированным бинарным протоколом; включая классы и async |
| Python | PyO3 (abi3), прямое преобразование, типизированные исключения |
| C | функции `extern "C"` с исходными именами и заголовочный файл |
| Go | типизированные вызовы cgo и сгенерированный бинарный протокол в пакете с исходным API |
| Ruby | расширение magnus в исходных модулях |
| Java | типизированный JNI и сгенерированный бинарный протокол в классах-обёртках с исходными методами |

Модули PHP и C# пока нельзя подключить через мост; см. [PHP](/docs/languages/php) и [C#](/docs/languages/csharp).

## Что решает bridge

- Экспорты, которые не могут пересечь мост, остаются на исходном языке с указанием причины, а теневой
  модуль реэкспортирует оригинал. Для TS:
  функции, которые принимают или возвращают функции, генераторы и итераторы, RegExp, проверки `instanceof`,
  дженерики (`--as-json T` подключает через мост тот, который приложение наполняет только данными) и значения, типы которых (с учётом импортов, реэкспортов и `extends`) содержат
  функции. `--keep "name: reason"` оставляет больше, например код, зависящий от данных `Intl`.
- Типы TS отображаются в типы Rust, псевдонимы типов разрешаются через импорты, а типы параметров
  выводятся из значений по умолчанию; структурированные значения передаются через сгенерированный бинарный протокол (JSON только
  как запасной вариант для форм, которые протокол не моделирует).
- JSON не может выразить `undefined`, NaN, Infinity, -0 или одиночные суррогаты: структурированные значения несут
  маркеры (`{"$undefined": true}`, `{"$num": "NaN"}`, `{"$utf16": [...]}`), которые транслирует сгенерированный
  `index.cjs`, с хелперами в `js.rs` крейта.

`record` выполняет исходники TS как есть: хук разрешения модулей Node следует импортам в стиле бандлеров
(`./errors` в `./errors.ts`), `--resolve-from` подставляет npm-пакеты, когда в репозитории они не
установлены, а TS, требующий трансформации (enum, parameter properties), запускается повторно с
`--experimental-transform-types`.
