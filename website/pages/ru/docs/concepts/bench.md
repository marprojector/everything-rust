# Бенчмарки (bench)

```sh
everything-rust bench <crate>
```

`bench` замеряет время записанных кейсов на оригинале и на собранном Rust-модуле, включая мост, и возвращает строки результатов и вердикт с советом: выкатывать, оставить более медленные функции на исходном языке или портировать модуль покрупнее. Ускорение ниже 1 означает, что порт медленнее при том способе вызова, каким его вызывает вызывающий код. `--min-ms` задаёт минимальное измеряемое время на функцию и сторону (по умолчанию 200).

Следуйте вердикту. Не выкатывайте порт, который замедляет вызывающий код, не сказав об этом.

## Почему порт может быть медленнее

Порт, вызываемый по разу на каждый элемент, платит за мост за каждый элемент. От чего это зависит:

- **Интерпретируемые оригиналы (Python, Ruby)**: вызов в Rust стоит около 100-300 ns, а код на Rust гораздо быстрее интерпретатора, так что выигрывают даже маленькие функции.
- **Компилируемые оригиналы (Go, Java после JIT)**: исходная листовая функция занимает 4-90 ns; один вызов cgo сам по себе стоит около 80 ns, вызов JNI со строками ещё дороже. Эти языки выигрывают, только когда один вызов делает много работы: портируйте функцию вместе с вызывающим её кодом.
- **C**: пересечения границы нет; код на Rust сравнивается с кодом на C напрямую.

Измерено на вызов на реальном коде ([шесть языков](/docs/real-world/six-languages)):

| Язык | Rust против оригинала (`bench`, среднее геометрическое) | Вердикт |
| --- | --- | --- |
| Ruby | **в 4.4x быстрее** (3.6-7x на функцию) | выкатывать |
| Python | **в 1.35x быстрее** (1.5-1.9x на большинстве вызовов) | выкатывать |
| C | 0.87x: ctype быстрее в 1.1-1.4x, оптимизированные в glibc `strtod`, `strspn`, `strcmp` 0.5-0.7x | оптимизировать или оставить более медленные |
| Java | 0.18x | портировать модули покрупнее |
| Go | 0.04x | портировать модули покрупнее |

Были портированы все 29 функций ядра x18n, которые можно перенести без изменения API: каждый гейт проходит и 7,925 записанных кейсов совпадают точно, а `bench` показал, что порты медленнее TS, если вызывать их из JS, потому что мост стоит дороже самой работы ([отчёт](https://github.com/marprojector/everything-rust/blob/main/demo/x18n-core/README.md)). vercel/ms работал на 0.56x на вызов по своим записанным кейсам ([разбор кейса](/docs/real-world/vercel-ms)).

## Что выигрывает: перенос цикла

`profile` находит цикл вокруг горячей функции, а `--batch` переносит весь цикл в Rust, на все ядра. См. [Пакеты и горячие пути](/docs/concepts/batches).

::: tip Замеряйте на ненагруженной машине
Запускайте `bench` на ненагруженной машине, запускайте дважды и указывайте железо и число ядер рядом с каждым опубликованным числом.
:::
