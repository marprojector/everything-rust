# Порт

Порт пишете вы или ваш агент в `src/port.rs`. Всё остальное в крейте генерируется. После изменения сигнатуры в `port.rs` запустите `everything-rust refresh <crate>`.

## Правила, которые экономят раунд diff

- Прежде чем писать код, прочитайте каждый риск, который план перечисляет для модуля, по его `file:line`.
- **Смещения в строках**: JS и Java индексируют кодовые единицы UTF-16, Rust индексирует байты UTF-8. Используйте сгенерированный `src/utf16.rs`.
- **Ошибки**: возвращайте `Err("TypeName: message")`. В Python, Ruby и Java это становится соответствующим исключением, а в Go текстом `error`. Паника в Rust никогда не совпадает с записанной ошибкой.
- **Числа в Python и Ruby**: целые числа, которые оригинал пропускает как есть, должны возвращаться как целые. В портах для Python используйте `crate::pynum::Num` для «int или float», а не `serde_json::Value`.
- **C**: входные данные, записанные как `crash:`, означают неопределённое поведение; проходит любой результат.
- **Упорядоченные map и ключи объектов**: `indexmap` там, где порядок попадает в вывод.
- **Lookaround или обратные ссылки в регулярных выражениях**: `fancy-regex`, а не `regex`. В любом случае `\w`, `\b`, `\d` и регистронезависимое сопоставление обрабатывают текст не-ASCII иначе, чем движок исходного языка. Задайте `unicode(false)` или явно выпишите ASCII-классы (`[A-Za-z0-9_]`) там, где `\w` оригинала работает только с ASCII (JS без `u`, Java).
- **Никакого `unsafe`.** Если он действительно нужен: минимальный, изолированный, с комментарием `// SAFETY:`.
- **Держите хелперы приватными.** `pub` только у экспортов модуля; хелпер с `pub` становится частью API за мостом.
- Добавляйте юнит-тесты на Rust в `port.rs` для кейсов, над которыми вы размышляете.

Сгенерированный `js.rs` содержит хелперы, воспроизводящие поведение JavaScript там, где Rust отличается, например `js::number_to_string` (JS `String(n)`) и `js::math_round` (`Math.round`).

## Пример: эмодзи, сдвинувший позицию

`packages/core/src/fuzzy.ts` из [x18n](https://github.com/x18n-dev/x18n), портированный обоими способами в
[`demo/`](https://github.com/marprojector/everything-rust/tree/main/demo):

```sh
everything-rust analyze ../x18n                                      # fuzzy.ts: ready, wasm-bindgen (core runs in browsers)
everything-rust bridge ../x18n packages/core/src/fuzzy.ts --out demo/fuzzy-rs
everything-rust record demo/fuzzy-rs --count 2000
# напишите src/port.rs
everything-rust gate demo/fuzzy-rs
```

Первый порт, который индексировал по Rust `char`, прошёл простые тесты, но провалил `diff`:

```
198/200 cases match
- fuzzyScore("b😀", "a😀b😀c"): expected {"ok":1997}, got {"ok":1998}
```

`indexOf` в JS считает кодовые единицы UTF-16, поэтому эмодзи занимает две позиции. Порт в
`demo/*/src/port.rs` использует сгенерированные хелперы `utf16` и проходит 2000/2000 кейсов и гейт,
и как napi-rs (`demo/fuzzy-napi`), и как wasm-bindgen (`demo/fuzzy-rs`).

План, который everything-rust пишет для всего x18n: [`docs/examples/x18n.md`](https://github.com/marprojector/everything-rust/blob/main/docs/examples/x18n.md).
## Каким большим он должен быть?

`gate` сравнивает число строк порта с оригиналом и падает при превышении в 3x (плюс 50 строк на импорты и сигнатуры). Превышение обычно означает, что вы вручную пишете то, что уже делает какой-то крейт, или обрабатываете кейсы по одному. `analyze` перечисляет крейты, которые стоит использовать.
