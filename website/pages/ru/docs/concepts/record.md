# Запись (record)

```sh
everything-rust record <crate>
everything-rust record <crate> --from-tests -- npx jest      # или: -- pytest
everything-rust record <crate> --inputs extra.jsonl
```

`record` запускает исходные функции и сохраняет то, что каждая из них возвращает или выбрасывает, в `cases.jsonl` рядом с крейтом: это поведение, которому должен соответствовать порт. Расхождение в дальнейшем означает различие в поведении: исправляйте порт, а не запись.

## Откуда берутся кейсы

- **Сгенерированные граничные случаи**: не-ASCII, эмодзи, `-0`, `NaN`, целые числа там, где ожидаются float, и многое другое (`--count` задаёт их количество на функцию).
- **Семантические ловушки** в каждом параметре: длина и регистр строк, деление со знаком, границы переполнения, печать float, порядок в map и порядок сортировки.
- **Ловушки для регулярных выражений** для каждой функции в файле, который использует регулярные выражения: турецкая `ı` без точки, знак Кельвина, длинная s, арабско-индийские цифры, разделители строк, конечная сигма, zero-width joiner.
- **Собственные тесты оригинала**: `--from-tests -- <test command>` записывает каждый вызов экспортируемых функций модуля, который делает набор тестов (TS/JS с любым раннером, Python с pytest или unittest). После этого исходники восстанавливаются. На vercel/ms это дало 340 вызовов из 167 тестов Jest.
- **Ваши входные данные**: `--inputs cases.jsonl` с одним `{"fn": name, "args": [...]}` на строку. Добавляйте реальные входные данные (выборки из продакшена, баг-репорты); пользовательский ввод, который ломает прод, редко бывает тем, что придумает генератор.

Вызывающий код на Python передаёт `1` так же часто, как `1.0`, поэтому при записи целочисленные значения передаются как int в каждом четвёртом кейсе Python.

## Маркеры в cases.jsonl

JSON не может выразить `undefined`, NaN, Infinity, -0 или одиночные суррогаты. Структурированные значения несут маркеры, которые транслирует сгенерированный `index.cjs`, с хелперами в `js.rs` крейта:

| Маркер | Означает |
| --- | --- |
| `{"$undefined": true}` | `undefined` из JavaScript |
| `{"$num": "NaN"}` | число, которое JSON не может хранить (`NaN`, `Infinity`, `-0`) |
| `{"$utf16": [...]}` | строка, заданная кодовыми единицами UTF-16, для одиночных суррогатов |

Входные данные C вне контракта функции могут уронить оригинал. Драйвер C запускает каждый кейс в дочернем процессе через fork и записывает `crash: SIGSEGV`; `diff` принимает здесь любое поведение порта, поскольку поведение C не определено.

## Два прогона и то, что различается

`record` запускает оригинал дважды и разбирает, что различалось между прогонами: изменившиеся значения (время, идентификаторы) становятся шаблонами; те же строки в другом порядке (хеш-таблицы, конкурентность) сравниваются в любом порядке; другое количество строк становится `...`, что совпадает с чем угодно. `record` перечисляет каждый вид. Просмотрите каждый, поскольку разница в порядке хеша или в конкурентности именно то, что в порте может измениться по-настоящему.

## Запись помнит свой оригинал

`record` сохраняет отпечаток файлов модуля (`recorded-from.json`). Когда оригинал позже меняется, `diff` предупреждает, а `gate` падает, пока вы не запишете заново, вместо того чтобы проходить против того, что оригинал делал раньше. См. [Diff](/docs/concepts/diff#stale-recordings).

## Особенности TypeScript

`record` выполняет исходники TS как есть: хук разрешения модулей Node следует импортам в стиле бандлеров (`./errors` в `./errors.ts`), `--resolve-from` подставляет npm-пакеты, когда в репозитории они не установлены, а TS, требующий трансформации (enum, parameter properties), запускается повторно с `--experimental-transform-types`. TS, который не может выполняться в Node напрямую, можно записать из результата сборки с `--module dist/x.mjs` или с `--node-arg=--import=tsx`.

## Численный код

Для кода, где float редко совпадают бит в бит, записывайте с `--float-tolerance`. См. [Допуск для float](/docs/concepts/float-tolerance).
