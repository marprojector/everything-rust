# Гейт (gate)

```sh
everything-rust gate <crate>
```

Готово означает, что `gate` проходит. Он проверяет:

- `cargo fmt`, clippy с `-D warnings` и тесты cargo;
- `unsafe` только с комментариями `// SAFETY:` и ничего с `unimplemented!`;
- записанный кейс с ошибкой для каждого места, где оригинал намеренно завершается ошибкой (`throw`, `raise`, результат `error`). Добавьте его через `record --inputs`, когда gate его назовёт;
- отсутствие `unwrap`, `expect` или `panic!` в функции, оригинал которой возвращает ошибку. Возвращайте `Err`; для состояния, которое оригинал тоже считает невозможным, оставьте комментарий `// INFALLIBLE: <why>`;
- порт не больше чем в 3x раза длиннее оригинала по строкам (плюс 50 строк на импорты и сигнатуры);
- модуль собирается, и все экспорты на месте;
- каждый записанный кейс совпадает, включая [известные расхождения](/docs/concepts/diff#known-diffs), и запись не [устарела](/docs/concepts/diff#stale-recordings);
- для TS/JS строка о [покрытии](/docs/concepts/coverage): какую часть оригинала выполнили кейсы.

Каждая упавшая проверка содержит `fix`: сначала выполните его.

## Затем отчёт и ожидание

Когда гейт проходит, навык рабочего процесса поручает агенту сообщить, что изменилось (файлы, функции, мост, пакеты), вывод гейта, счётчики diff и числа бенчмарка, оставшиеся различия в поведении или риски и то, что осталось в плане, и дождаться разрешения, прежде чем браться за следующий модуль.
