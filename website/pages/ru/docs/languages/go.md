# Go

| | |
| --- | --- |
| Модуль | пакет |
| Мост | типизированные вызовы cgo и сгенерированный бинарный протокол в пакете с исходным API |
| Чем записывается и воспроизводится | сгенерированный Go-драйвер, собранный как отдельный модуль |
| Требуется | Go 1.21+ |
| Статус | Проверен на `path` из Go 1.24: 2,642/2,642 (542 из собственных тестовых таблиц Go), gate проходит |

`profile` работает через `go test`: `everything-rust profile <repo> -- go test -run X -bench . ./pkg`. Пакеты создаются как `NewFnBatch(items)`; закрывайте их, когда закончите.

## Что порт должен сделать правильно

- `path.Clean`: `lazybuf` в Go читает байт по индексу записи после того, как тот сдвинулся назад, а не последний сохранённый байт (9 кейсов, из собственной тестовой таблицы Go).
- `strings.ToLower` переводит в нижний регистр каждую руну отдельно: `ΣΊΣΥΦΟΣ` становится `σίσυφοσ`, тогда как `to_lowercase` в Rust применяет правило конечной сигмы. Go также отображает `İ` в `i`, а Rust даёт `i̇`.
- Go режет строки по байтам; разрез посреди руны доходит до JSON как по одному U+FFFD на каждый байт.

## Скорость

Go выполняет листовые функции за несколько наносекунд, а один вызов cgo сам по себе стоит около 80 ns. На `path` `bench` намерил порт на уровне 0.04x на вызов: портируйте более крупные модули. В виде пакета работа уходит в Rust на все ядра: `Slugify` на 50,000 строк занимал в Go 49 ms, а пакет работал **в 4x быстрее** (порт с вызовом на каждый элемент: 0.93x). Пакетные крейты выделяют память через mimalloc: с системным аллокатором пакет для Go был медленнее одного потока.
