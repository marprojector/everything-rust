# Java

| | |
| --- | --- |
| Модуль | пакет методов `public static` |
| Мост | типизированный JNI и сгенерированный бинарный протокол в классах-обёртках с исходными методами |
| Чем записывается и воспроизводится | сгенерированный драйвер на рефлексии |
| Требуется | JDK 17+ (`javac` и `java`) |
| Статус | Проверен на JDK 21 за фасадом: 4,492/4,492 (226 с исключением), gate проходит |

Пакеты создаются как `new FnBatch(items)`; закрывайте их, когда закончите. `profile` использует JFR.

## Что порт должен сделать правильно

- `Integer.parseInt` принимает любую десятичную цифру Unicode (`١٢`, `２`) через `Character.digit`.
- `Double.toString` (JDK 19+) печатает кратчайшую десятичную запись, но не меньше двух цифр: `4.9E-324`, тогда как кратчайшая форма в Rust `5e-324`.
- `\s` распознаёт только ASCII; `split_whitespace` в Rust также разбивает по U+00A0.
- Числа с плавающей точкой должны переживать круговое преобразование: парсер float по умолчанию в `serde_json` не всегда округляет корректно, поэтому everything-rust и каждый генерируемый им крейт используют его фичу `float_roundtrip`.

## Скорость

После JIT листовые функции занимают несколько наносекунд, а вызов JNI со строками стоит больше. На фасаде JDK `bench` намерил порт на уровне 0.18x на вызов: портируйте более крупные модули. В виде пакета на 4 ядрах `slugify` на 50,000 строк (43 ms в Java) работал **в 3x быстрее** (порт с вызовом на каждый элемент: 0.68x).
