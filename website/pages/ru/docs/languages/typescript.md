# TypeScript/JavaScript

| | |
| --- | --- |
| Модуль | каталог или файл |
| Мост | napi-rs или wasm-bindgen со сгенерированным бинарным протоколом; включая классы и async |
| Чем записывается и воспроизводится | Node, напрямую выполняющий исходники `.ts` |
| Требуется | Node 22.6+ (`profile` требует Node 24+) |
| Статус | Проверен |

## Выбор моста

`analyze` выбирает napi-rs, когда модулю или чему-то, что он импортирует, нужен Node, wasm-bindgen для переносимого кода (он работает и в браузерах), а код UI и редактора оставляет на JS. `bridge --kind napi|wasm` переопределяет выбор.

Экспорты, которые не могут пересечь мост, остаются на TS с указанием причины, а теневой модуль реэкспортирует оригинал: функции, которые принимают или возвращают функции, генераторы и итераторы, RegExp, проверки `instanceof`, дженерики (`--as-json T` подключает через мост тот, который приложение наполняет только данными) и значения, типы которых содержат функции. См. [Мост (bridge)](/docs/concepts/bridge).

## Запись TS как есть

`record` выполняет исходники TS напрямую: хук разрешения модулей Node следует импортам в стиле бандлеров, `--resolve-from` подставляет npm-пакеты, когда в репозитории они не установлены, а TS, требующий трансформации (enum, parameter properties), запускается повторно с `--experimental-transform-types`. `record --from-tests -- npx jest` записывает каждый вызов, который делает собственный набор тестов оригинала, с любым раннером. Для TS/JS измеряется покрытие оригинала ([Покрытие](/docs/concepts/coverage)).

## Что порт должен сделать правильно

Найдено записанными кейсами на реальном коде:

- `str.length`, `indexOf` и `slice` считают кодовые единицы UTF-16, поэтому эмодзи занимает две позиции. Используйте сгенерированные хелперы `utf16`.
- `/.../i` без флага `u` сворачивает регистр только ASCII-букв, тогда как `regex` в Rust сворачивает Unicode, поэтому `"1 ſ"` (длинная s) и знак Кельвина распознались бы в vercel/ms как секунды.
- `Math.round` округляет половины вверх (`-2.5` даёт `-2`); `round` в Rust округляет от нуля. В сгенерированном `js.rs` есть `js::math_round`.
- `${n}` печатает `1e+21`, `5e-324` и `0` для `-0`. `js::number_to_string` воспроизводит это.
- `String.prototype.trim` использует пробельные символы JS, а не `char::is_whitespace` из Rust.

## Скорость

При вызове на каждый элемент порт каждый раз платит за мост, а V8 выполняет маленькие функции за наносекунды. vercel/ms работал на 0.56x на вызов по своим записанным кейсам; порты ядра x18n медленнее TS, если вызывать их из JS. В виде пакетов цикл уходит в Rust:

| Нагрузка | Оригинал | С everything-rust |
| --- | ---: | ---: |
| Поиск в боковой панели x18n, 50,000 ключей (Node) | 10 ms на запрос | 0.5 ms: в 20x быстрее |
| Тот же поиск в браузере (wasm, один поток) | 10 ms | 0.95 ms: 11.5x |
| Fuse.js, 50,000 строк | 91.2 ms | 2.8 ms: 32x |
| vercel/ms `parse` x100,000 | 11.8 ms | 0.65 ms: 18x (3.4x с учётом передачи данных) |
| vercel/ms `format` x100,000 | 2.1 ms | 2.5 ms с учётом передачи данных: 0.8x |

Разборы кейсов: [json-server](/docs/real-world/json-server), [Fuse.js](/docs/real-world/fuse-js), [vercel/ms](/docs/real-world/vercel-ms), [x18n](/docs/real-world/x18n).
