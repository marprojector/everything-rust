# Языки

Шесть языков проходят весь цикл: Node.js (TypeScript/JavaScript), Python, C, Go, Ruby и Java. PHP и C# находятся в превью: уже сейчас `analyze` и целые приложения, мосты для модулей на подходе.

| Язык | Модуль | Мост | Чем записывается и воспроизводится |
| --- | --- | --- | --- |
| TypeScript/JavaScript | каталог или файл | napi-rs или wasm-bindgen со сгенерированным бинарным протоколом; включая классы и async | Node, напрямую выполняющий исходники `.ts` |
| Python | пакет или модуль | PyO3 (abi3), прямое преобразование, типизированные исключения | Python, импортирующий оригинал |
| C | файл `.c` | функции `extern "C"` с исходными именами и заголовочный файл | оригинал, скомпилированный в разделяемую библиотеку, вызов через ctypes, отдельный fork на кейс |
| Go | пакет | типизированные вызовы cgo и сгенерированный бинарный протокол в пакете с исходным API | сгенерированный Go-драйвер, собранный как отдельный модуль |
| Ruby | файл или каталог с функциями модуля | расширение magnus в исходных модулях | сгенерированный Ruby-драйвер |
| Java | пакет методов `public static` | типизированный JNI и сгенерированный бинарный протокол в классах-обёртках с исходными методами | сгенерированный драйвер на рефлексии |
| PHP (превью) | каталог функций и методов `public static` | далее: PHP FFI поверх C ABI | целые приложения уже сейчас: `app record`, `app replay` и входная точка, для CLI и серверов (`php -S`) |
| C# (превью) | каталог методов `public static` | далее: P/Invoke поверх C ABI | целые приложения уже сейчас: `app record`, `app replay` и входная точка, для CLI и серверов ASP.NET (`dotnet <app>.dll`) |

Для каждого языка, кроме C, также генерируются пакетные классы (`--batch`): элементы пересекают границу один раз и остаются
в Rust, а каждый вызов обрабатывает их все на всех ядрах.

Язык определяется по репозиторию (`go.mod`, `pom.xml`, `.csproj` или `.sln`,
`pyproject.toml`, `Gemfile`, `composer.json`, `package.json`, иначе по преобладающим исходным файлам);
флаг `--lang` переопределяет автоопределение. Типы берутся из исходного кода: типы TS, аннотации типов Python, сигнатуры C, Go, Java и C#,
теги YARD в Ruby, типы и phpdoc в PHP; нетипизированные параметры, используемые как числа, выводятся
как числовые.

PHP находится в превью: `analyze` планирует PHP-приложение (пакеты Composer и автозагрузка PSR-4, риски
вроде нестрогого сравнения и переполнения целых чисел во float, сопоставление пакетов Composer с крейтами),
а PHP CLI или сервер можно записать, воспроизвести и поставить за входную точку на Rust. Перенос его
модулей в Rust через PHP FFI станет следующим этапом ([issue #2](https://github.com/marprojector/everything-rust/issues/2)).

C# находится в превью аналогичным образом: `analyze` читает проекты `.csproj` и их пакеты NuGet
(сопоставляемые с крейтами), разрешает директивы `using` в каталоги и отмечает, что C# делает иначе
(`decimal`, `dynamic`, отложенные запросы LINQ, `Task`, `lock`, рефлексия). C# CLI или сервер ASP.NET
можно записать, воспроизвести и поставить за входную точку на Rust; перенос модулей через P/Invoke
появится далее.
