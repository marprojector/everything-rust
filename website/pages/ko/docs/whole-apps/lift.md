# 리프트

재생이 폴백 비율 0으로 통과하고 모든 유닛이 게이트를 통과하면 순수 Rust 앱으로 만드세요:

```sh
everything-rust app lift .
```

- `app lift`는 두 조건이 모두 충족될 때까지 거부하며, 무엇이 막고 있는지 알려 줍니다: 아직 폴백하는 케이스, 여전히 스텁인 글루 코드, 게이트에 실패하는 유닛.
- 먼저 복사본에서 폴백 경로와 킬 스위치를 제거하고, 각 유닛 crate를 `rust/app`의 일반 라이브러리로 바꾸며(`cdylib`, 바인딩, 생성된 래퍼 없음), `cargo test` 시 trycmd로 `rust/app-cases`를 실행하는 `rust/app/tests/app_cases.rs`를 추가합니다. 그래서 CI에는 cargo 외에 아무것도 필요하지 않습니다.
- 그다음 리프트 체크리스트를 실행합니다: 모든 유닛과 `rust/app`에 대한 fmt, clippy `-D warnings`, 테스트, `rust/DECISIONS.md`에 적힌 모든 타깃을 설치된 곳에서 빌드 또는 검사, 실행 시점에 읽는 파일과 임베드되지 않은 에셋 폴더 확인, 순수 바이너리에서의 재생. 모두 통과해야만 변경 사항이 다시 기록됩니다. 원본은 전혀 건드리지 않습니다.

## 리프트 이후

유닛에는 더 이상 바인딩이 없습니다. json-server에서는 각 crate의 `tests/recorded.rs`가 기록된 케이스를 포트에서 재생합니다: 3,399개 모두 `cargo test`로 실행되며, HTTP 케이스 514개도 함께 실행됩니다.

원본이 사라지면 Rust 코드를 자유롭게 재구성하세요. `app replay`가 여전히 동작을 증명합니다.

## 그다음 전환

워크플로 스킬은 에이전트가 할 수 있는 일을 하게 하고, 개발자만 할 수 있는 단계(배포, DNS, 시크릿)를 위한 대화형 스크립트 `rust/cutover.sh`를 작성하게 합니다. 각 단계마다 되돌아갈 방법이 있습니다.
