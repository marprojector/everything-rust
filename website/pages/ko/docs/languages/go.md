# Go

| | |
| --- | --- |
| 유닛 | 패키지 |
| 브리지 | 원래 API를 가진 패키지 안의, 타입이 있는 cgo 호출과 생성된 바이너리 와이어 |
| 기록과 재생 담당 | 독립 모듈로 빌드되는, 생성된 Go 드라이버 |
| 필요 조건 | Go 1.21+ |
| 상태 | Go 1.24의 `path`에서 검증: 2,642/2,642 (542개는 Go 자체 테스트 테이블에서), 게이트 통과 |

`profile`은 `go test`를 통해 동작합니다: `everything-rust profile <repo> -- go test -run X -bench . ./pkg`. 배치는 `NewFnBatch(items)`이며, 다 쓰면 닫아야 합니다.

## 포트가 정확히 맞춰야 할 부분

- `path.Clean`: Go의 `lazybuf`는 쓰기 인덱스가 뒤로 이동한 뒤 그 위치의 바이트를 읽으며, 마지막으로 남긴 바이트를 읽지 않습니다(Go 자체 테스트 테이블의 9개 케이스).
- `strings.ToLower`는 각 룬을 개별적으로 소문자로 바꿉니다: `ΣΊΣΥΦΟΣ`는 `σίσυφοσ`가 되지만, Rust의 `to_lowercase`는 어말 시그마 규칙을 적용합니다. Go는 `İ`도 `i`로 바꾸지만 Rust는 `i̇`를 냅니다.
- Go는 문자열을 바이트 단위로 자릅니다. 룬 중간을 자르면 JSON에서 바이트마다 U+FFFD 하나가 됩니다.

## 속도

Go는 리프 함수를 몇 나노초 만에 실행하며, cgo 호출 하나만으로도 약 80 ns가 듭니다. `path`에서 `bench`는 포트를 호출당 0.04x로 측정했습니다. 더 큰 유닛을 포팅하세요. 배치로 하면 작업이 모든 코어에서 Rust로 옮겨집니다: 문자열 50,000개에 대한 `Slugify`는 Go에서 49 ms가 걸렸고, 배치는 **4배 더 빨랐습니다**(호출당 포트: 0.93x). 배치 crate는 mimalloc으로 메모리를 할당합니다. 시스템 할당자를 쓰면 Go 배치가 단일 스레드보다 느렸습니다.
