# Запис і відтворення

`record` і `diff` доводять один модуль; `app record` і `app replay` доводять застосунок, для CLI та серверів будь-якою з шести мов. Застосунок є чорною скринькою.

```sh
everything-rust app record . -- python3 cli.py          # команда, що запускає оригінал
everything-rust app replay .                            # оригінал має пройти 100%
everything-rust app replay . --build "target/release/mytool"
```

## Звідки беруться випадки

`app record` запускає оригінал на:

- власних задокументованих прикладах застосунку: рядках `$ mytool ...` у його файлах Markdown і shell, разом із файлами, які вони називають;
- файлі JSONL з `--inputs`, по одному `{"name", "args", "stdin", "env", "files"}` на рядок;
- семантичних пастках, виведених із цих випадків: рядки з не-ASCII та емодзі, від'ємне ділення і залишок, переповнення, дуже великі й дуже малі float, порядок у мапах, відсутні файли.

Кожен випадок запускається двічі; те, що відрізняється між двома запусками, стає шаблоном `[..]`. `--normalize timestamps|uuids|key-order` або `--normalize name=regex` додає нормалізатори, що зберігаються разом із випадками. `app record` повідомляє, що відрізнялося, за видами: значення (тепер шаблони), порядок (рядки порівнюються в будь-якому порядку) і рядки (`...`, що збігається з будь-чим). Перегляньте кожне.

## Випадки є звичайними файлами

Випадки зберігаються як файли [trycmd](https://docs.rs/trycmd) у `rust/app-cases/`:

| Файл | Містить |
| --- | --- |
| `<case>.toml` | argv, змінні середовища, код виходу |
| `<case>.stdin` | стандартний ввід |
| `<case>.stdout`, `<case>.stderr` | те, що надрукував оригінал |
| `<case>.in/` | вхідні файли |
| `<case>.out/` | записані файли |

Читайте і редагуйте їх вручну; тест на Rust може запускати їх через `trycmd`, щойно в порту з'явиться бінарник.

## Відтворення

- `app replay` проганяє будь-яку збірку на випадках, друкує `passed/total`, пише `rust/app-cases/replay-report.md` з diff для кожного провального випадку і завершується з ненульовим кодом за будь-якої розбіжності.
- Збірка, що дописує у файл, названий у `EVERYTHING_RUST_FALLBACK_LOG` (по рядку на кожен fallback до оригіналу), як це робить [front door](/docs/whole-apps/front-door), також отримує звіт про свою частку fallback.
- `app replay --case <name>` повторно запускає один випадок за іменем, яке дає йому звіт: швидкий, відтворюваний цикл для виправлення розбіжності, перш ніж знову проганяти все.

## Відтворення в CI

Звіт не містить таймінгів чи тимчасових шляхів: два відтворення однієї збірки пишуть однаковий файл. Закомітьте його, потім запускайте в CI:

```sh
everything-rust app replay .
git diff --exit-code rust/app-cases/replay-report.md
```

Тоді наполовину портований застосунок валить CI за будь-якої зміни в тому, що проходить, на краще чи на гірше, доки звіт не оновлять відповідно.

## Числовий вивід

`app record --float-tolerance 1e-9` дозволяє числам збігатися в межах цієї частки від більшого значення. Див. [Допуск для float](/docs/concepts/float-tolerance).
