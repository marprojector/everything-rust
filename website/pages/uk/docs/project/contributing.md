# Як долучитися

Дякуємо за допомогу. Звіти про баги, виправлення, підтримка нових мов і описи реальних портів
вітаються, і вам не треба питати дозволу, перш ніж відкрити pull request з виправленням бага.

## Перш ніж почати

- **Баг:** відкрийте [issue](https://github.com/marprojector/everything-rust/issues/new/choose) з
  командою, яку ви запустили, її виводом, вашою платформою і версією everything-rust
  (`everything-rust --version`). Найбільше допомагає крихітний проєкт для відтворення.
- **Більша зміна** (нова мова, нова команда, зміна того, що таке модуль чи запис):
  спершу відкрийте issue, щоб ми домовилися про форму, перш ніж ви її напишете. Причини минулих
  рішень описано в [DECISIONS.md](https://github.com/marprojector/everything-rust/blob/main/DECISIONS.md).
- **Проблема безпеки:** не відкривайте публічний issue; див. [SECURITY.md](https://github.com/marprojector/everything-rust/blob/main/SECURITY.md).

## Налаштування

Вам потрібен Rust (stable, 1.97 або новіший). Тести також запускають мову, яку обробляє кожна частина, і
пропускають частину, для якої немає середовища виконання, тож встановіть ті, яких торкаєтеся:

| Для | Встановити |
| --- | --- |
| TypeScript/JavaScript | Node 24 (22.6+ працює, крім `profile`) |
| Python | Python 3.9+ |
| C | компілятор C (`cc`) |
| Go | Go 1.22+ |
| Ruby | Ruby 3.x |
| Java | JDK (17+) |
| PHP | PHP 8 |
| C# | .NET SDK |
| wasm-мости | `rustup target add wasm32-unknown-unknown` і відповідний `wasm-bindgen-cli` |

```sh
git clone https://github.com/marprojector/everything-rust
cd everything-rust
git config core.hooksPath .githooks
cargo test
```

`cargo run -- doctor` показує, які з цих середовищ виконання у вас є, їхні версії і команду,
що встановлює або оновлює кожне з них. Щоб відсутнє середовище валило свої тести, а не пропускало
їх (так робить CI), назвіть його в `EVERYTHING_RUST_REQUIRE`, наприклад
`EVERYTHING_RUST_REQUIRE=node,python3,go,ruby,java cargo test`.

Хук запускає `scripts/check-secrets.sh`, який відхиляє ключі, токени і шляхи до особистих домашніх тек
у тому, що ви комітите. CI запускає його на кожному файлі.

## Внесіть зміну

- **Кожне виправлення приходить із тестом, який без нього падає.** Один раз запустіть тест на старому коді, щоб
  переконатися в цьому.
- **Куди класти тести:**
  - `tests/analyze.rs`: визначення мови, модулі, ризики, залежності, `--whole-app`.
  - `tests/loop.rs`: bridge, record, diff і shadow для кожної мови, із замінниками замість збірок.
  - `tests/native.rs`: мости, зібрані по-справжньому, потім завантажені й відтворені.
  - `tests/app.rs` і `tests/http.rs`: запис, відтворення, front door і lift цілого застосунку, для CLI та
    серверів.
  - `tests/library.rs`: портування цілих бібліотек.
  - Модульні тести лежать поруч із кодом.
- **Фікстури** є невеликими застосунками в `tests/fixtures/`. Фікстури CLI і HTTP реалізують ті самі
  команди й маршрути кожною мовою (`tcli upper|len|div|words|copy|now`, `/hello`, `/upper`,
  `/div/{a}/{b}`, `/now`), тож нова має поводитися ідентично до інших.
- **Згенерований код** (мости, драйвери і front door, які пише everything-rust) теж має проходити
  `clippy -D warnings`, бо `gate` запускає його на крейтах користувачів.
- **Стиль:** дотримуйтеся коду навколо. Лишайте коментарі для того, чого код не може сказати сам, а
  обґрунтування зміни пишіть у pull request.

## Додайте зіставлення з крейтом

`analyze` називає крейт Rust для кожної бібліотеки, яку імпортує код, із `src/crates.toml`. Щоб додати
зіставлення, допишіть запис під потрібною мовою: `names` (точні імена пакетів) або `prefixes` (початок
імені, для Java і C#), `crates`, `fit` (`good`, `partial` або `none`) і `note`, коли ступінь відповідності
потребує пояснення. Перемагає перший запис, що збігся, тож ставте конкретні перед широкими префіксами.
Бібліотека, якої немає в таблиці, позначається як `unknown`; ніколи не вгадуйте крейт.

## Додайте мову

PHP і C# було додано як попередній перегляд у двох комітах, які варто прочитати першими:
[e8ac243](https://github.com/marprojector/everything-rust/commit/e8ac243) (PHP) і
[caea59a](https://github.com/marprojector/everything-rust/commit/caea59a) (C#). Нова мова починається
так само:

1. Плагін у `src/lang/<name>.rs`: пошук, сканування (імпорти і ризики), резолвінг та експорти,
   плюс крейти для її бібліотек як записи `[[<name>]]` у `src/crates.toml`.
2. Визначення та диспетчеризація в `src/lang/mod.rs`.
3. Підтримка цілого застосунку в `src/whole_app.rs`: точки входу, сервери, оголошені залежності.
4. Фікстури CLI і HTTP, фікстура бібліотеки і тести в `tests/analyze.rs`, `tests/app.rs`
   і `tests/http.rs`.
5. `bridge` відхиляє модулі цієї мови із зрозумілим повідомленням, доки не з'явиться міст.

## Перекладіть README

Переклади вітаються, їх підтримує спільнота. Новий переклад:

1. Лежить у `docs/README_<CODE>.md` (наприклад `docs/README_PT.md`); кореневий `README.md` лишається
   англійською і ніколи не перейменовується і не замінюється.
2. Використовує шляхи, що працюють із `docs/`: `assets/logo.svg`, `../LICENSE`, `../README.md`.
3. Починається з того самого рядка мов, що й інші переклади, де власна мова вказана звичайним
   текстом, а за ним іде примітка, що переклад підтримує спільнота і він може відставати від англійського
   README (скопіюйте її з `docs/README_DE.md` і перекладіть).
4. Додається в **кінець** рядка мов, у `README.md` і в кожному перекладі. Порядок
   уже наведених мов не змінюється.

## Сайт документації

Сайт документації лежить у `website/` (Void, `@void/md`, React). Багато його сторінок включають
розділи `README.md`, `CONTRIBUTING.md` і `docs/*.md` під час збірки, тож редагуйте ці файли, і
сайт підтягнеться. Запускайте його через `cd website && npm ci --ignore-scripts && npm run dev`, а збирайте через
`npm run build`. Довідник CLI береться зі знімка `--help` у
`website/content/cli-help.json`; після зміни CLI оновіть його через `cargo build --release` і
`npm run cli-help` у `website/`.

## Відкрийте pull request

Перед push:

```sh
cargo fmt
cargo clippy --all-targets -- -D warnings
cargo test
```

- Опишіть, що було не так, як це відтворити і як зміна це виправляє.
- Додайте посилання на issue (`Fixes #123`).
- Зазначте все, що ви не змогли протестувати (інша ОС, середовище виконання, якого у вас немає).
- Обмежтеся однією зміною: два виправлення легше рецензувати як два pull request.

CI працює на Ubuntu і macOS з усіма встановленими середовищами виконання. Для того, хто робить внесок уперше, GitHub
чекає, поки мейнтейнер схвалить запуск CI, тож очікуйте невеликої затримки перед початком перевірок.

Pull request зливаються зі збереженням комітів, тож ваша історія лишається вашою. Якщо зміна потребує
невеликих правок, мейнтейнер може додати коміт зверху, замість того щоб просити ще один раунд.

## Поділіться реальним портом

Порти реальних проєктів є найкращим доказом того, що працює, а що ламається. Якщо ви використали
everything-rust на чомусь реальному, issue або pull request, що додає його до
[docs/real-world.md](/docs/real-world/overview), дуже вітаються. Вкажіть проєкт, команди, які ви
запускали, кількість випадків і все, що вас здивувало.
