# Java

| | |
| --- | --- |
| Модуль | пакет методів `public static` |
| Міст | типізований JNI і згенерований бінарний wire, у класах-обгортках з оригінальними методами |
| Записує і відтворює | згенерований драйвер на основі рефлексії |
| Потрібно | JDK 17+ (`javac` і `java`) |
| Статус | Перевірено на JDK 21 за фасадом: 4,492/4,492 (226 кидають виняток), gate проходить |

Пакети створюються як `new FnBatch(items)`; закривайте їх після використання. `profile` використовує JFR.

## Що порт має зробити правильно

- `Integer.parseInt` приймає будь-яку десяткову цифру Unicode (`١٢`, `２`) через `Character.digit`.
- `Double.toString` (JDK 19+) друкує найкоротший десятковий запис, але не менше двох цифр: `4.9E-324`, тоді як найкоротша форма в Rust `5e-324`.
- `\s` охоплює лише ASCII; `split_whitespace` у Rust також ділить по U+00A0.
- Числа з рухомою комою мають пережити перетворення туди й назад: стандартний парсер float у `serde_json` не завжди округлює правильно, тому everything-rust і кожен згенерований ним крейт використовують його можливість `float_roundtrip`.

## Швидкість

Після JIT листкові функції займають кілька наносекунд, а виклик JNI з рядками коштує більше. На фасаді JDK `bench` виміряв порт на рівні 0.18x на виклик: портуйте більші модулі. У пакеті на 4 ядрах `slugify` по 50,000 рядках (43 ms у Java) працював **у 3x швидше** (порт з викликом на кожен елемент: 0.68x).
