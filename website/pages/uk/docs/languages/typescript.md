# TypeScript/JavaScript

| | |
| --- | --- |
| Модуль | тека або файл |
| Міст | napi-rs або wasm-bindgen зі згенерованим бінарним wire; класи та async теж |
| Записує і відтворює | Node, що запускає вихідні файли `.ts` |
| Потрібно | Node 22.6+ (`profile` потребує Node 24+) |
| Статус | Перевірено |

## Вибір мосту

`analyze` обирає napi-rs, коли модуль або щось, що він імпортує, потребує Node, wasm-bindgen для портабельного коду (він також працює в браузерах), а код UI і редактора лишає в JS. `bridge --kind napi|wasm` перевизначає вибір.

Експорти, що не можуть перетнути міст, лишаються в TS із зазначеною причиною, а shadow-модуль реекспортує оригінал: функції, що приймають або повертають функції, генератори та ітератори, RegExp, перевірки `instanceof`, генерики (`--as-json T` з'єднує мостом той, який застосунок заповнює лише даними) і значення, чиї типи містять функції. Див. [Bridge](/docs/concepts/bridge).

## Запис TS як є

`record` запускає вихідні файли TS напряму: хук резолвінгу Node обробляє імпорти в стилі бандлерів, `--resolve-from` підставляє пакети npm, коли в репозиторії нічого не встановлено, а TS, що потребує трансформації (enum, parameter properties), повторно запускається з `--experimental-transform-types`. `record --from-tests -- npx jest` записує кожен виклик, який робить власний набір тестів оригіналу, з будь-яким раннером. Для TS/JS вимірюється покриття оригіналу ([Покриття](/docs/concepts/coverage)).

## Що порт має зробити правильно

Знайдено записаними випадками на реальному коді:

- `str.length`, `indexOf` і `slice` рахують кодові одиниці UTF-16, тож емодзі займає дві позиції. Використовуйте згенеровані хелпери `utf16`.
- `/.../i` без прапорця `u` згортає регістр лише для літер ASCII, а `regex` у Rust згортає Unicode, тож `"1 ſ"` (довга s) і знак Кельвіна розбиралися б як секунди у vercel/ms.
- `Math.round` округлює половини вгору (`-2.5` дає `-2`); `round` у Rust округлює від нуля. У згенерованому `js.rs` є `js::math_round`.
- `${n}` друкує `1e+21`, `5e-324` і `0` для `-0`. `js::number_to_string` відтворює це.
- `String.prototype.trim` використовує пробільні символи JS, а не `char::is_whitespace` з Rust.

## Швидкість

При поодиноких викликах порт щоразу платить за міст, а V8 виконує маленькі функції за наносекунди. vercel/ms працював на рівні 0.56x на виклик на своїх записаних випадках; порти ядра x18n повільніші за TS при виклику з JS. У пакетах цикл переходить у Rust:

| Навантаження | Оригінал | З everything-rust |
| --- | ---: | ---: |
| Пошук у бічній панелі x18n, 50,000 ключів (Node) | 10 ms на запит | 0.5 ms: у 20x швидше |
| Той самий пошук у браузері (wasm, один потік) | 10 ms | 0.95 ms: 11.5x |
| Fuse.js, 50,000 рядків | 91.2 ms | 2.8 ms: 32x |
| vercel/ms `parse` x100,000 | 11.8 ms | 0.65 ms: 18x (3.4x з урахуванням передачі) |
| vercel/ms `format` x100,000 | 2.1 ms | 2.5 ms з передачею: 0.8x |

Приклади з практики: [json-server](/docs/real-world/json-server), [Fuse.js](/docs/real-world/fuse-js), [vercel/ms](/docs/real-world/vercel-ms), [x18n](/docs/real-world/x18n).
