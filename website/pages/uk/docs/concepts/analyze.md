# Профілювання й аналіз

## Profile: знайдіть, що варто переносити

Коли мета в швидкості, вимірюйте, перш ніж щось обирати:

```sh
everything-rust profile <repo> -- node bench.mjs      # або: python3 bench.py, ruby bench.rb,
                                                    #     java -cp out Main, go test -run X -bench . ./pkg
```

`profile` запускає реальне навантаження під профайлером мови (node, cProfile, pprof через `go test`, JFR, трейсер Ruby) і перелічує гарячі функції за інклюзивним часом, код, що їх викликає, і цикли, які варто запакетувати. Go профілюється лише через `go test`; C не підтримується.

- Маленьку функцію, яку викликають раз на елемент, **не** варто портувати окремо: один виклик у Rust коштує більше за її роботу, а JIT (V8, JVM, Go) виконують її за наносекунди. Портуйте її разом із кодом, що її викликає, або [запакетуйте її](/docs/concepts/batches). Рядок поради каже, що саме, з точною командою.
- Код, уже скомпільований (numba `@njit`, Cython, `@jax.jit`), виконується як машинний: порт на Rust мало що дасть у швидкості. `profile` перелічує його в розділі "Already compiled".

## Analyze: сплануйте портування

```sh
everything-rust analyze <repo> -o plan.md        # для людей
everything-rust analyze <repo> --json            # для агентів: схема everything-rust/analyze@1
everything-rust analyze <repo> --whole-app       # плюс точки входу, форма, залежності, рішення
```

`analyze` перелічує модулі, порядок портування, ризики з `file:line`, міст для кожного модуля, наскільки добре кожна залежність відповідає крейту, і `start_here`: найкращі перші порти. `--whole-app` додає форму застосунку (CLI, сервер чи бібліотека) і точки входу, кожну залежність (імпортовану чи оголошену) з її крейтом, частини (модулі, що імпортують один одного, переносяться разом) і пронумеровані рішення з рекомендованою відповіддю. Див. [Портування цілого застосунку](/docs/whole-apps/overview).

- Пакети (`package.json`) і вихідні файли; пропускає `node_modules`, результати збірки, фікстури,
  пісочниці, конфіги інструментів. Блоки `<script>` у Vue/Svelte/Astro розбираються на імпорти.
- **Модулі**: тека з вихідними файлами або файл у корені вихідного коду пакета.
- **Хвилі**: імпорти модуля потрапляють у попередні хвилі; циклічні імпорти портуються разом.
- **Міст**: napi-rs, коли модуль або щось, що він імпортує, потребує Node; wasm-bindgen для портабельного
  коду; лишити в JS для коду UI і редактора.
- **Готовність** (наскільки безпечно) і **пріоритет** (безпечно і варто того: цикли і робота з рядками, тести, розмір).

| Ризик | Серйозність | Приклад |
| --- | --- | --- |
| Зміщення в рядках | висока | `slice`, `indexOf`, `matchAll`, прапорець `d`: UTF-16 проти UTF-8 |
| Синтаксис регулярних виразів | висока | lookaround, зворотні посилання, `y`: немає в крейті `regex` |
| Динамічні регулярні вирази | висока | `new RegExp(userPattern)`: синтаксис JS під час виконання |
| Динамічний код | висока | `eval`, `new Function`, обчислюваний `import()` |
| Динамічна типізація | середня | `any`, `'key' in value` |
| Впорядковані колекції | середня | `Map`, `Set`, `Object.keys`: порядок вставки |
| Async, генератори | середня | межі промісів і генераторів |
| Успадкування класів, рефлексія | середня | `extends`, `Proxy`, `Reflect`, `Symbol` |
| API на колбеках | середня | параметри й методи з типом функції: балакучі мости |
| Винятки, числа, JSON | низька | `throw`, побітові операції, порядок у `JSON.stringify` |
## Крейти для залежностей

`analyze` називає крейт Rust для кожної бібліотеки, яку імпортує код, з оцінкою відповідності `good`, `partial` або `none`. Бібліотека, якої немає в таблиці, позначається як `unknown`; таблиця ніколи не вгадує крейт. Щоб додати бібліотеку, див. [Як долучитися](/docs/project/contributing#add-a-crate-mapping).
