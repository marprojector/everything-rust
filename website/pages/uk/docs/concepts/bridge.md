# Bridge

```sh
everything-rust bridge <repo> <unit-id>          # крейт у <repo>/rust/<name>; ніколи не перезаписує
everything-rust refresh <crate>                  # після зміни сигнатури в port.rs
```

`bridge` створює крейт із прив'язками (`lib.rs` плюс обгортка, яку завантажує мова оригіналу) і заглушками для портування (`port.rs`). Порт ви пишете лише в `src/port.rs`; `src/lib.rs` та обгортки генеруються, а `refresh` перегенеровує їх із сигнатур у `port.rs`, додаючи нові пакетні класи. `port.rs` він ніколи не чіпає.

Параметри:

- `--batch fn:param` додає клас, що тримає багато значень `param` у Rust. Див. [Пакети](/docs/concepts/batches).
- `--as-json T` передає через міст як значення JSON параметр типу, який застосунок заповнює лише даними (`T` у `paginate<T>(items: T[])`).
- `--keep "name: reason"` лишає більше експортів мовою оригіналу, наприклад код, що залежить від даних `Intl`.
- `--kind` перевизначає міст, обраний планом (napi-rs або wasm для TypeScript).

## Міст для кожної мови

| Мова | Міст |
| --- | --- |
| TypeScript/JavaScript | napi-rs або wasm-bindgen зі згенерованим бінарним wire; класи та async теж |
| Python | PyO3 (abi3), пряме перетворення, типізовані винятки |
| C | функції `extern "C"` з оригінальними іменами та заголовний файл |
| Go | типізовані виклики cgo і згенерований бінарний wire, у пакеті з оригінальним API |
| Ruby | розширення magnus під оригінальними модулями |
| Java | типізований JNI і згенерований бінарний wire, у класах-обгортках з оригінальними методами |

Модулі PHP і C# поки не можна з'єднати мостом; див. [PHP](/docs/languages/php) і [C#](/docs/languages/csharp).

## Що вирішує bridge

- Експорти, що не можуть перетнути міст, лишаються мовою оригіналу із зазначеною причиною, а shadow-модуль
  реекспортує оригінал. Для TS це:
  функції, що приймають або повертають функції, генератори та ітератори, RegExp, перевірки `instanceof`,
  генерики (`--as-json T` з'єднує мостом той, який застосунок заповнює лише даними) і значення, чиї типи (з урахуванням імпортів, реекспортів і `extends`) містять
  функції. `--keep "name: reason"` лишає більше, наприклад код, що залежить від даних `Intl`.
- Типи TS зіставляються з типами Rust: псевдоніми типів розв'язуються через імпорти, а типи параметрів
  виводяться зі значень за замовчуванням; структуровані значення передаються через згенерований бінарний wire (JSON лише
  як запасний варіант для форм, які wire не моделює).
- JSON не може виразити `undefined`, NaN, Infinity, -0 чи поодинокі сурогати: структуровані значення несуть
  позначки (`{"$undefined": true}`, `{"$num": "NaN"}`, `{"$utf16": [...]}`), які перекладає згенерований
  `index.cjs`, з хелперами в `js.rs` крейта.

`record` запускає вихідні файли TS як є: хук резолвінгу Node обробляє імпорти в стилі бандлерів
(`./errors` до `./errors.ts`), `--resolve-from` підставляє пакети npm, коли в репозиторії нічого не
встановлено, а TS, що потребує трансформації (enum, parameter properties), повторно запускається з
`--experimental-transform-types`.
