# Пакети й гарячі шляхи

```sh
everything-rust bridge <repo> <unit> --batch fn:param    # або: everything-rust refresh <crate> --batch fn:param
```

`--batch` генерує клас, що приймає значення `param` один раз і тримає їх у Rust: `new FnBatch(items)` (TS, Python, Java), `Mod::FnBatch.new(items)` (Ruby), `NewFnBatch(items)` (Go). На кожен запит `run(<other args>)` повертає всі результати одним масивом, а `rank(<other args>, min)` повертає індекси елементів, найкращі першими. Він працює на всіх ядрах, а помилки такі самі, як в оригіналу. Пакети отримує кожна мова, крім C.

Порт, який викликають раз на елемент, платить за міст раз на елемент і програє JIT. Виграє
перенесення циклу: `profile` знаходить його, а `--batch` генерує клас, що приймає елементи один раз
і на кожен виклик проганяє функцію по всіх них, на всіх ядрах, з результатами у типізованих масивах.

```sh
everything-rust profile ../x18n -- node --experimental-strip-types $PWD/demo/x18n-search/search.ts .
# -> fuzzyScore: чверть прогону, викликається для кожного ключа з `matched`: запакетуйте
everything-rust bridge ../x18n packages/core/src/fuzzy.ts --batch fuzzyScore:text
```

```js
const search = new FuzzyScoreBatch(keys)          // once
const order = search.rank(query, 0)               // per keystroke: indexes, best first
```

Структура `FuzzyScoreIndex` у `port.rs` замінює стандартний цикл таким, що готує
елементи один раз і вміє сам ранжувати (`rank`): вона тримає ключі в нижньому регістрі з маскою символів
для кожного, таблицю першої позиції кожного поширеного символу в кожному ключі (однолітерний запит є одним
стовпцем) і збіги останнього запиту (введення `se` після `s` переоцінює лише те, що збіглося з `s`). На
пошуку в бічній панелі x18n по 50,000 ключах, з введенням по літері, з ідентичними результатами:

| | На запит | проти TS |
| --- | ---: | ---: |
| TS: `map(fuzzyScore)`, filter, sort | 10 ms | 1x |
| TS з тим самим звуженням, що й індекс | 4.1-5.4 ms | 2x |
| Той самий порт, викликаний для кожного ключа | - | 0.2-0.4x |
| `FuzzyScoreBatch`, стандартний індекс (4 ядра) | 5.1 ms | 1.7x |
| `FuzzyScoreBatch` з `FuzzyScoreIndex` (napi, 4 ядра) | 0.45-0.56 ms | **18-22x** |
| Те саме з wasm (один потік) | 0.95 ms | **11.5x** |

Порівняно з TS, що робить те саме звуження, Rust усе одно у 7-12x швидший (wasm 5x). Перетворюйте повернені
індекси на ключі звичайним циклом: `Array.from(order, i => keys[i])` коштував у 20x більше, 0.4 ms.

Пакети отримує кожна мова, і вони обганяють оригінал навіть там, де порти з поодинокими викликами програють. Та
сама робота на 4 ядрах, ідентичні результати і помилки (бенчмарки в теці кожного демо):

| Мова | Навантаження | Оригінал | Порт з поодинокими викликами проти оригіналу | Пакет проти оригіналу |
| --- | --- | ---: | ---: | ---: |
| TS | пошук x18n, 50,000 ключів | 10 ms | 0.2-0.4x | **20x** |
| Python | `slugify`, 20,000 рядків | 98 ms | - | **17x** |
| Ruby | `slugify`, 20,000 рядків | 110 ms | - | **12.7x** |
| Ruby | `shellescape` (stdlib), 50,000 різнотипних значень | 88 ms | - | **11.8x** |
| Go | `Slugify`, 50,000 рядків | 49 ms | 0.93x | **4x** |
| Java | `slugify`, 50,000 рядків | 43 ms | 0.68x | **3x** |

Скомпільовані оригінали виграють менше: робота на елемент і так швидка, тож пакет виграє приблизно на кількість
ядер. Пакетні крейти виділяють пам'ять через mimalloc: із системним алокатором пакет Go був повільнішим за
один потік. Демо: [`demo/x18n-search`](https://github.com/marprojector/everything-rust/blob/main/demo/x18n-search/README.md).
## Як написати швидкий індекс

- Нехай код, що викликає, будує пакет один раз, а не на кожен запит. Перетворюйте повернені індекси назад на елементи звичайним циклом.
- Щоб підготувати елементи один раз (нижній регістр, маски, таблиці позицій), визначте `pub struct FnIndex` у `port.rs` з `new(items)` і `run(<other args>)`. Він має давати той самий результат, що й функція, елемент за елементом.
- Коли ранжування може пропускати роботу, дайте індексу власний `rank(<other args>, min)`. Він має збігатися з ранжуванням результатів функції: оцінка від більшої до меншої, рівні в порядку елементів.
- Пакет множить швидкість порту на елемент на кількість ядер. Проти скомпільованих оригіналів (Go, Java) сам порт має бути швидким: обробляйте ASCII без таблиць Unicode, будуйте кожен результат в одному заздалегідь розміщеному `String`, уникайте проміжних копій.
- У Go і Java закривайте пакет після використання (фіналізатори лише запасний варіант).
