# Цикл

Кожне портування, від однієї гарячої функції до цілого застосунку, проходить ті самі кроки, по одному модулю за раз. Порт готовий лише тоді, коли проходить `gate`.

Як everything-rust перевіряє порт, що вирішують його команди і де пролягають його межі. Назад до [README](/).

## Як це працює

```
profile ──> analyze ──> bridge ──> record ──> port.rs ──> diff ──> bench ──> shadow ──> gate
 where the    what to     the Rust   what the    you or      every     faster?    both side   done means
 time goes    port first  crate and  original    your agent  recorded  the        by side in  this passes
                          wrapper    does        write it    case      verdict    production
```

Оригінал лишається джерелом істини: `record` запускає його на граничних випадках (і ваших власних вхідних даних) і
зберігає, що він повертає або кидає; `diff` відтворює кожен випадок на Rust; нічого не йде в реліз, доки
всі вони не збігаються і `gate` не проходить. Код, що викликає, увесь час зберігає оригінальний API.

Цілий застосунок проходить той самий цикл модуль за модулем, усередині рамки, що доводить усю
програму ([Портування цілого застосунку](/docs/whole-apps/overview)):

```
analyze --whole-app ──> app record ──> app front-door ──> per unit: the loop above, then app wire ──> app lift
 shape, every           what the app    Rust owns the       gate passes, so the unit answers in         pure Rust,
 dependency, the        does from the   entry point; the     Rust: replay 100%, fallback rate down      proved by
 decisions to make      outside         original answers                                                replay
```

## Цикл

| Крок | Команда | Що робить |
| --- | --- | --- |
| 0. Профілювання | `everything-rust profile <repo> -- node bench.mjs` | Запускає реальне навантаження під профайлером мови (node, cProfile, pprof через `go test`, JFR, трейсер Ruby): гарячі функції за інклюзивним часом, код, що їх викликає, і цикли, які варто запакетувати; позначає вже скомпільований код (numba, Cython, JAX), де Rust мало що виграє |
| 1. План | `everything-rust analyze <repo>` | Модулі, порядок портування, ризики з `file:line`, міст для кожного модуля, відповідність залежностей крейтам, найкращі перші порти; `--whole-app` додає точки входу і форму, кожну залежність (імпортовану чи оголошену) з її крейтом, частини (модулі, що імпортують один одного, переносяться разом) і пронумеровані рішення з рекомендованою відповіддю |
| 2. Міст | `everything-rust bridge <repo> <unit>` | Крейт із прив'язками (`lib.rs` плюс обгортка, яку завантажує мова оригіналу) і заглушками для портування (`port.rs`); `--batch fn:param` додає клас, що тримає багато значень `param` у Rust; `--as-json T` передає через міст як значення JSON параметр типу, який застосунок заповнює лише даними |
| 3. Запис | `everything-rust record <crate>` | Запускає оригінал на згенерованих граничних випадках (не-ASCII, емодзі, `-0`, `NaN`, int там, де очікуються float, ...) і на кожній семантичній пастці в кожному параметрі (довжина і регістр рядків, ділення зі знаком, межі переповнення, друк float, порядок у мапах і сортуванні) і зберігає `cases.jsonl`; `--from-tests -- npx jest` (або `-- pytest`) також записує кожен виклик, який робить власний набір тестів оригіналу; `--float-tolerance 1e-9` дозволяє float збігатися в межах цієї частки для числового коду |
| 3. Збірка | `everything-rust build <crate>` | Збирає сторону Rust: `.node`, пакет wasm, розширення Python або спільну бібліотеку |
| 3. Diff | `everything-rust diff <crate>` | Відтворює записані випадки на Rust, викликаючи його так, як його викликає код оригіналу; перелічує розбіжності |
| 3. Bench | `everything-rust bench <crate>` | Вимірює час записаних випадків на оригіналі та на Rust, включно з мостом |
| 4. Shadow | `everything-rust shadow <crate>` | Заміна, що запускає обидва, повертає результат оригіналу, повідомляє про розбіжності; `EVERYTHING_RUST_MODE=old\|shadow\|new` |
| 5. Gate | `everything-rust gate <crate>` | fmt, clippy `-D warnings`, тести, аудит `unsafe`, нічого непортованого, записаний провальний випадок для кожного шляху помилки оригіналу, жодних `unwrap`/`expect`/`panic!` там, де оригінал повертає помилку (якщо не позначено `// INFALLIBLE: <why>`), збірка, API, поведінка |
| Агенти | `everything-rust setup` | Реєструє сервер MCP (`everything-rust mcp`, кожен крок як інструмент) і навичку робочого процесу ([`skills/everything-rust/SKILL.md`](https://github.com/marprojector/everything-rust/blob/main/skills/everything-rust/SKILL.md)) у ваших агентах для програмування |

## Гарячі шляхи: тримайте дані в Rust

Порт, який викликають раз на елемент, платить за міст раз на елемент і програє JIT. Виграє
перенесення циклу: `profile` знаходить його, а `--batch` генерує клас, що приймає елементи один раз
і на кожен виклик проганяє функцію по всіх них, на всіх ядрах, з результатами у типізованих масивах.

```sh
everything-rust profile ../x18n -- node --experimental-strip-types $PWD/demo/x18n-search/search.ts .
# -> fuzzyScore: чверть прогону, викликається для кожного ключа з `matched`: запакетуйте
everything-rust bridge ../x18n packages/core/src/fuzzy.ts --batch fuzzyScore:text
```

```js
const search = new FuzzyScoreBatch(keys)          // once
const order = search.rank(query, 0)               // per keystroke: indexes, best first
```

Структура `FuzzyScoreIndex` у `port.rs` замінює стандартний цикл таким, що готує
елементи один раз і вміє сам ранжувати (`rank`): вона тримає ключі в нижньому регістрі з маскою символів
для кожного, таблицю першої позиції кожного поширеного символу в кожному ключі (однолітерний запит є одним
стовпцем) і збіги останнього запиту (введення `se` після `s` переоцінює лише те, що збіглося з `s`). На
пошуку в бічній панелі x18n по 50,000 ключах, з введенням по літері, з ідентичними результатами:

| | На запит | проти TS |
| --- | ---: | ---: |
| TS: `map(fuzzyScore)`, filter, sort | 10 ms | 1x |
| TS з тим самим звуженням, що й індекс | 4.1-5.4 ms | 2x |
| Той самий порт, викликаний для кожного ключа | - | 0.2-0.4x |
| `FuzzyScoreBatch`, стандартний індекс (4 ядра) | 5.1 ms | 1.7x |
| `FuzzyScoreBatch` з `FuzzyScoreIndex` (napi, 4 ядра) | 0.45-0.56 ms | **18-22x** |
| Те саме з wasm (один потік) | 0.95 ms | **11.5x** |

Порівняно з TS, що робить те саме звуження, Rust усе одно у 7-12x швидший (wasm 5x). Перетворюйте повернені
індекси на ключі звичайним циклом: `Array.from(order, i => keys[i])` коштував у 20x більше, 0.4 ms.

Пакети отримує кожна мова, і вони обганяють оригінал навіть там, де порти з поодинокими викликами програють. Та
сама робота на 4 ядрах, ідентичні результати і помилки (бенчмарки в теці кожного демо):

| Мова | Навантаження | Оригінал | Порт з поодинокими викликами проти оригіналу | Пакет проти оригіналу |
| --- | --- | ---: | ---: | ---: |
| TS | пошук x18n, 50,000 ключів | 10 ms | 0.2-0.4x | **20x** |
| Python | `slugify`, 20,000 рядків | 98 ms | - | **17x** |
| Ruby | `slugify`, 20,000 рядків | 110 ms | - | **12.7x** |
| Ruby | `shellescape` (stdlib), 50,000 різнотипних значень | 88 ms | - | **11.8x** |
| Go | `Slugify`, 50,000 рядків | 49 ms | 0.93x | **4x** |
| Java | `slugify`, 50,000 рядків | 43 ms | 0.68x | **3x** |

Скомпільовані оригінали виграють менше: робота на елемент і так швидка, тож пакет виграє приблизно на кількість
ядер. Пакетні крейти виділяють пам'ять через mimalloc: із системним алокатором пакет Go був повільнішим за
один потік. Демо: [`demo/x18n-search`](https://github.com/marprojector/everything-rust/blob/main/demo/x18n-search/README.md).

## Що вирішує `bridge`

- Експорти, що не можуть перетнути міст, лишаються мовою оригіналу із зазначеною причиною, а shadow-модуль
  реекспортує оригінал. Для TS це:
  функції, що приймають або повертають функції, генератори та ітератори, RegExp, перевірки `instanceof`,
  генерики (`--as-json T` з'єднує мостом той, який застосунок заповнює лише даними) і значення, чиї типи (з урахуванням імпортів, реекспортів і `extends`) містять
  функції. `--keep "name: reason"` лишає більше, наприклад код, що залежить від даних `Intl`.
- Типи TS зіставляються з типами Rust: псевдоніми типів розв'язуються через імпорти, а типи параметрів
  виводяться зі значень за замовчуванням; структуровані значення передаються через згенерований бінарний wire (JSON лише
  як запасний варіант для форм, які wire не моделює).
- JSON не може виразити `undefined`, NaN, Infinity, -0 чи поодинокі сурогати: структуровані значення несуть
  позначки (`{"$undefined": true}`, `{"$num": "NaN"}`, `{"$utf16": [...]}`), які перекладає згенерований
  `index.cjs`, з хелперами в `js.rs` крейта.

`record` запускає вихідні файли TS як є: хук резолвінгу Node обробляє імпорти в стилі бандлерів
(`./errors` до `./errors.ts`), `--resolve-from` підставляє пакети npm, коли в репозиторії нічого не
встановлено, а TS, що потребує трансформації (enum, parameter properties), повторно запускається з
`--experimental-transform-types`.

## На що дивиться `analyze`

- Пакети (`package.json`) і вихідні файли; пропускає `node_modules`, результати збірки, фікстури,
  пісочниці, конфіги інструментів. Блоки `<script>` у Vue/Svelte/Astro розбираються на імпорти.
- **Модулі**: тека з вихідними файлами або файл у корені вихідного коду пакета.
- **Хвилі**: імпорти модуля потрапляють у попередні хвилі; циклічні імпорти портуються разом.
- **Міст**: napi-rs, коли модуль або щось, що він імпортує, потребує Node; wasm-bindgen для портабельного
  коду; лишити в JS для коду UI і редактора.
- **Готовність** (наскільки безпечно) і **пріоритет** (безпечно і варто того: цикли і робота з рядками, тести, розмір).

| Ризик | Серйозність | Приклад |
| --- | --- | --- |
| Зміщення в рядках | висока | `slice`, `indexOf`, `matchAll`, прапорець `d`: UTF-16 проти UTF-8 |
| Синтаксис регулярних виразів | висока | lookaround, зворотні посилання, `y`: немає в крейті `regex` |
| Динамічні регулярні вирази | висока | `new RegExp(userPattern)`: синтаксис JS під час виконання |
| Динамічний код | висока | `eval`, `new Function`, обчислюваний `import()` |
| Динамічна типізація | середня | `any`, `'key' in value` |
| Впорядковані колекції | середня | `Map`, `Set`, `Object.keys`: порядок вставки |
| Async, генератори | середня | межі промісів і генераторів |
| Успадкування класів, рефлексія | середня | `extends`, `Proxy`, `Reflect`, `Symbol` |
| API на колбеках | середня | параметри й методи з типом функції: балакучі мости |
| Винятки, числа, JSON | низька | `throw`, побітові операції, порядок у `JSON.stringify` |

## Чого він не впіймає

Проходження означає, що Rust збігається з кожним записаним випадком, і не більше. Те, що шкодить переписуванням,
зазвичай лежить поза записом, тож знайте, де пролягають межі:

- **Вхідні дані, яких ніхто не записав.** Згенеровані випадки, пастки, набір тестів оригіналу
  (`record --from-tests`) і ваші власні `--inputs` є стелею. Додавайте реальні вхідні дані (зразки з
  продакшну, звіти про баги); введення користувача, що ламає прод, рідко буває тим, яке спаде на думку генератору.
- **Оригінал, що змінився.** `record` зберігає відбиток файлів модуля
  (`recorded-from.json`); коли оригінал згодом змінюється, `diff` попереджає, а `gate` падає, доки ви
  не запишете знову, замість того щоб проходити проти того, що оригінал робив раніше.
- **Регулярні вирази.** Крейт `regex` не має lookaround і зворотних посилань, і навіть шаблон, який
  компілюється, може обробляти `\w`, `\b`, `\d` і пошук без урахування регістру на не-ASCII тексті інакше,
  ніж JS, Python чи Java. Заміна на `fancy-regex` чи переписаний шаблон можуть пройти кожен
  записаний випадок і все одно розійтися на турецькій `ı` без крапки чи на zero-width joiner. `record` додає
  пастки для регулярних виразів (ці, знак Кельвіна, довгу s, арабсько-індійські цифри, роздільники рядків, кінцеву сигму)
  до кожної функції у файлі, що використовує регулярні вирази, але також фазьте свої реальні шаблони на реальному тексті.
- **Те, що змінюється між запусками.** `record` запускає оригінал двічі і розбирає, що відрізнялося:
  змінені значення (час, ідентифікатори) стають шаблонами; ті самі рядки в іншому порядку (хеш-мапи,
  конкурентність) порівнюються в будь-якому порядку, тож порт усе одно має видати саме ці рядки;
  інша кількість рядків стає `...`, що збігається з будь-чим. `record` перелічує кожен вид:
  перегляньте кожен, бо відмінність у порядку хешів чи в конкурентності якраз і може реально змінитися
  в порті.
- **Float.** Перетворення чисел на текст відрізняється між мовами (`1e21`, `-0`, кількість цифр).
  Пастки містять такі значення, і вони мають збігатися точно; `--float-tolerance` пробачає
  лише округлення, ніколи не форматування.
- **Усе, чого немає у виводі.** Час виконання, пам'ять, конкурентність під навантаженням і побічні ефекти, окрім
  stdout, stderr, кодів виходу, записаних файлів і HTTP-відповідей (мережеві виклики, бази даних,
  сигнали), не порівнюються.
- **Інші платформи.** Запис доводить поведінку на машині, яка його виконала. Код C, чиї результати
  залежать від розмірів типів, порядку байтів чи компілятора, може поводитися інакше на цільовій платформі; `analyze`
  з цієї причини лишає код C, що працює із залізом, у C.

Gate | `everything-rust gate <crate>` | fmt, clippy `-D warnings`, тести, аудит `unsafe`, нічого непортованого, записаний провальний випадок для кожного шляху помилки оригіналу, жодних `unwrap`/`expect`/`panic!` там, де оригінал повертає помилку (якщо не позначено `// INFALLIBLE: <why>`), збірка, API, поведінка |
| Агенти | `everything-rust setup` | Реєструє сервер MCP (`everything-rust mcp`, кожен крок як інструмент) і навичку робочого процесу ([`skills/everything-rust/SKILL.md`](https://github.com/marprojector/everything-rust/blob/main/skills/everything-rust/SKILL.md)) у ваших агентах для програмування |
