# Bench

```sh
everything-rust bench <crate>
```

`bench` вимірює час записаних випадків на оригіналі та на зібраному модулі Rust, включно з мостом, і повертає рядки результатів і вердикт із порадою: випускати, лишити повільніші функції мовою оригіналу або портувати більший модуль. Прискорення менше за 1 означає, що порт повільніший у тому вигляді, як його викликає код. `--min-ms` задає мінімальний виміряний час на функцію і на кожну сторону (за замовчуванням 200).

Дотримуйтеся вердикту. Не випускайте порт, що сповільнює код, який його викликає, не сказавши про це.

## Чому порт може бути повільнішим

Порт, який викликають раз на елемент, платить за міст раз на елемент. Що вирішує:

- **Інтерпретовані оригінали (Python, Ruby)**: виклик у Rust коштує близько 100-300 ns, а код Rust набагато швидший за інтерпретатор, тож виграють навіть маленькі функції.
- **Скомпільовані оригінали (Go, Java після JIT)**: листкова функція оригіналу займає 4-90 ns; один виклик cgo сам по собі коштує близько 80 ns, виклик JNI з рядками більше. Ці мови виграють лише тоді, коли один виклик робить багато роботи: портуйте функцію разом із кодом, що її викликає.
- **C**: перетину межі немає; код Rust порівнюється з кодом C напряму.

Виміряно на виклик на реальному коді ([шість мов](/docs/real-world/six-languages)):

| Мова | Rust проти оригіналу (`bench`, середнє геометричне) | Вердикт |
| --- | --- | --- |
| Ruby | **у 4.4x швидше** (3.6-7x на функцію) | випускати |
| Python | **у 1.35x швидше** (1.5-1.9x на більшості викликів) | випускати |
| C | 0.87x: ctype у 1.1-1.4x швидше, налаштовані в glibc `strtod`, `strspn`, `strcmp` 0.5-0.7x | оптимізувати або лишити повільніші |
| Java | 0.18x | портувати більші модулі |
| Go | 0.04x | портувати більші модулі |

Усі 29 функцій ядра x18n, які можна перенести без зміни API, було портовано: кожен gate проходить і 7,925 записаних випадків збігаються точно, а `bench` показав, що порти повільніші за TS при виклику з JS, бо міст коштує більше за саму роботу ([звіт](https://github.com/marprojector/everything-rust/blob/main/demo/x18n-core/README.md)). vercel/ms працював на рівні 0.56x на виклик на своїх записаних випадках ([розбір](/docs/real-world/vercel-ms)).

## Що виграє: перенесення циклу

`profile` знаходить цикл навколо гарячої функції, а `--batch` переносить увесь цикл у Rust, на всі ядра. Див. [Пакети й гарячі шляхи](/docs/concepts/batches).

::: tip Вимірюйте на ненавантаженій машині
Запускайте `bench` на ненавантаженій машині, запускайте його двічі і вказуйте залізо та кількість ядер поруч із кожним опублікованим числом.
:::
