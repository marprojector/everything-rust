# Record

```sh
everything-rust record <crate>
everything-rust record <crate> --from-tests -- npx jest      # або: -- pytest
everything-rust record <crate> --inputs extra.jsonl
```

`record` запускає оригінальні функції і зберігає, що кожна з них повертає або кидає, у `cases.jsonl` поруч із крейтом: це поведінка, якій має відповідати порт. Розбіжність надалі є відмінністю в поведінці: виправляйте порт, ніколи не запис.

## Звідки беруться випадки

- **Згенеровані граничні випадки**: не-ASCII, емодзі, `-0`, `NaN`, int там, де очікуються float, тощо (`--count` задає, скільки на функцію).
- **Семантичні пастки** в кожному параметрі: довжина і регістр рядків, ділення зі знаком, межі переповнення, друк float, порядок у мапах і сортуванні.
- **Пастки для регулярних виразів** для кожної функції у файлі, що використовує регулярні вирази: турецька `ı` без крапки, знак Кельвіна, довга s, арабсько-індійські цифри, роздільники рядків, кінцева сигма, zero-width joiner.
- **Власні тести оригіналу**: `--from-tests -- <test command>` записує кожен виклик, який набір тестів робить до експортованих функцій модуля (TS/JS з будь-яким раннером, Python з pytest або unittest). Після цього вихідний код відновлюється. На vercel/ms це захопило 340 викликів із 167 тестів Jest.
- **Ваші вхідні дані**: `--inputs cases.jsonl` з одним `{"fn": name, "args": [...]}` на рядок. Додавайте реальні вхідні дані (зразки з продакшну, звіти про баги); введення користувача, що ламає прод, рідко буває тим, яке спаде на думку генератору.

Код на Python передає `1` так само часто, як `1.0`, тож під час запису цілі значення передаються як int у кожному четвертому випадку Python.

## Позначки в cases.jsonl

JSON не може виразити `undefined`, NaN, Infinity, -0 чи поодинокі сурогати. Структуровані значення несуть позначки, які перекладає згенерований `index.cjs`, з хелперами в `js.rs` крейта:

| Позначка | Означає |
| --- | --- |
| `{"$undefined": true}` | `undefined` у JavaScript |
| `{"$num": "NaN"}` | число, яке JSON не може зберегти (`NaN`, `Infinity`, `-0`) |
| `{"$utf16": [...]}` | рядок, заданий кодовими одиницями UTF-16, для поодиноких сурогатів |

Вхідні дані C поза контрактом функції можуть обвалити оригінал. Драйвер C запускає кожен випадок у дочірньому процесі через fork і записує `crash: SIGSEGV`; `diff` приймає там будь-яку поведінку порту, бо поведінка C невизначена.

## Два прогони і що відрізняється

`record` запускає оригінал двічі і розбирає, що відрізнялося між прогонами: змінені значення (час, ідентифікатори) стають шаблонами; ті самі рядки в іншому порядку (хеш-мапи, конкурентність) порівнюються в будь-якому порядку; інша кількість рядків стає `...`, що збігається з будь-чим. `record` перелічує кожен вид. Перегляньте кожен, бо відмінність у порядку хешів чи в конкурентності якраз і може реально змінитися в порті.

## Запис пам'ятає свій оригінал

`record` зберігає відбиток файлів модуля (`recorded-from.json`). Коли оригінал згодом змінюється, `diff` попереджає, а `gate` падає, доки ви не запишете знову, замість того щоб проходити проти того, що оригінал робив раніше. Див. [Diff](/docs/concepts/diff#stale-recordings).

## Особливості TypeScript

`record` запускає вихідні файли TS як є: хук резолвінгу Node обробляє імпорти в стилі бандлерів (`./errors` до `./errors.ts`), `--resolve-from` підставляє пакети npm, коли в репозиторії нічого не встановлено, а TS, що потребує трансформації (enum, parameter properties), повторно запускається з `--experimental-transform-types`. TS, який не може запуститися напряму в Node, можна записати з результату збірки через `--module dist/x.mjs` або з `--node-arg=--import=tsx`.

## Числовий код

Для коду, де float рідко збігаються біт у біт, записуйте з `--float-tolerance`. Див. [Допуск для float](/docs/concepts/float-tolerance).
