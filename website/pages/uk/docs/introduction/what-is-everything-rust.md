# Що таке everything-rust

<p class="lead">Перепишіть увесь застосунок на Rust, по одній частині за раз. everything-rust записує, що ваш застосунок на Node.js (TypeScript/JavaScript), Python, C, Go, Ruby або Java робить сьогодні, а потім звіряє кожну частину переписаного на Rust коду з цим записом, перш ніж рухатися далі, доки застосунок не стане чистим Rust.</p>

Він працює з CLI, HTTP-серверами і бібліотеками. Rust пише ваш агент для програмування (Claude Code, Codex, Cursor, Gemini CLI) або ви самі. PHP і C# у стадії [попереднього перегляду](/docs/languages/php).

## Що він робить і чого не робить

everything-rust не перекладає код. Він дає те, чого агент не може надійно вгадати:

- **куди йде час**: `profile` запускає реальне навантаження і впорядковує гарячі функції;
- **що портувати першим і в якому порядку**: `analyze` планує модулі, хвилі, ризики й крейти;
- **міст**, щоб решта коду викликала Rust з незмінним API (`bridge`);
- **точну поведінку, якій має відповідати порт**: `record` запускає оригінал на граничних випадках і зберігає, що він повертає або кидає;
- **безпечний спосіб випустити його**: `shadow` запускає обидва поруч;
- **перевірку, яка каже, коли порт завершено**: `gate`.

Оригінал лишається джерелом істини. `diff` відтворює кожен записаний випадок на Rust, і нічого не йде в реліз, доки всі вони не збігаються і `gate` не проходить.

## Чотири кроки

| Крок | Що відбувається |
| --- | --- |
| **Запис** | `record` запускає оригінал на згенерованих граничних випадках, семантичних пастках і ваших власних вхідних даних і зберігає, що він повертає або кидає. |
| **Портування** | `bridge` генерує крейт Rust і обгортку, тож код, що викликає, зберігає оригінальний API. Rust пишете ви або ваш агент. |
| **Перевірка** | `diff` відтворює кожен записаний випадок на Rust, і нічого не йде в реліз, доки всі вони не збігаються і `gate` не проходить. |
| **Lift** | Коли відтворення проходить без fallback і кожен модуль проходить gate, `app lift` робить із нього чистий застосунок на Rust. Оригінал ніколи не змінюється. |

## Чи Rust завжди швидший?

Ні, і everything-rust так і каже. Маленька функція, яку викликають раз на елемент, у Rust часто повільніша, бо кожен виклик перетинає міст; V8, JVM і Go виконують такі функції за наносекунди. `profile` знаходить цикл навколо неї, `--batch` переносить увесь цикл, а `bench` дає вердикт до випуску. Виміряні числа, зокрема повільні, див. у [Пакети й гарячі шляхи](/docs/concepts/batches).

## Він ловить лише те, що покриває запис

Проходження означає, що Rust збігається з кожним записаним випадком, і не більше. Прочитайте [Чого він не впіймає](/docs/concepts/limits), перш ніж довіряти зеленому gate.

::: warning Запускайте на копії
`record` і `app record` запускають ваш оригінальний код, викликаючи кожну функцію (або весь застосунок) на багатьох згенерованих вхідних даних, а `app record` запускає кожен випадок двічі. `diff`, `gate` і `app replay` знову запускають ті самі випадки, на порті або на оригіналі. Код, що пише файли, звертається до бази даних чи мережі, робить це один раз на кожен випадок. Запускайте їх на копії проєкту, з тестовою базою даних і без продакшн-облікових даних у середовищі.
:::
