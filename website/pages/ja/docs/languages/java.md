# Java

| | |
| --- | --- |
| ユニット | `public static` メソッドのパッケージ |
| ブリッジ | 型付き JNI と自動生成のバイナリワイヤ。元のメソッドを持つラッパークラスとして提供 |
| 記録とリプレイの実行方法 | 自動生成のリフレクションドライバー |
| 必要なもの | JDK 17+（`javac` と `java`） |
| ステータス | ファサード経由の JDK 21 で検証済み: 4,492/4,492（226 件は例外を投げる）、gate に合格 |

バッチは `new FnBatch(items)` です。使い終わったら閉じてください。`profile` は JFR を使います。

## 移植版が正しく扱うべきこと

- `Integer.parseInt` は `Character.digit` を通じて、あらゆる Unicode の 10 進数字（`١٢`、`２`）を受け付けます。
- `Double.toString`（JDK 19+）は最短の 10 進表記を出力しますが、桁数は最低 2 桁です: `4.9E-324` となり、Rust の最短表記は `5e-324` です。
- `\s` は ASCII のみです。Rust の `split_whitespace` は U+00A0 でも分割します。
- 浮動小数点数は往復変換で値が保たれなければなりません: `serde_json` のデフォルトの浮動小数点パーサーは常に正しく丸めるとは限らないので、everything-rust とそれが生成するすべてのクレートは `float_roundtrip` 機能を使います。

## 速度

JIT 後は末端関数が数ナノ秒で済み、文字列を伴う JNI の呼び出しはそれ以上のコストがかかります。JDK のファサードでは、`bench` の計測で移植版は呼び出しごとに 0.18 倍でした: より大きなユニットを移植してください。4 コアのバッチでは、50,000 文字列に対する `slugify`（Java で 43 ms）が **3 倍高速**でした（呼び出しごとの移植版は 0.68 倍）。
