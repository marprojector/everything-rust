# Go

| | |
| --- | --- |
| ユニット | パッケージ |
| ブリッジ | 型付き cgo 呼び出しと自動生成のバイナリワイヤ。元の API を持つパッケージとして提供 |
| 記録とリプレイの実行方法 | 独立したモジュールとしてビルドされる自動生成の Go ドライバー |
| 必要なもの | Go 1.21+ |
| ステータス | Go 1.24 の `path` で検証済み: 2,642/2,642（542 件は Go 自身のテストテーブルから）、gate に合格 |

`profile` は `go test` 経由で動作します: `everything-rust profile <repo> -- go test -run X -bench . ./pkg`。バッチは `NewFnBatch(items)` です。使い終わったら閉じてください。

## 移植版が正しく扱うべきこと

- `path.Clean`: Go の `lazybuf` は、書き込みインデックスが戻った後にその位置のバイトを読みます。最後に保持したバイトではありません（Go 自身のテストテーブルから 9 ケース）。
- `strings.ToLower` は各ルーンを個別に小文字化します: `ΣΊΣΥΦΟΣ` は `σίσυφοσ` になりますが、Rust の `to_lowercase` は語末シグマのルールを適用します。Go は `İ` を `i` に対応付けますが、Rust は `i̇` を返します。
- Go は文字列をバイト単位でスライスします。ルーンの途中で切ると、JSON にはバイトごとに 1 つの U+FFFD として現れます。

## 速度

Go は末端関数を数ナノ秒で実行し、cgo の呼び出し 1 回だけで約 80 ns かかります。`path` では、`bench` の計測で移植版は呼び出しごとに 0.04 倍でした: より大きなユニットを移植してください。バッチにすると、処理は Rust に移って全コアで実行されます: 50,000 文字列に対する `Slugify` は Go で 49 ms かかり、バッチは **4 倍高速**でした（呼び出しごとの移植版は 0.93 倍）。バッチのクレートは mimalloc でメモリを確保します: システムのアロケーターでは、Go のバッチはシングルスレッドより遅くなりました。
