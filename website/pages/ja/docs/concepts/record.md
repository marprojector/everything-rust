# 記録

```sh
everything-rust record <crate>
everything-rust record <crate> --from-tests -- npx jest      # または: -- pytest
everything-rust record <crate> --inputs extra.jsonl
```

`record` は元の関数を実行し、それぞれが返したもの、または投げたものを、クレートの隣の `cases.jsonl` に保存します: これが移植版が一致させなければならない挙動です。後で不一致が出たら、それは挙動の違いです: 直すのは移植版であり、記録ではありません。

## ケースの出どころ

- **生成されたエッジケース**: 非 ASCII、絵文字、`-0`、`NaN`、float が期待される場所での int など（`--count` で関数ごとの数を設定）。
- すべての引数に対する**セマンティックトラップ**: 文字列の長さと大文字小文字、符号付き除算、オーバーフローの境界、浮動小数点数の表示、マップとソートの順序。
- 正規表現を使うファイル内のすべての関数に対する**正規表現トラップ**: トルコ語のドットなし `ı`、ケルビン記号、長い s、アラビア・インド数字、行区切り文字、語末シグマ、ゼロ幅接合子。
- **元の実装自身のテスト**: `--from-tests -- <test command>` は、テストスイートがユニットのエクスポートされた関数に対して行うすべての呼び出しを記録します（TS/JS は任意のテストランナー、Python は pytest または unittest）。ソースはその後元に戻されます。vercel/ms では 167 個の Jest テストから 340 件の呼び出しを取得しました。
- **あなたの入力**: `--inputs cases.jsonl` で、1 行に 1 つの `{"fn": name, "args": [...]}` を与えます。実際の入力（本番環境のサンプル、バグ報告）を追加してください。本番を壊すユーザー入力は、ジェネレーターが思いつくものではまずありません。

Python の呼び出し元は `1.0` と同じくらい頻繁に `1` を渡すので、記録では Python のケースの 4 回に 1 回、整数値を int として渡します。

## cases.jsonl のマーカー

JSON は `undefined`、NaN、Infinity、-0、孤立サロゲートを表現できません。構造化された値はマーカーを持ち、生成された `index.cjs` がそれを変換します。ヘルパーはクレートの `js.rs` にあります:

| マーカー | 意味 |
| --- | --- |
| `{"$undefined": true}` | JavaScript の `undefined` |
| `{"$num": "NaN"}` | JSON が保持できない数値（`NaN`、`Infinity`、`-0`） |
| `{"$utf16": [...]}` | 孤立サロゲートのために UTF-16 コードユニットで与えられた文字列 |

関数の契約外の C の入力は、元の実装をクラッシュさせることがあります。C のドライバーは各ケースを fork した子プロセスで実行し、`crash: SIGSEGV` と記録します。C の挙動は未定義なので、`diff` はそこでは移植版のどんな挙動も受け入れます。

## 2 回の実行と、その違い

`record` は元の実装を 2 回実行し、実行間で異なった部分を分類します: 変わった値（時刻、ID）はワイルドカードになります。同じ行が別の順序で出る場合（ハッシュマップ、並行処理）は順序を問わず比較されます。行数が異なる場合は `...` になり、何にでも一致します。`record` はそれぞれの種類を一覧表示します。ハッシュ順や並行処理による違いは、移植版で実際に変わりうるものなので、すべて確認してください。

## 記録は元の実装を覚えている

`record` はユニットのファイルのフィンガープリントを保存します（`recorded-from.json`）。後で元の実装が変わると、元の実装の以前の挙動に対して合格させるのではなく、`diff` が警告し、再度記録するまで `gate` が失敗します。[差分](/docs/concepts/diff#stale-recordings)を参照してください。

## TypeScript 固有の事項

`record` は TS のソースをそのまま実行します: Node の resolve フックがバンドラー形式のインポート（`./errors` から `./errors.ts`）をたどり、リポジトリに何もインストールされていない場合は `--resolve-from` が npm パッケージを提供し、変換が必要な TS（enum、パラメータプロパティ）は `--experimental-transform-types` 付きで再試行されます。Node で直接実行できない TS は、`--module dist/x.mjs` でビルド出力から記録するか、`--node-arg=--import=tsx` で記録できます。

## 数値計算のコード

浮動小数点数がビット単位でほとんど一致しないコードは、`--float-tolerance` 付きで記録してください。[浮動小数点の許容誤差](/docs/concepts/float-tolerance)を参照してください。
