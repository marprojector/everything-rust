# よくある質問

everything-rust についてよく寄せられる質問です。[README](/) に戻る。

## よくある質問

**コードを自動で書き直してくれますか？** いいえ。何を移すべきかを見つけ、ブリッジを生成し、
元の実装の挙動を記録し、Rust をそれと照合します。Rust を `port.rs` に書くのはあなたかエージェントで、
それが正しいかどうかは `diff` と `gate` が判定します。

**アプリの API は変わりますか？** いいえ。呼び出し元は同じ関数（またはシャドウモジュール。
信頼性を確かめている間、両方を実行して元の実装の結果を返します）をインポートします。

**Rust は常に速いですか？** いいえ。そして everything-rust はそれをはっきり伝えます。要素ごとに 1 回呼ばれる小さな関数は、
呼び出しのたびにブリッジを越えるため、Rust の方が遅くなることがよくあります。V8、JVM、Go はそうした関数を
ナノ秒で実行します。`profile` はそれを囲むループを見つけ、`--batch` はループ全体を移し、`bench` は
出荷前に判定を出します。numba、Cython、JAX ですでにコンパイルされているコードもマシンコードとして
実行されます: 移植しても速度はほとんど上がらないので、`profile` と `analyze` はそれを指摘します。

**数値計算のコードですが、浮動小数点数は完全に一致しますか？** 多くの場合は一致しません: 演算の順序、融合
積和演算、数学ライブラリがコンパイラごとに異なるためです。`--float-tolerance 1e-9` 付きで記録すると
（`record` または `app record`）、浮動小数点数は大きい方の値に対するその割合の範囲内（1 未満では
絶対値）で一致とみなされます。整数、テキスト、構造は引き続き完全に一致しなければなりません。

**APK、JAR、.exe しかないアプリを移植できますか？** いいえ。移植するのはソースコードです: 関数を
パースし、それぞれの挙動を記録し、実行中の元の実装と Rust を照合します。コンパイル済みのアプリには
その材料が何もなく、`analyze` もそう伝えます。バイナリの見える挙動から新しい Rust
アプリを書くのは別のプロジェクトです。

**実績のある C を移植すべきですか？** 多くの場合はすべきではなく、`analyze` がそれがどこかを教えてくれます。ハードウェア
レジスタに触れるコード、コンパイラの型サイズやメモリレイアウトに依存するコード、インラインアセンブリを使うコード
（`volatile`、ビットフィールド、packed 構造体、`__asm__`、アドレスにキャストされる整数）は「C のまま
残す」とマークされます: あなたのマシンでの記録はターゲット上のことを何も証明せず、安定したドライバーやファームウェアの
コードは書き直しで得るものがほとんどありません。うまく移せるのは、その周りにあるポータブルなロジック（パース、プロトコル、データ処理）です。

**Electron アプリを移植できますか？** ロジックはできます。ウィンドウはウェブページのままです。`analyze
--whole-app` は Electron を見つけ、レンダラーはそのままにメインプロセスを 1 ピースずつ移植する計画を立てます。
UI を Tauri（同じウェブ UI を Rust のバックエンドで動かす）に移すのは、ロジックが Rust になった後の
別のステップです。

**C#、Kotlin、Swift はどうですか？** C# はプレビュー版です（[対応言語](/docs/languages/overview)を参照）。Kotlin と
Swift はまだサポートしていません。各言語には、パーサー、レコーダー、ブリッジ、リプレイ
ドライバーが必要で、すべてをエンドツーエンドでテストする必要があります。必要な言語について Issue を開く（または既存のものに賛成票を入れる）ことができます。

**Rust の方が元の実装よりずっと大きくなりませんか？** そうなるべきではありません。`gate` は移植版の
行数を元の実装の行数と比較し、3 倍（インポートとシグネチャのために 50 行の余裕あり）を超えると失敗します: それを超えるのは、たいていクレートがすでにやっていることを
手書きしているか、ケースを 1 つずつ処理しているからです。使うべきクレートは `analyze` が一覧表示します。

**一つずつ移植すると、Rust が古いアプリの設計に縛られませんか？** 縛られるのは両方を並べて実行している間だけです。
記録が確認するのはアプリの境界での挙動（CLI の出力、サーバーの
レスポンス、モジュールがエクスポートする関数）であり、内部構造ではありません。ユニットがまだブリッジを越えている間は
古い構造に合わせ、`app lift` が元の実装を取り除いたら Rust を
自由に再構成してください。`app replay` は引き続き挙動を証明します。元の実装へのコールバックもありません:
フロントドアは元の実装を別プロセスとして実行し（または HTTP をそこに転送し）、ブリッジされたユニットは
元の実装から呼ばれるだけで逆方向はなく、コールバックは元の言語に残ります。

**コードが自分のマシンの外に出ますか？** いいえ: everything-rust はローカルで実行され、コードをどこにも
送りません。Cargo はいつもどおりクレートをダウンロードし、エージェントのモデルプロバイダーは、エージェントが
送ったものを、そのプロバイダー自身のポリシーのもとで見ることになります。

**何をインストールする必要がありますか？** Rust に加え、移植する言語のランタイムが必要です（
[インストール](/docs/introduction/install)を参照）。

**何か壊れています。** 実行したコマンド、その出力、お使いのプラットフォームを添えて Issue を開いてください。
