# Fuse.js

[Fuse.js](https://github.com/krisk/Fuse)（20k スター、npm で週に約 2,000 万ダウンロード、
コミット `edf2fb6`）は、数え切れないほどの検索ボックスを支えるあいまい検索ライブラリです。
everything-rust 1.6（未リリース）で移植しました。クレートは [`demo/real-world/fuse-rs`](https://github.com/marprojector/everything-rust/tree/main/demo/real-world/fuse-rs) にあります。

`analyze` は `src/` のすべてのフォルダを 1 つのインポート循環に入れたので、Fuse はファイル単位では移植できません。
代わりに、移植は検索が時間を費やすパスを対象にしています: 54 行のアダプター
（`adapter/relevance.ts`）が、文字列リストの 1 つの文字列に対する Fuse 自身のスコアをエクスポートします。これは
Fuse の `BitapSearch`、フィールドノルム、`computeScoreSingle` から作られています。この関数は、
50,000 文字列に対する検索で 50,000 回実行されるものです。`bridge --batch relevance:text` は文字列を Rust 側に保持し、
それらすべてに対する検索を全コアで実行します。

| ステップ | 結果 |
| --- | --- |
| アダプター | Rust を書く前に、アダプターのランキングが 81 個のクエリとオプションの組み合わせで `new Fuse(list).search(q)` と一致 |
| `record --inputs` | 3,414 ケース: Fuse 自身のフィクスチャのタイトル、非 ASCII、絵文字、32 ユニットより長いパターン、サポートされるすべてのオプション、誤った型のオプション（拒否される、149 ケース） |
| 移植 | 置き換える Fuse の 839 行に対して 673 行の Rust |
| `diff` | 最初のビルドで 3,414/3,414 が一致 |
| `gate` | 合格 |
| 差し替え | `withRust(Fuse)` は文字列リストの検索を Rust で処理し、それ以外はすべて Fuse に渡します。360 回の検索（12 のオプションの組み合わせ、15 のクエリ、`limit` あり・なし）で Fuse とバイト単位で同一の結果を返します |

1 クエリあたりの検索時間、Apple M4（10 コア）、Node 24、計測前に結果が同一であることを確認:

| リスト | Fuse.js | Rust | 高速化 |
| ---: | ---: | ---: | ---: |
| 1,000 文字列 | 1.9 ms | 0.1 ms | 18x |
| 10,000 文字列 | 19.1 ms | 0.7 ms | 27 to 30x |
| 50,000 文字列 | 91.2 ms | 2.8 ms | **32x** |
| 50,000 文字列、1 コア | 92.0 ms | 17.5 ms | 5.3x |

移植版が正しく扱わなければならなかったこと:

- Bitap は JS の 32 ビット整数で動作します: `1 << 31` は負の値で、`(1 << 31) - 1` は次のシフトで
  `2147483647` になる倍精度浮動小数点数です。移植版はこれらの値を JS と同じように保持します。
- テキストは UTF-16 コードユニットでインデックスされるので、Fuse と同様に絵文字は 2 つの位置になります。
- `ignoreDiacritics` は NFD と、結合文字の範囲のリスト、そして明示的に書き出されたいくつかの文字
  （`ł`、`ß`、`ı`）です。移植版は同じリストを使います。
- `String.prototype.trim` が、Fuse がどの文字列をスキップするかを決めます: JS の空白文字であり、Rust の
  `char::is_whitespace`（U+0085 を含み、U+FEFF を含まない）ではありません。

ツールで見つかり、修正されたもの: 要素は文字列だが結果は文字列でないバッチのクレートに未使用のヘルパーが入り、
`clippy -D warnings` に失敗していました。また `gate` のサイズチェックが、インポートする Fuse のファイルではなく
アダプター（54 行なので 12.5 倍「大きすぎる」）だけを数えていました。

カバーしないもの: `keys` を持つオブジェクトのリスト、拡張検索とトークン検索、論理クエリ、
`includeMatches`、カスタムの `sortFn` や `getFn`。差し替え版はそれらを変更せずに Fuse に渡します。
高速化には、検索の間リストが Rust 側に留まっている必要があります。その構築には Fuse 自身のインデックスとほぼ同じコストがかかります
（50,000 文字列で 3.4 ms 対 2.8 ms）。
