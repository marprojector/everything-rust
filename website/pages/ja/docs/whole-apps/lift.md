# リフト

リプレイがフォールバック率 0 で合格し、すべてのユニットが gate に合格したら、純粋な Rust アプリにします:

```sh
everything-rust app lift .
```

- `app lift` は両方の条件が満たされるまで拒否し、何が妨げているかを示します: まだフォールバックしているケース、まだスタブのままのグルーコード、gate に失敗しているユニットです。
- まずコピー上で、フォールバックのパスとキルスイッチを取り除き、各ユニットのクレートを `rust/app` の普通のライブラリ（`cdylib`、バインディング、生成されたラッパーなし）にし、`rust/app/tests/app_cases.rs` を追加します。これは `cargo test` で trycmd を使って `rust/app-cases` を実行するので、CI には cargo 以外何も必要ありません。
- それからリフトのチェックリストを実行します: すべてのユニットと `rust/app` に対する fmt、clippy `-D warnings`、テスト、`rust/DECISIONS.md` に記載されたすべてのターゲットのビルドまたはチェック（インストールされている場合）、実行時に読み込まれるファイルと埋め込まれていないアセットフォルダ、そして純粋なバイナリでのリプレイです。すべてに合格した場合にのみ、変更が書き戻されます。元の実装には一切手を加えません。

## リフトの後

ユニットにはもうバインディングがありません。json-server では、各クレートの `tests/recorded.rs` が移植版に対して記録ケースをリプレイします: 3,399 件すべてが `cargo test` で、514 件の HTTP ケースと並んで実行されます。

元の実装がなくなったら、Rust を自由に再構成してください。`app replay` は引き続き挙動を証明します。

## そして切り替える

ワークフロースキルに従い、エージェントはできることを行い、`rust/cutover.sh` を書きます。これはあなたにしかできないステップ（デプロイ、DNS、シークレット）のための対話式スクリプトで、各ステップに戻る手段があります。
