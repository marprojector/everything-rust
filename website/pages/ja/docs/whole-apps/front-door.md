# フロントドアとワイヤリング

まずエントリポイントを Rust に移し、それから 1 ユニットずつコマンドを引き渡します:

```sh
everything-rust app front-door .                            # rust/app: すべてのコマンドが元の実装を実行する
everything-rust app wire . textkit --command upper          # textkit-rs が gate に合格した後
# rust/app/src/units/textkit.rs にグルーコードを書き、その後:
everything-rust app wire . textkit                          # 再び 100%、フォールバック率は下がる
```

## フロントドア

`app front-door` は `rust/app` を生成します。これはアプリの名前を持つ Rust バイナリで、記録ケースに含まれるコマンドとフラグのための clap パーサーを持ちます。すべてのコマンドは同じ argv、stdin、環境変数で元の実装を実行し、その出力と終了コードをそのまま返します。フォールバックはそれぞれカウントされるので、生成直後のフロントドアをリプレイすると、フォールバック率 100% で 100% 合格となります（それを示すためにビルドとリプレイを行います）。`rust/app` を上書きすることはありません: それ以降、コードはあなたのものです。

## ユニットのワイヤリング

`app wire <repo> <unit> --command <name>` は:

1. ユニットのクレートに対して `gate` を実行します（直前に合格したなら `--skip-gate`）。
2. それをライブラリとして `rust/app` に追加します。
3. `src/units/<unit>.rs` を一度だけ書き出します。中身はあなたかエージェントが埋めます: 引数をパースし、`<crate>::port` を呼び、元の実装が出力するものを出力します。
4. コマンドをそこにルーティングし、ビルドしてリプレイします。

グルーコードを書いた後にもう一度実行すると、100% 合格でフォールバック率が下がります。`EVERYTHING_RUST_UNIT_<NAME>=original` を指定すると、リフトまでの間、ワイヤリングしたユニットを元の実装に戻せます。

コマンド名のない argv（引数なし、未知のコマンド、使い方のエラー）のために、アプリ自身の名前をコマンドとしてワイヤリングしてください（`--command mytool`）。

## 元の実装へのコールバックはない

フロントドアは元の実装を別プロセスとして実行し（または HTTP をそこに転送し）、ブリッジされたユニットは元の実装から呼ばれるだけで逆方向はなく、コールバックは元の言語に残ります。

サーバーはコマンドの代わりにルートを使います: [サーバー](/docs/whole-apps/servers)を参照してください。ライブラリは公開 API を使います: [ライブラリ](/docs/whole-apps/libraries)を参照してください。
